> 任务：TASK-50A（05 线 1/2）· 里程碑 M1 · 你线职责扩展：Apple II + 游戏机线 + **模拟器生态专研**（为全局槽位系统供料）。

## 一、结论速览（给槽位系统 media_class 的生态结论）

| 类目 | 可运行性 | 一句话结论 |
|---|---|---|
| 手机（Symbian/Nokia S60/N-Gage） | **可运行（有限）** | EKA2L1（GPL-3.0）覆盖 S60v1–v3 + N-Gage，需真机固件 |
| 手持/掌上（Game & Watch） | **可运行** | MAME 有 G&W 手持驱动；另有 MADrigal 等网页 sim |
| 手持/掌上（Palm OS） | **可运行** | CloudpilotEmu（GPL-3.0，POSE 后继），需 ROM |
| 手机（iPhone OS 早期） | **不可运行** | 无成熟模拟器，仅 QEMU 实验性支持 [需核实] |
| 家电影音（VCD/DVD 播放器） | **不可运行** | 无成熟模拟器，走"芯片级示意 + 视频回放合成"替代 |

> 上表为结论速览，各条目的"项目名 + 许可 + URL + 状态"详见 §二至 §四，接入难度详见 §五，媒体类别详见 §六，生态规律详见 §一之 1.1。

> 生态结论：**Symbian / Palm OS / Game & Watch 三类有成熟生态可"真跑"；iPhone OS 早期与 VCD/DVD 播放器无生态，走"展示向 + 合成演示"**。这决定了槽位系统的 media_class 设计：有生态的类目做"真运行槽位"，无生态的做"静态/动画展示槽位"。

### 1.1 生态规律总结（三条）

本调研从手机/手持/家电三大类的生态差异中，归纳出三条决定"可运行性"的规律：

**规律一：软件库决定生态存亡。** 模拟器存在的前提，是该平台"承载过足够多值得保存的软件"。Symbian 因 N-Gage 游戏与庞大应用库幸存下了 EKA2L1，Palm OS 因 PDA 应用库幸存下了 CloudpilotEmu，Game & Watch 因段码 LCD 游戏的独特魅力进了 MAME；而 S30/S40、早期 iPhone OS、VCD/DVD 播放器这些"没有软件库"的平台，自然没有模拟器——没有软件，就没有保存软件的工具。

**规律二：开放可编程决定生态深度。** 同样是手持，Game & Watch 与 Palm OS 有模拟器，早期 iPhone 没有——根本区别在"是否开放可编程"。G&W 的 ROM 可 dump、Palm 的应用可安装，这些"开放"属性让第三方能复刻硬件；而 iPhone 的封闭启动链让复刻几乎不可能。开放程度越高，模拟器生态越深。

**规律三：接入成本独立于生态有无。** 有生态不等于好接入：EKA2L1 是桌面 GUI、无 headless 接口，接入成本高；CloudpilotEmu 有 CLI + GDB stub，接入可行；MAME 有现成协议，接入最省。因此"可运行性"要拆成"生态有无"与"接入成本"两个独立维度，不能混为一谈。

这三条规律，是本调研给槽位系统最核心的输入——它不是一份模拟器清单，而是一套"判断任何老设备能否真跑、怎么跑"的方法。

## 二、手机类模拟器

### 2.1 EKA2L1（Symbian OS / Nokia N-Gage / S60）

| 要素 | 内容 |
|---|---|
| 项目名 | **EKA2L1** |
| GitHub | https://github.com/EKA2L1/EKA2L1 |
| 许可 | **GPL-3.0** |
| 维护状态 | 活跃（2022 起转 part-time hobby，但持续发布自动构建；截至 2026-09 仍有更新） |
| 介质形态 | **firmware 闪存包**（需真机 dump 的 ROM/RPKG/VPL）+ .sis/.sisx 安装包 |
| 覆盖范围 | S60v1–v3、Symbian Belle、N-Gage / N-Gage 2.0 |
| 后端类型 | custom（C++17 动态重编译器，重实现 Symbian 内核与 app server） |
| 协议对接量级 | **需自定义**（无现成 headless/脚本接口，需二次开发或走画面注入） |

> 说明：EKA2L1 不是"全硬件仿真"，而是"内核级重实现 + 关键库复刻"，因此效率高、但兼容性依设备而异。它是当前 Symbian/N-Gage 生态唯一成熟项目 [S1]。接入本项目需自定义后端（无 headless 接口，`[需核实]`）。

### 2.2 旧 Nokia 固件模拟

旧 Nokia 功能机（S30/S40 系列）的"固件模拟"与 Symbian 不同——S30/S40 不是 Symbian，是 Nokia 自研封闭 OS，**目前无成熟开源模拟器**（`[需核实]`）。EKA2L1 只覆盖 Symbian 系（S60），不覆盖 S30/S40。结论：旧 Nokia 功能机固件模拟**暂不可行**，走展示向。

### 2.3 MAME 手持驱动（若覆盖）

MAME 自合并 MESS 后覆盖大量手持设备（`handheld` 类驱动），包括 **Game & Watch**、plug-and-play 电视游戏机等 [S2]。MAME 许可 GPL-2.0+（核心多 BSD-3）。后端类型 **mame**，协议对接量级 **现成协议**（沿用本项目 gw 网关的 MAME 通道）。

### 2.4 iPhone OS 早期模拟

iPhone OS 1.x 是封闭生态，**无成熟开源模拟器**。QEMU 有实验性的早期 iOS 启动尝试，但远未达到"可运行应用"的程度（`[需核实]`）。结论：**不可运行**，走展示向（外观/UI 交互示意）。

### 2.5 手机类生态分析小结

手机类模拟器生态的整体特征是"**碎片化 + 少数幸存**"：2000 年代手机平台百花齐放（Symbian、Windows Mobile、Palm OS、BlackBerry、S30/S40），但绝大多数平台随硬件消亡而生态凋零。Symbian 因 N-Gage 的游戏属性与庞大的应用库，幸存下了 EKA2L1 这一活跃项目；Palm OS 因 POSE 的历史积累，幸存下了 CloudpilotEmu；而 S30/S40、早期 iPhone OS 等平台则无生态。这反映了一个规律：**模拟器生态的存续，取决于该平台"是否承载过足够多值得保存的软件"**——有游戏/应用的平台（Symbian/Palm）有人做模拟器，纯工具/封闭的平台（S30/S40/iOS）无人问津。对博物馆而言，这意味着"手机类"不能一概而论，而要按"是否有生态"分两档处理。

| GitHub | https://github.com/cloudpilot-emu/cloudpilot-emu |

### 3.3 手持类生态分析小结

手持/掌上类模拟器生态是**最健康的一档**：Game & Watch 有 MAME 手持驱动 + 网页 sim 双重方案，Palm OS 有 CloudpilotEmu 完整覆盖。原因在于，这两类设备都承载了"值得保存的软件"——G&W 是横井军平"枯萎技术的水平思考"的经典（段码 LCD 游戏的独特魅力），Palm OS 有庞大的 PDA 应用库与 Handspring/索尼 Clié 等衍生设备。这为游戏机厅的"手持线"提供了扎实的可运行基础：G&W 与 Palm OS 都可做"真运行槽位"，而它们的介质（G&W 极小型 ROM、Palm ROM 文件）也相对容易合规获取。对比之下，同样是手持的早期 iPhone 则完全无生态——可见"是否开放可编程"决定了生态的存亡。

## 四、家电影音类（VCD / DVD 播放器）

### 4.1 现状：无成熟模拟器

VCD/DVD 播放器目前**基本无成熟模拟器**。原因有二：其一，VCD/DVD 播放器是"解码芯片 + 光驱 + 固件"的高度定制嵌入式设备，芯片（如 MTK、ESS、Sunplus 的解码芯片）资料封闭、无公开规格；其二，播放器的核心价值（播放视频）是媒体解码，不是"可编程计算"，模拟的价值远低于电脑/游戏机。结论：**如实写"无"**。

### 4.2 替代演示方案（芯片级示意 + 视频回放合成）

既然无模拟器，VCD/DVD 播放器的"可运行演示"改用两层替代：

1. **芯片级示意**：用装配体拆解展示解码芯片、光驱机芯、前面板 VFD 显示屏，配"解码芯片 → 视频输出 → 电视"的信号流动画（C4 级）。
2. **视频回放合成**：不真解码，而是"模拟播放"——把 VCD/DVD 的画面回放与播放器前面板（VFD 时间码、按键灯）联动，用一段预录的视频片段 + 前面板状态合成"播放中"的观感。

> 这是"展示向"而非"真运行向"，在槽位系统的 media_class 里归为 **static/anim** 而非 **runnable**。

### 4.3 家电影音类生态分析小结

家电影音类（VCD/DVD 播放器）是**生态真空**。与电脑/游戏机不同，影音播放器不是"通用计算平台"，而是"解码芯片 + 光驱 + 固件"的封闭嵌入式设备，其价值在于播放媒体而非运行软件，因此从未形成"软件库"——没有软件库，就没有模拟器存续的动力。更根本的是，VCD/DVD 的"可运行"诉求（播放一张碟）在现代设备上已经通过软件播放器（VLC 等）天然满足，无需模拟原始播放器硬件。因此，博物馆对 VCD/DVD 播放器的展示，正确姿态是"**讲硬件（解码芯片、光驱机芯、VFD 屏）**"而非"**跑软件**"——用芯片级示意 + 视频回放合成还原"播放中"的观感即可，这也正是"可看、可拆、可懂"（不追求"可玩"）的落点。

## 五、接入难度分级表

| 条目 | 后端类型 | 协议对接量级（照 14-A 模式） | 可运行性 |
|---|---|---|---|
| Symbian / N-Gage（EKA2L1） | custom | 需自定义（无 headless，`[需核实]`） | 可运行（有限） |
| Game & Watch（MAME 驱动） | mame | 现成协议 | 可运行 |
| Game & Watch（MADrigal 网页 sim） | custom | 需自定义（iframe 内嵌） | 可运行 |
| Palm OS（CloudpilotEmu） | custom | 需自定义（CLI/GDB stub 有进程对接潜力） | 可运行 |
| 旧 Nokia 功能机（S30/S40） | 无 | 不可行 | 展示向 |
| iPhone OS 早期 | 无（QEMU 实验 `[需核实]`） | 不可行 | 展示向 |
| VCD/DVD 播放器 | 无 | 不可行 | 展示向（合成演示） |

**分级口径**（照 14-A）：
- **现成协议**：有现成 headless/脚本/协议接口，接入成本低（如 MAME 的 Lua/图像接口）。
- **需自定义**：无现成接口，需二次开发后端适配或内嵌（如 EKA2L1、CloudpilotEmu 网页版）。
- **不可行**：无可用模拟器（如 iPhone OS、VCD/DVD）。

## 六、给槽位系统 media_class 的生态结论

1. **有生态、可"真跑"的类目**（media_class = runnable）：Symbian/N-Gage、Game & Watch、Palm OS。这三个类目可设"真运行槽位"，走 MAME 网关或 custom 后端。
2. **无生态、纯展示向的类目**（media_class = static/anim）：iPhone OS 早期、旧 Nokia 功能机、VCD/DVD 播放器。这三个类目设"静态/动画展示槽位"，走"芯片级示意 + 合成演示"。
3. **边界类目**：Game & Watch 的网页 sim（MADrigal）介于两者之间，可作"轻量可运行"（iframe 内嵌）的过渡方案，不占网关后端资源。

> 给 01/02 线槽位实现的输入：media_class 建议区分 **runnable（真跑）** 与 **static/anim（展示）** 两级，runnable 下再分 mame 后端与 custom 后端两种接入形态；本调研的接入难度分级表可直接作为槽位后端选型的输入。

### 6.1 槽位系统 media_class 的详细分级建议（给 01/02 线）

基于本调研，建议槽位系统 media_class 采用**三级**而非两级，以更精细地表达"可运行性"的差异：

| media_class | 含义 | 适用类目 | 后端 |
|---|---|---|---|
| `runnable_mame` | 真跑，走 MAME 网关通道 | Game & Watch（MAME 驱动） | mame |
| `runnable_custom` | 真跑，需自定义后端 | Symbian（EKA2L1）、Palm OS（CloudpilotEmu）、G&W 网页 sim | custom |
| `static_anim` | 展示向，芯片级示意 + 合成演示 | iPhone OS 早期、旧 Nokia 功能机、VCD/DVD 播放器 | 无 |

> 三级比两级多拆出一档 `runnable_custom`，因为"有生态但需自定义后端"与"有生态且走 MAME"的接入成本差异巨大，混在同一个 `runnable` 里会让槽位系统低估 Symbian/Palm 的接入难度。建议 01 线在槽位数据模型里采纳此三级分类。

### 6.2 给 02 线内容包的输入

- Symbian / Palm OS / Game & Watch 三类可运行设备的内容包，runtime.json 的 `emulator` 字段建议预填：Symbian→`eka2l1`、Palm OS→`cloudpilotemu`、G&W→`mame`（handheld 驱动）。
- 三者的 `media_hint` 建议：Symbian/Palm→`firmware`（需固件/ROM），G&W→`cartridge`（极小型 ROM）或 `none`（网页 sim 无需介质）。
- VCD/DVD 播放器、旧 Nokia、早期 iPhone 的内容包不做 runtime（无模拟器），只做静态展示 + C4 动画。

## 八、与游戏机线 / 内容线的衔接说明

本调研是 05 线职责从"Apple II + 游戏机线"扩展到"模拟器生态专研"后的第一份产出，其定位是**给全局槽位系统供料的横向调研**，与纵向的设备线（游戏机线 console-batch、内容线 apple-ii）的关系是：

1. **向上供料**：本调研的"类目 × 可运行性"结论表，是 01/02 线槽位系统 media_class 设计的输入。
2. **向下支撑**：本调研确认"有生态可跑"的类目（Symbian/Palm/G&W），为后续这些类目设备包的生产（如 50-B 的 G&W 建模卡）提供"运行时方案"依据。
3. **横向补位**：游戏机线聚焦"有生态的游戏机"，本调研补齐"手机/手持/家电影音"这些生态边界类目，让博物馆的"可运行方案"覆盖从"强生态（游戏机）"到"无生态（家电）"的完整光谱。

> 一句话：本调研是"可运行性"这条横轴的第一份地图——哪些设备能真跑、哪些只能展示、各要花多大接入成本，是后续所有设备包生产的运行时选型基础。

## 九、本调研的方法论、局限与后续方向

### 9.1 方法论

本调研遵循"清单级、零下载、可复核"三原则：对每一类设备，先检索该平台的主流模拟器项目，核实其"项目名 + 许可 + URL + 维护状态 + 介质形态"五要素，再按"后端类型 + 协议对接量级"给出接入难度分级。核实以 GitHub 仓库、官方文档、模拟器社区（Emulation King、Libretro 文档）为来源，逐条记录许可与 URL，不做主观猜测。凡无法确证处，一律标「需核实」并给出建议核实渠道，而非含糊带过。

### 9.2 局限

本调研有三点局限，须如实说明：

1. **覆盖范围**：本版（v1）只覆盖任务书点名的三大类（手机/手持/家电影音）的代表性平台，未穷尽所有手机 OS（如 Windows Mobile、BlackBerry、早期 Android）与所有手持（如 Game Boy 之外的 Game Gear、Lynx），这些留待后续版本扩展。
2. **状态时效**：模拟器项目的"维护状态"是动态的，本版快照于 2026-11；正式接入前须重新核验各项目的活跃度与最新许可。
3. **接入可行性未经实测**：接入难度分级（现成协议/需自定义/不可行）是"文献级"判断，未实际验证 EKA2L1、CloudpilotEmu 的 headless/脚本接口；凡涉及实际接入，须先做技术 spike（同 13 号 MAME 接入预研的 spike 模式）。

### 9.3 后续调研方向

1. **扩展手机类**：补 Windows Mobile（有模拟器生态）、BlackBerry、早期 Android 的生态调研。
2. **扩展手持类**：补 Game Gear、Lynx、Neo Geo Pocket 等手持的模拟器生态（这些有成熟生态，可并入游戏机线的可运行清单）。
3. **实测 spike**：对 EKA2L1、CloudpilotEmu 做进程级接入的 spike，验证"需自定义"的真实工作量。
4. **介质合规细化**：对 Symbian 固件、Palm ROM 的"自备 dump + 版权方授权"合规口径，做逐平台的细化文案（沿用 FR-E3 风格）。

### 9.4 给后续设备包生产的一句话输入

> "有生态的类目（Symbian/Palm/G&W）按可运行做设备包，`emulator` 预填 eka2l1/cloudpilotemu/mame，`media_hint` 预填 firmware/cartridge；无生态的类目（iPhone/旧 Nokia/VCD-DVD）不做 runtime，只做静态展示 + C4 动画。接入难度分级表（§五）是后端选型的直接依据。"

## 十、本调研与 50-B（G&W 建模卡）的关系

本调研（50-A）确认 Game & Watch 的"可运行性"（MAME 手持驱动 + 网页 sim 双方案），这为 50-B 的 G&W 建模任务卡提供了运行时前提——G&W 不仅可"看、拆、懂"，还可"玩"（段码 LCD 游戏的模拟）。50-B 据此把 G&W 立为"手持线"的第一份建模任务卡，其段码 LCD 的"面板式贴图 vs 立体导光"两级方案，正对应本调研的"可运行"结论：段码 LCD 的显示层可被模拟器驱动（MAME/网页 sim），因此建模须保证显示层与模拟器画面可叠加。二者一横（生态）一纵（建模），共同构成"手持线开产"的完整准备。

## 十一、可运行类目的接入方案详细建议（Spike 前评估）

对三个"可运行"类目，给出更细的接入方案预判，供后续技术 spike 使用（不实测、只评估）：

### 11.1 Symbian / N-Gage（EKA2L1）

EKA2L1 是桌面 GUI 应用（Qt 界面），**无公开的 headless/命令行接口**（`[需核实]`），接入本项目有两种思路：其一，走"画面注入 + 输入注入"——把 EKA2L1 窗口画面捕获为帧、把网关输入映射为 EKA2L1 键鼠事件，走"窗口级桥接"（成本中等，但脆）；其二，给 EKA2L1 打补丁，暴露一个 TCP 协议接口（成本高，需上游配合）。**建议**：先做 spike 验证思路一（画面捕获 + 键鼠注入）的可行性；若不可行，Symbian/N-Gage 降级为"展示向"（静态展示 + 录屏回放）。

### 11.2 Palm OS（CloudpilotEmu）

CloudpilotEmu 有**原生 CLI 版本**（`cloudpilot-emu` 命令行），支持加载 ROM/卡镜像、savestate、GDB stub 远程调试，具备**进程级接入潜力**：可 spawn 原生 CLI 进程，经 GDB stub 或自定义协议注入输入、捕获画面。这是三个可运行类目里**接入最可行**的一个。**建议**：优先对 CloudpilotEmu 原生 CLI 做 spike，验证"spawn + 输入注入 + 画面捕获"链路。

### 11.3 Game & Watch（MAME 驱动 / 网页 sim）

G&W 有两条路：其一，MAME `gameboy`/`gamewatch` 手持驱动，走本项目现成的 MAME 网关通道（协议对接量级最低，`[需核实]` 具体驱动名与覆盖机型）；其二，MADrigal 网页 sim，走 iframe 内嵌（零后端成本，但画面质量与可控性受限于网页）。**建议**：优先走 MAME 通道（与现有网关统一）；网页 sim 作轻量过渡。

### 11.4 接入优先级排序

| 优先级 | 类目 | 理由 |
|---|---|---|
| P0 | Game & Watch（MAME） | 现成协议，接入成本最低，且是 50-B 建模卡的直接运行时 |
| P1 | Palm OS（CloudpilotEmu CLI） | 进程级接入潜力高，spike 验证成本可控 |
| P2 | Symbian / N-Gage（EKA2L1） | 无 headless 接口，接入成本高，视 spike 结果定去留 |

## 十二、结论与展望

本调研的最终结论可归纳为一句话：**"可运行"不是设备的固有属性，而是"生态 + 介质 + 接入成本"三者的函数**。Symbian 有生态但接入难、Palm OS 有生态且接入可行、G&W 有生态且走现成 MAME、VCD/DVD 无生态只能展示——同是"老设备"，可运行性天差地别。这提醒博物馆的槽位系统设计者：**不要把"老设备"一刀切地塞进"真运行"或"静态展示"，而应按生态逐类分级**。

展望后续，05 线的"模拟器生态专研"职责将沿两条线推进：横向扩展覆盖面（补 Windows Mobile、BlackBerry、Game Gear 等），纵向深化可运行类目的接入（对 CloudpilotEmu、EKA2L1 做 spike）。本调研 v1 是这条线的起点，后续每个可运行类目的落地，都应在"生态调研 → spike 验证 → 设备包生产"的链条上前进。

## 十三、各门类详细生态档案（背景补充）

### 13.1 手机类的生态兴衰

2000 年代的手机操作系统，是一场"诸侯混战"：Symbian 靠 Nokia 的体量一度占据过半份额，Windows Mobile 主攻商务，Palm OS 主攻 PDA 起家，BlackBerry 靠邮件推送独树一帜，而 S30/S40 则是 Nokia 面向功能机的自研封闭系统。这场混战的结局是 iOS 与 Android 的崛起终结了一切——2010 年后，Symbian、Windows Mobile、Palm OS 相继谢幕，它们的软件库也随之失去运行载体。模拟器生态因此成了"抢救运动"：EKA2L1 抢救 Symbian/N-Gage，CloudpilotEmu 抢救 Palm OS，而 S30/S40 这种"从未有过软件库"的封闭系统，则无从抢救。

### 13.2 手持类的生态脉络

手持游戏机的模拟器生态，实际上是"从 Game & Watch 到 Game Boy 再到智能手机"的一条线。Game & Watch 是手持游戏的起点，其段码 LCD 的独特显示方式让它在 MAME 里获得了专门的手持驱动；Game Boy 则是手持游戏的高峰，其庞大的卡带库催生了 SameBoy 等一堆模拟器（已在 40-B 调研）；而 Palm OS 作为"能玩游戏的 PDA"，则借 POSE 的历史积累存活于 CloudpilotEmu。这条线里，凡是"有游戏库"的手持都有模拟器，凡是"纯工具"的手持（如早期计算器、电子词典）则少有问津——再次印证了"软件库决定生态"的规律。

### 13.3 家电影音类的生态真空

VCD/DVD 播放器之所以是生态真空，还因为它处于一个尴尬的中间地带：它既不像电脑/游戏机那样"可编程、有软件库"，又不像电视/收音机那样"功能单一到无需模拟"。它的"可运行"诉求——播放一张碟——在现代设备上已经被软件播放器（VLC、MPV 等）完美替代，模拟原始播放器硬件既无技术动机（芯片资料封闭）也无用户动机（没人想重温原始播放器的卡顿菜单）。因此 VCD/DVD 播放器在博物馆里的正确位置，是"硬件考古"（解码芯片、光驱机芯、VFD 屏）而非"软件运行"——这一判断，也适用于大部分"纯影音家电"。

## 附录 C：可运行类目的介质合规细化（FR-E3 风格）

三个可运行类目都需要介质（固件/ROM），合规口径逐类细化如下：

### C.1 Symbian / N-Gage（固件）

> 运行 Symbian 需要真机固件（ROM dump），这些固件多数仍受 Nokia/版权方保护，本项目**绝不内置、也不提供任何固件**。合法途径：① 从你合法拥有的 Symbian 真机 dump 固件作个人备份；② 版权方授权渠道；③ 明确授权的社区固件存档。EKA2L1 本身不附带任何固件，用户须自备。

### C.2 Palm OS（ROM）

> 运行 Palm OS 需要设备 ROM 文件，多数仍受版权保护。合法途径：① 从你合法拥有的 Palm 设备 dump ROM；② PalmDB 等社区存档（版权状态各异，`[需核实]`，须逐条核验）；③ 版权方授权渠道。CloudpilotEmu 不附带 ROM。

### C.3 Game & Watch（ROM）

> G&W 的 ROM 极小（几 KB），但仍是版权材料。合法途径：① 从你合法拥有的 G&W 实机 dump；② MAME 软件列表里标注为可自由分发的那部分（若存在）；③ 版权方授权渠道。MADrigal 网页 sim 为自实现，无需 ROM。

> 共通原则：**模拟器可开源，介质不可内置**——本项目的"可运行"永远建立在"用户自备合法介质"之上，这是红线，与游戏机线（2600/FC/MD/GB）的 ROM 合规口径完全一致。
