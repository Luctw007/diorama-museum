
## 三、gd_naming_check 说明（GN-01~03，已由 01 线实现）

> **状态变更**：v1.1 阶段本检查仅为 02 线在 `规范增补_v0.6.3` 附录 A 定义的"需求"（"预计新增"）；
> **v1.2 起已由 01 线实现并纳入门禁**——脚本路径 `01/repo/01/scripts/gd_naming_check.py`，与
> `gd_symbol_check.py` 并列。02 线不再持有"待实现"口径。

检查点与 v0.6.3 附录 A 逐字对齐（02 线定义、01 线实现）：

| 检查点 | 内容 | 命中输出 |
|---|---|---|
| GN-01 | gd 内 `func <name>(` 的 `<name>` 命中 Object/Node 原生方法黑名单（get_index/get_meta/get_name/get_parent/get_class/get_path/get_child/get_node/set_meta/set_name/has_method 等） | `FAIL GN-01 <文件>:<行> 方法名 <name> 与原生冲突` |
| GN-02 | `var <id> := <三元或动态调用>` 且左侧未显式标注类型（`: Type`） | `FAIL GN-02 <文件>:<行> := 推断 Variant 未标注类型` |
| GN-03 | 类型标注 `<Type>` 未在工程内任何 gd 声明 `class_name <Type>` | `FAIL GN-03 <文件>:<行> 类型 <Type> 未注册 class_name` |

- **输出格式**：对齐 `gd_symbol_check.py`——逐条 `FAIL <规则> <文件>:<行> <消息>` + 末尾 `FAIL n`
  计数行；全过退出码 0，有 FAIL 退出码 1（供 CI 解析）。
- **边界**：仅静态文本匹配，不解析 GDScript 语义；误报按需加白名单。
- **依据**：`规范增补_v0.6.3` 条文 v0.6.3-01（方法名冲突）、-02（`:=` 推断纪律）、-03（class_name
  缓存重载），三处均可做引擎外静态检查，故不侵入 01 线运行时。

## 四、内容清单脚本化（build_content_manifest.py）

**脚本路径**：`tools/contrib_kit/build_content_manifest.py`（02 线侧，TASK-172-A 新建）。

- **职责**：只读扫描 §一 的收录范围 → 对每个文件做「存在性 → 扩展名黑名单 → 字样黑名单 → md5」，
  生成 `docs/自测包内容清单_v1.2.md`。
- **不越界**：**不产出 zip**（打包仍在 01 线 `make_contrib_kit.py`），不改任何被扫描文件，不联网、
  不写二进制。
- **黑名单对齐**：`BLOCK_EXTS` / `BLOCK_SUBSTR` 与 01 线 `make_contrib_kit.py` **逐项一致**，命中
  `.exe/.bin/.rom/.zip/.pyc` 等扩展名或 `ghp_/credential/private key` 等字样即判违规，退出码 1。
- **汇总口径**：末行 `汇总：条目 N / 总字节 X / 违规 0`；`N ≥ 10`（8 校验器 + 1 schema + 1 说明）。

> 命令：`python tools/contrib_kit/build_content_manifest.py`（在 repo 根或脚本目录下运行均可，
> 脚本按 `__file__` 自定位 repo 根）。

## 五、给贡献者：自测包怎么用、边界在哪

### 5.1 为什么要把 02 线校验器分发给贡献者

本项目对"开放贡献"的门槛是四件套：内容包规范 v0.6.x + 门禁 0 FAIL + 贡献指南 + 槽位即插即用
（00 基线「决策 1」）。其中"门禁 0 FAIL"依赖的校验器本身必须能跑到贡献者手里——否则贡献者只能
"凭感觉"交包，把校验负担全部推给维护者。自测包就是把 `tools/validate/` 这套校验器连同 schema 与
说明打包，让贡献者**在本地就能跑到与门禁一致的结果**，交包即过闸、少走返工。

### 5.2 分发边界（红线）

- **只发纯文本**：校验器（`.py`）、schema（`.json`）、说明（`.md`）——全部纯文本，无二进制、无 ROM、
  无图片、无凭据。黑名单命中的文件在打包与清单自检两处都会被拦截。
- **ROM / 二进制永不进包**：槽位需要的模拟器二进制与 ROM 一律由用户按 `规范v0.5` 自备放进 `slots/`，
  自测包只登记哈希清单与来源，不放实体。
- **只读分发**：自测包是被"复制"给贡献者，不承载任何写回；贡献者用它在自己机器上跑，结果不会
  回流到仓库，提交时按 `CONTRIBUTING.md` 流程走。

### 5.3 清单脚本化解决什么

v1/v1.1 的内容清单是**手工罗列**——新增/删除一个校验器，清单就得靠人记得去改，一旦忘改就出现
"说明写了 8 个、实际包里 9 个"的漂移。v1.2 起改为 `build_content_manifest.py` 脚本化生成：扫描
`tools/validate/` 顶层 `*.py` 得到校验器清单，逐文件算 md5、跑黑名单，产出 `docs/自测包内容清单_v1.2.md`。
**清单永远由机器从真实文件生成**，不再依赖人工记忆，漂移从源头消除。
