## 1. 定位与三层分工声明

- **20 号**《音频工程规格》= 资产工程层：音源怎么做、多响、存哪（母带/响度/授权/物理目录）。
- **40 号**《全馆音频事件对齐总表》= id 对齐审计层：event_id 对不对、谁定义、谁待修。
- **65 号（本文）**= 事件系统层：事件在运行时怎么**触发/调度/抢占/闪避/路由混响/回收**。本文档不重写前两者，只在其 id 与参数之上新增运行时规格；引用的数值与 20/40 号一致，冲突处只标「待裁决」不改原文。

## 2. 事件对象模型

- 字段（对齐 20 号 §2 事件表列定义）：`{event_id, 触发源, 母线, 优先级, 互斥组, 空间定位, 包络, 停止条件}`——20 号列「触发点/音轨/3D 位置/音量包络/停止条件」依次映射为「触发源/母线/空间定位/包络/停止条件」；`优先级`/`互斥组` 为本层新增调度字段（不改变 20 号已有列语义）。
- **触发源五类枚举（齐）**：

| 枚举 | 语义 | 例（40 号在册 id） |
|---|---|---|
| state | 设备/厅状态机变迁触发 | sfx_power_on、sfx_crash、sfx_auto_recover_ok |
| proximity | 玩家进出半径/热区触发 | amb_hall、amb_cabinet、amb_crt_room |
| input | 玩家输入/抓取/面板操作触发 | sfx_confirm、sfx_deny、sfx_slider_tick、sfx_page |
| hook | 引擎帧/时序钩子触发（字幕/动画同帧） | sfx_ui_badge、sfx_boundary |
| gateway | 网关 audio_chunk 直通（模拟器原声） | run_speaker_beep |

## 3. 事件调度器（EventBus）抽象

| 机制 | 规则 | 数值/出处 |
|---|---|---|
| 注册表 | 每个 event_id 一张运行时描述（§2 字段全量）；未知 id 记 warn 不崩 | 40 号 A 区在册 id 全量可注册 |
| 去抖 | 同 id 最小重触发间隔 **250 ms**；窗口内重复触发只保留末次 | [需实机核对：手感] |
| 并发上限 | 单总线并发见 §6 预算表；全局 streaming pool **32 路** | [需实机核对：Godot VoiceLimiter] |
| 互斥组 | 同组内后触发抢占，交叉淡化 **40 ms**（组定义沿用 04 号 §1.6 / 20 号 §1.6 口径）；组 run 崩溃急停开关（04 号 §1.6.4） | 04 号 §1.6 |
| 跨厅优先级 | 数值 0~4：bed=0、bgm=1、run=2、narr=3、ui/gateway=4；高优先抢占低优先（闪避例外见 §4） | 本层新增，不覆盖 20 号任何数值 |

## 4. 抢占与闪避（ducking）状态机

**参数（与 20 号 §1.1 数值不漂移）**：narr 播放时 bgm 自动 **−8 dB（0.3 s ramp）**；bed 层按 04 号 §2.4 再 **−6 dB**。

**状态转移（文字版）**：

```
Idle ──narr start──▶ DuckBGM(bgm −8 dB, bed 再 −6 dB, ramp 0.3 s)
DuckBGM ──narr end───▶ RampBack(0.3 s 恢复)
DuckBGM ──更高优先级(ui/gateway)──▶ PassThrough（不叠加闪避，见下）
PassThrough ──事件毕──▶ DuckBGM
DuckBGM/RampBack ──同互斥组新事件──▶ 交叉 40 ms 抢占（§3）
```

- 1.0 多厅并发跨厅闪避规则：**近厅为主、远厅按衰减让位**——玩家所在厅为「主厅」（全响），相邻厅 bgm/narr 按 20 号 §4.2 逆距离衰减叠加；跨厅 narr 不与主厅 narr 同时升（远厅 narr 触发时只 -12 dB 预览，不抢占）[需实机核对：双厅声场]。

## 5. 总线路由与区域混响

- 四母线对齐 20 号 §4.1：**厅母线**（bed/bgm/narr/ui 子层）、**设备母线**（run/grab/bed）、**模拟器音频母线**（audio_chunk 直通零处理）、**UI 母线**（单声道→双耳直送）。
- 1.0 新增 **per-hall reverb zone**：每厅一个 Zone3D，混响发送量（建模口径）——主厅 0.20、辅厅 0.12、走廊/过渡区 0.05、出口 0.08；跨厅发送按「接收者在两 zone 的权重线性混合」[需实机核对：Godot Reverb bus 实现路径]。

## 6. 生命周期与资源预算

| 预算项 | 数值 |
|---|---|
| streaming pool | 全局 32 路（§3） |
| 每厅并发上限（1.0 多厅预算表） | bgm ≤1 + bed ≤1 + narr ≤1 + run ≤3 + sfx ≤6 = **单厅 ≤12 声** |
| 四厅同开最坏 | 4×12 = 48 > pool 32 → 触发降级 |
| 超预算降级 | 按优先级淘汰：先 bed 后 bgm，再 run，再 sfx；**narr/ui/gateway 永不淘汰**（缺声记 warn + 日志） |
| 回收 | 停止条件命中即回收：播完/离半径/互斥抢占/急停开关；回收延迟 ≤ 1 帧 |

## 7. 与网关 audio_chunk 直通互斥

- 对齐 20 号 §4.3、40 号 run_speaker_beep：**gateway 直通期间，同设备本地合成 run 类（run_transformer/run_fan/run_relay）暂停**，避免同源双响；直通信号音量挂 04 号 §4「模拟器音频 90%」轨。
- **断连保护**：网关停发 ≥ **500 ms** → 直通淡出 + 本地合成 run 类自动接管；重连 <500 ms 内恢复直通无爆音（20 号 §4.3 断路保护口径）。
