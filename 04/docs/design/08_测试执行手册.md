## 9. 常见失败模式与对策（执行者速查）

| 失败现象 | 首要怀疑点 | 对策（按序） |
|---|---|---|
| start_device_ack 超时 | 网关未起/端口错 | `heartbeat` 探活；查 7331 是否被占；回 §6.1 重起 |
| frame_chunk 收不齐 total | 客户端重组键混帧 | 按 (device_id,frame_id) 归组；丢老帧的 keep 队列超 200 条清 oldest |
| load_state_ack.frame_id 不回跳 | 快照 id 不存在或后端不支持 | 先 `save_state` 再 `load_state`；查 error{NOT_FOUND} 顺序 |
| 崩溃后收不到 restarting | config.auto_restart 意外为 false | 查 start_device config 回显 `info.auto_restart` |
| RESTART_EXCEEDED 提前到来 | 后端启动即崩（如 auto_crash_frame 过小） | auto_crash_frame ≥3；确认失败计数清零规则（PROTOCOL §10.4-4） |
| input_ack 串设备 | 客户端 device_id 拼错 | 断言只匹配目标 device_id（m1_check recv pred 范式） |
| 手工档 toast 不出 | Godot 订阅 status 状态未接 | 检查 06 号 FUNC-004 状态机与 gateway_client 事件桥 |
| VR 面板不面向玩家 | 面板未挂 Camera3D 对齐逻辑 | 03 号 §6.3 锚角表复核 |

> 以上对策不改动规格；若对策无效，按 09 号 §3 贴证并转入 DEFECT 流程，不得现场绕过（绕过视为用例未执行）。
