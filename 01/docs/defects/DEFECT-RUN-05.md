# DEFECT-RUN-05（实机首验缺陷 · closed）

> 状态：**closed（2026-11-05 修复提交 02dd2d7）** · 修复已入 main
> 复现环境：Godot 4.4 · 用户实机按 F5 · 项目"警告即错误"开启
> 档案补登：本档案由 06 线 debug 专员按 git 提交记录补登（原档欠登）；现象为按修复 diff 与项目已知前科反推，用户原始报屏未存留。

## 现象（表现错误 · 无报错但不对）

点选设备"时中时不中"：鼠标被环视捕获（captured）时，视觉上把画面中心准星对准
设备点击却点不中；按 Esc 释放鼠标后，又按屏幕真实鼠标位置拾取——行为随捕获状态漂移。

## 根因

点选拾取依赖 `_update_hover(event.position)`。玩家环视使用捕捉鼠标模式
（血泪坑清单第 4 条：鼠标坐标**永远在屏幕中心**），而左键点击分支未强制以
中心准星为拾取点，拾取位置与用户预期（准星所指）不一致；未捕捉时行为又切换为
真实屏幕坐标，两种模式互相打架。

## 修复（提交 02dd2d7 前半）

左键按下时强制中心准星拾取：

```gdscript
MOUSE_BUTTON_LEFT:
    _dragging = event.pressed
    if event.pressed:
        # 鼠标被玩家环视捕捉时事件坐标恒为屏幕中心——点选即"准星拾取"
        _update_hover(get_viewport().get_visible_rect().size * 0.5)
```

## 复盘

- 点选系统定性为"画面中心准星拾取"，任何后续拾取逻辑不得按屏幕鼠标位置编写
  （已固化为血泪坑清单第 4 条）。
- 悬停（mouse motion）通道仍用 event.position：捕捉模式下恒为中心，恰好与准星拾取
  语义一致，无需改动；但若未来玩家改为非捕捉环视，悬停通道需并轨此修复。
