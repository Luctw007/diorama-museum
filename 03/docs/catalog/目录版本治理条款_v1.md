# 目录版本治理条款 v1

> 03 线 TASK-163-A 交付。固化「同一大类目录只保留一个活跃版本、发新版必先撤旧版」的治理条款，防止通讯目录 v2/v3 并存触发 CC-02 重复 id 的事故再犯。

## 一、治理条款（每条四要素：规则 → 适用对象 → 归档去向 → 门禁检查）

### 条款 1：一条目录只保留一个活跃版本
- **规则**：同一大类目录（计算机 / 通讯与移动）在 `docs\catalog\` 活跃位置任何时刻只允许存在一个版本的 `.jsonl` + `.md`。
- **适用对象**：`docs\catalog\` 下所有 `*大类_目录_vN.jsonl` 与 `*大类_目录_vN.md`。
- **归档去向**：旧版一律移出活跃位置（见条款 2/3）。
- **门禁检查**：`catalog_ingest --from-work --gate`（CC-02 跨文件 id 唯一）+ `catalog_check.py`（CC-02 批内跨文件联合查重）。

### 条款 2：发新版必先撤旧版
- **规则**：升级版本（v2→v3 等）时，**先**把旧版 `.jsonl` + `.md` 移动到归档位置，**再**写入新版；顺序不可颠倒。
- **适用对象**：任何一次目录版本升级。
- **归档去向**：v2 及以上旧版 → `docs\migrate_backup\`；v1 旧版 → `docs\catalog\_v1归档\`。
- **门禁检查**：移动后立即跑 `catalog_ingest --from-work --gate`，确认无重复 id（否则「双活」会被 CC-02 抓到 306 条级重复）。

### 条款 3：归档命名保留版本号
- **规则**：归档文件名必须带 `_vN` 后缀（如 `通讯与移动大类_目录_v2.jsonl`），禁止去掉版本号同名覆盖，保证历史可溯。
- **适用对象**：`docs\migrate_backup\`、`docs\catalog\_v1归档\` 下的归档文件。
- **归档去向**：`docs\migrate_backup\`（v2+）或 `docs\catalog\_v1归档\`（v1）。
- **门禁检查**：无直接门禁，靠人工核名 + 盘点表（附录）兜底。

### 条款 4：门禁复测义务
- **规则**：任何目录改动（含移动旧版、写新版、改 status 字段）后，必须立刻跑 `catalog_ingest --from-work --gate` + `catalog_check.py`，确认 0 重复 id、0 FAIL 才算完成。
- **适用对象**：所有涉及 `docs\catalog\` 文件增删改的操作。
- **归档去向**：不适用（流程条款）。
- **门禁检查**：`catalog_ingest --from-work --gate`（0 FAIL）+ `catalog_check.py`（CC-01~08 全过）。

## 二、事故复盘（通讯目录 v2/v3 并存）

**时间线**：
1. TASK-63-B 产出通讯目录 v2（306 条）为活跃版本。
2. TASK-135 按《年代字段回填规范_v1》升级产 v3，**未撤 v2**，导致 `docs\catalog\` 下 v2/v3 并存。
3. `catalog_check` CC-02 跨文件查重报 **306 个重复 id**（v2 与 v3 全量同 id），门禁失败。
4. 统筹处置：把 v2 的 `.jsonl` + `.md` 移入 `docs\migrate_backup\`，v3 保留活跃；复测门禁 **37/37 全绿**。

**根因**：升级版本时「只写新版、未撤旧版」，违反「一条目录一个活跃版本」原则，触发 CC-02 跨文件唯一约束。

**本条款如何逐条堵根因**：
- 条款 1 从「状态」上禁止双活；条款 2 从「动作顺序」上强制先撤旧版；条款 3 保证归档可溯；条款 4 把「复测」固化为强制义务——任一环节落地都能拦住这次事故。
