## 一、gd 脚本方法名不与 Godot 原生方法冲突（v0.6.3-01）

- **描述**：gd 脚本自定义方法名不得与 Godot `Object`/`Node` 原生方法重名。命名前自查黑名单
  （非穷举，命中即改）：`get_index` / `get_meta` / `get_name` / `get_parent` / `get_class` /
  `get_path` / `get_child` / `get_node` / `set_meta` / `set_name` / `has_method` 等。
- **反例**：RUN-01 `device_loader.gd` L242 `get_index()` 与 `Node.get_index(bool)` 签名冲突、
  L254 `get_meta()` 与 `Object.get_meta(StringName, Variant)` 冲突 → 脚本整张未加载 → 空厅。
- **违规判定**：gd 内定义的 `func` 名命中 `Object`/`Node` 原生方法名集合 → FAIL；命名前自查，
  冲突即改名（如 `get_index`→`get_device_index`、`get_meta`→`get_device_meta`）。

## 二、`:=` 推断纪律：Variant 三元必须显式标注类型（v0.6.3-02）

- **描述**：项目开启"警告即错误"；`:=` 推断类型时，凡结果可能为 `Variant`（三元两分支不收敛、
  动态调用返回值），必须显式标注类型（`: String` / `: Dictionary` / `: Array` / `: Variant`），
  不得裸 `:=` 让编译器推断出 Variant 而顶格报错。
- **反例**：RUN-01 `device_loader.gd` L88 / L110 两处裸 `:=` 推断 Variant；RUN-02
  `inspect_controller.gd` L149 `var role := ...get_node_role(...) if ... != null else ""` 三元两分支
  不收敛 → 推断 Variant → warning-as-error 顶格错误 → 点选系统无响应。
- **违规判定**：`:=` 右侧为三元表达式或动态调用（返回 Variant）且左侧未显式标注类型 → FAIL。
  修正：`var role: String = ...`。

## 三、class_name 新增/改名后的缓存重载约定（v0.6.3-03）

- **描述**：凡新增 / 改名 `class_name`，或改动脚本间类型标注引用，必须删除引擎缓存目录
  `.godot/` 后重开引擎（提示 Reload 选 Reload），否则 Godot 沿用旧类表继续报"类名未注册"。
- **反例**：RUN-03 `device_loader.gd` 补 `class_name DeviceLoader` 后，须删 `01\godot\.godot\`
  缓存；若脚本间用类型标注引用另一脚本，被引用脚本必须显式 `class_name`。
- **违规判定**：提交含 class_name 变更的 gd 但未在提交说明 / 自查里注明"删 .godot 缓存重载" →
  提示级；类型标注引用了未注册类名 → FAIL。

## 四、白模占位内容包材质约定（v0.6.3-04）

- **描述**：白模占位网格可能**没有材质**（`material_override == null`）。引擎高亮 / 选中系统必须
  对无材质网格**现建 `StandardMaterial3D` override**，不得以 `material_override is
  StandardMaterial3D` 为前置条件而让高亮成死路。
- **反例**：RUN-07 `_set_selected` 仅在 `mi.material_override is StandardMaterial3D` 时才点亮；
  白模占位网格无材质 → 条件恒假 → 高亮永不生效，交互观感等于"点了没反应"。
- **违规判定**：高亮 / 选中逻辑以 `material_override is StandardMaterial3D` 为前置条件且无 null
  分支现建 override → FAIL。修正：`if mat == null: mat = StandardMaterial3D.new(); mi.material_override = mat`。

## 五、引擎对内容输入一律"可降级"处理（v0.6.3-05）

- **描述**：引擎侧对内容包字段（`meta` / `annotations` / glTF）一律按"可降级"处理——字段缺失、
  类型不符时回退默认值或跳过，**不得崩溃**（本项目"降级表"原则）。
- **反例**：RUN-04 `explode_controller.gd` 未防御非法输入：装配体条目缺 `transform` 键时
  `entry.get("transform")` 返回 null，旧代码 `null.get("translation", ...)` 直接崩溃；`parent`
  指向不存在装配体时 `_axis.get(null, ...)` 崩溃 → 拆解三态无响应。
- **违规判定**：引擎代码对内容字段取值后未判空 / 判型即继续链式调用 → FAIL。修正：先取值后判型、
  父级缺失回退到自身轴。

## 六、点选拾取统一"准星拾取"语义（v0.6.3-06）

- **描述**：捕捉鼠标模式下鼠标坐标**恒在屏幕中心**。点选拾取一律以画面中心准星为拾取点，任何
  后续拾取逻辑不得按屏幕鼠标位置编写。
- **反例**：RUN-05 左键点击分支未强制以中心准星为拾取点，捕捉 / 非捕捉两种模式行为漂移 →
  点选"时中时不中"。
- **违规判定**：拾取逻辑在鼠标捕捉模式下使用 `event.position` 而非屏幕中心
  （`get_viewport().get_visible_rect().size * 0.5`）→ FAIL。

## 七、视角/交互参数收敛为具名常量（v0.6.3-07）

- **描述**：视角（FOV）、移动速度、高亮色等交互参数不得散落为魔法数字，应聚到脚本顶部常量区
  （如 `FOV_DEFAULT` / `FOV_MAX`），初始值在 `_ready` 显式设置。
- **反例**：RUN-06 `player.gd` 滚轮 FOV 钳制上限散落为 `100.0`（广角透视畸变），且 `_ready`
  未显式设初始 fov → 依赖相机默认值。
- **违规判定**：交互参数以字面量散落在函数体内（且影响观感 / 多处复用）→ 提示级。修正：
  `const FOV_DEFAULT := 70.0; const FOV_MAX := 85.0`。

## 八、生成物不入库（缓存/帧/临时产物 ignore 约定）（v0.6.3-08）

- **描述**：引擎缓存（`.godot/`）、demo 帧 / 临时输出（`demo_out*/`、`slots/_drill/`）、
  `__pycache__/`、`*.pyc` 等生成物一律进 `.gitignore`，不入版本库。
- **反例**：RUN-03 涉及 `.godot/` 缓存目录（改 class_name 后须删除重载）；工程 `.gitignore`
  已列 `demo_out/`、`__pycache__/`、`*.pyc` 等（81-B git 化约定）。
- **违规判定**：版本库 / 提交中出现上述生成物 → 回退该提交、补 `.gitignore`。
