| `research_doc` | string | 否 | 调研文档路径 |

### 1.2 裁决理由（为何英文，而非采纳中文键）

**裁决：统一英文键，05 线中文字段列为"非规范写法"并给出迁移对照表。** 理由三条：

1. **机器可读惯例**：JSONL 是机器摄取/校验的权威格式，键名用 ASCII 英文是跨语言工具链的通行
   惯例（中文键在部分 CSV/JSON 工具里易出编码与列名漂移）；
2. **01 线摄取器已按英文键实现**：`catalog_ingest._adapt` 的内部统一键就是英文（name/aliases/
   manufacturer/…），采纳英文键与摄取器零返工；
3. **03 线已产 463 条英文键**：让 463 条英文键迁到中文，比让 05 线 425 条中文键迁到英文更不经济。

英文键名取自 03 线的实际字段（`manufacturer/era/taxonomy_path/influence/verify`），语义比草案的
`maker/year/path/reason` 更直白（manufacturer 比 maker 明确、taxonomy_path 比 path 无歧义），故
定稿一并吸收 03 线命名。

## 二、三级分类裁决：允许两级（第三级"未细分"）

### 2.1 裁决

**`taxonomy_path` 允许两级或三级；两级时第三级视为"未细分"。**

### 2.2 触发条件

- **三级（推荐）**：中分类下能明确细分出子分类时，写满三级，如 `["计算机","个人机","PC 兼容"]`。
- **两级（允许）**：中分类下暂无法细分、或细分无实际策展价值时，省略第三级，如
  `["家电影音","影音播放机"]`——机器语义等价于 `["家电影音","影音播放机","未细分"]`。

### 2.3 理由

首批普查中，05 线"家电影音与外设"大类大量条目只写到两级（如"影音播放机"没有第三级），03 线
"通讯与移动"也有部分两级。强行要求三级会让普查员为了填满第三级而生造无意义的子分类，违背
"分类为策展服务"的初衷。允许两级 + 机器侧补"未细分"，既保留"大/中"的可靠分层，又不逼造数据。
01 线 `catalog_ingest` 已按"补未细分"实现（`len(path)==2 → +["未细分"]`），该实现 = 规范的机器语义。

## 五、给三线的对齐指令

### 5.1 给 03 线（已合规部自查）

03 线 463 条已用英文键，**基本合规**，自查两处：

1. **`alias` → `aliases`**：03 线键名是单数 `alias`，定稿是复数 `aliases`（与"别名数组"语义一致）。
   下一批起改用 `aliases`，存量 463 条由 01 归一层兼容（`pick("aliases","alias",…)`），可不返工。
2. **id 无前缀**：03 线 id 是无前缀英文 slug（如 `acorn-archimedes`、`eniac`），不满足定稿的
   "大类码-中分类码-6 位序号"格式。需向 02 线 `id_registry` 申请正式前缀 id（计算机→`C-*`、
   通讯与移动→`M-*`），slug 可保留为 `aliases` 或 `name`。

### 5.2 给 05 线（中文键迁移清单）

05 线 425 条用中文键，需按 §1.3 的 11 键对照表迁移为英文键。**迁移清单已全量给出（§1.3）**，
迁移动作是"键名替换"（值不变），可脚本化批量完成。id 前缀 `A-*`/`P-*`/`G-*` 已符合定稿大类码
（A/P/G），无需改 id 值，仅中分类码 3~4 字符（ARC/HOME/PER）在定稿允许范围内（2~4 字符），保留。

### 5.3 给 01 线（归一层保留期限）

01 线 `catalog_ingest._adapt` 的三种键格式兼容（英文定稿键/05 中文键/草稿键）**保留**，作为
迁移期的过渡层。**收紧条件**：当 03/05 存量 888 条全部迁移到定稿英文键并通过 catalog_check 后，
`_adapt` 可收紧为"仅接受英文定稿键"，移除中文键与草稿键分支。此前不得移除（否则 05 存量数据
摄取会失败）。

   枚举仍在普查中演进，需 v0.7 吸收 03/05 的实际中分类/子分类值后定稿。

   迁移脚本与回溯台账需后续落。
3. **`verify` 与 `sources` 的关系**：`verify=true` 表示"需核实"，与 `sources` 缺省是否有联动（需核实
   则必须标来源），待定。

   码表（如全部 2 字符），待 v0.7 定。
