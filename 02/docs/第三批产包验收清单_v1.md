## 二、每台产包完成判据（四道验收命令 + rc=0）

> 四道命令均为「产包完成后、目录反链回填后」执行，全部 rc=0 才判定该台过闸。

```
1. python tools/validate/validate.py <包>        → 0 FAIL（rc=0）
2. python tools/validate/model_check.py <包>     → FAIL 0 / WARN 0（rc=0）
3. python tools/validate/catalog_ref_check.py    → REF-01~04 全 0、FAIL 0（rc=0）
4. 目录反链：id_registry allocate 真号后，目录条目回填 device_id=<包 id> + status=done
   → 复跑 catalog_ref_check，REF-02 反链缺失 0
```

> 第 4 道依赖定案四步（用户点头 → 01 线登记 → 02 线 allocate 10 真实 id）完成后方可执行；本清单不 allocate
> （占位 `0xx` 待定案后换真号）。

## 三、逐台验收口径要点（emulator + 需核实）

- **4 台有明确模拟器（GPL/QPL 隔离形态）**：System/370→`hercules`（QPL 已核实，S/370 支持需核实）、
  MSX2→`openmsx`（GPLv2 已核实）、IBM PC XT→`86Box`（GPLv2 已核实，5160 支持需核实）、Macintosh Plus→
  `mini-vmac`（GPL 许可需核实）。四台均在 THIRD_PARTY 标「GPL/QPL 隔离 + 二进制不进仓 + 用户自备」。
- **6 台无成熟模拟器（none 静态+动画）**：Archimedes（Arculator/ArcEm 候选）、ZX81（EightyOne/sz81 候选）、
  SGI Indigo（MAME/QEMU 候选）、Compaq Portable（86Box/PCem 候选）、Whirlwind（无候选）、Newton（Einstein 候选），
  候选记 THIRD_PARTY、缺失作 NOTE 级提示（不算缺口、不进失败判定）。
- **分档**：7 A（1~7）+ 3 B（8~10）；三档硬底线（validate 0 FAIL / REF 四查 0 / THIRD_PARTY 三件套 / id 唯一 /
  反链 REF-02）不降，分档只区分生产深度。

## 四、与任务书的漂移（如实）

1. **包 id 建议为 kebab-case 建议值**（非权威），产包时以 02 线 id_registry allocate 的目录 id + 内容包
   meta.id 为准（内容包 meta.id 即目录 device_id，参考第二批 `altair-8800`/`sparcstation-1` 等）。
2. **validate PASS 数为参考**（约 78/84），硬底线 0 FAIL；实际 PASS 数以件清单为准，本清单不臆造精确 PASS 数。
3. **反链第 4 道依赖定案四步**，本清单不 allocate（占位待换真号），与任务书边界一致。
