## 1. 新断言命名规则

- **命名格式**：`check_<FR域>_<场景>`（全小写下划线）。`<FR域>` 取冻结基准表域字母（a/b/c/d/e/f/g/h/i/j 域），`<场景>` 用 ≤3 词的英文短语。
- 合法示例：`check_e8_manual_mode`、`check_e9_gw_disconnect`、`check_g3_load_missing`、`check_i4_snapshot_isolation`、`check_f2_pkg_version_gate`、`check_e4_media_magic`。
- **非法示例**（红线）：`check_T043`、`check_crash_test`、`check_桃子_崩溃`、`QA_check_1`。
- 每条断言**必须先在 08 号 §2.1 登记草案**（编号 草案 A~G 等），随实现把草案提升为正式断言并回填 08 号对照表 → 状态列改「已覆盖」。
- 断言函数实现约定（与 m0/m1_check 同风格）：
  ```python
  def check_e8_manual_mode(client) -> None:
      ...
  ```
  - 成功：调用 `check(True, "描述")`（沿用 m1_check 的 PASSED 计数）；
  - 失败：`raise AssertionError("超时等待 <消息名>")`；退出码 0/1 语义与 m1_check 一致。
- **断言归属**：网关级断言放 `01/repo/scripts/`（后续并入 m2_check.py [TBD]）；Godot 侧单元假放 `01/repo/godot/tests/`。

## 2. 日志格式约定

### 2.1 网关 stderr（已有，遵守即可）

- 每行一条：`[时间] [级别] 消息`；启动/崩溃/重启/快照事件必须含 `device_id`。
- 崩溃与恢复专行（供 T-043~T-052 取证）：
  ```text
  [2026-11-01T10:00:00] [ERROR] device d-crash1 PROCESS_CRASHED (exit=1)
  [2026-11-01T10:00:01] [INFO]  device d-crash1 auto_restart -> restarting attempt=1
  [2026-11-01T10:00:02] [INFO]  device d-crash1 load __auto (frame=17)
  [2026-11-01T10:00:04] [ERROR] device d-deg RESTART_EXCEEDED (3 次失败) -> degraded
  ```
- 失败贴证时**必须附 stderr 尾部 ≥40 行**（m1_check `_dump_gateway_tail` 同源）。

### 2.2 Godot 客户端日志（新增，供手工档取证）

- 格式：`[HH:MM:SS.mmm] [FR-E8a] T-043 崩溃弹层已显示 (trigger=status:crashed)`。
- 每条手工用例执行时打 3 类日志：`[T-xxx] 步骤n 开始`、`[T-xxx] 观察点 达成/失败`、`[T-xxx] 结束 通过/未通过`。
- 日志文件滚存：`godot/user://logs/acceptance/YYYYMMDD_HHMM.log`；一天一个文件；失败行前缀 `FAIL`。

## 3. 失败贴证要求

| 档位 | 贴证物（缺一不可） |
|---|---|
| 自动化 | ① 断言名+失败描述 ② 网关 stderr 尾部 ≥40 行 ③ 触发该失败的最小 JSON 命令序列（可复现） |
| 手工 | ① 执行记录表行（08 号 §3 模板）② 失败现场截图（`shot/` 或日志路径）③ 步骤√ 编号 |
| 待实机 | ① 设备/固件版本（头显型号、运行时版本）② 录像 ≥10 s 或截图 ③ 复现步数 |

- 提交入口：失败贴证进 `04/repo/docs/design/defects/`（本轮新建），文件名 `DEFECT-<T编号>-<日期>.md`；同用例二次失败追加 `-r2`。
- 无贴证的失败视为「未发生」（不可计入回归结论）。

## 4. 与 11-B（m1b_check）衔接条款

1. **分工**：m1 三件套 = 网关协议全链路（08 号自动档）；m1b = 内容包 runtime → 网关映射桥（run_profile 映射、sinks、键名、首键注入）。**互不越界**：内容包字段问题归 m1b 断言（`check_` 前缀同规则），网关行为问题归 m1/m2。
2. **联合触发点**：08 号 T-023/024/025/026 的「补验」消息序列（fake 320×240@24 起设备）允许被 m1b 的 `start_and_check` 复用；若两者同轮执行，端口必须错开（GW_TEST_PORT 17333 / 17334 默认即可）。
3. **版本门槛**：m1b 的 `run_profile.py` 映射结果要求 spec_version=0.1 通过校验（R-071）；apple-ii 包若升 spec_version，须先过 TASK-02 校验器再进 m1b。
4. **双线结论合并**：每日回归结论 = m1（08 自动档）+ m1b + 手工最小集 10 条，三份结论并表（模板见 08 号 §3）。v2.0 起每日口径跟随 08 号 §4.2（m0+m1b+内容包校验），m1 全量与手工 10 条为发版前口径；本句以 08 号 v2.0 §4.2 为准。

### 4.5 缺陷提级模板（v2.0 修订）

> 适用：round_N 复测仍失败、需跨线提级时。表单经 04 线填写后随 DEFECT 报告 `round_N 复测结果` 节一并归档 `design/defects/`；**闭环（复测通过）时无需提级**（round_2 两缺陷即属此情形，未触发本模板）。

| 字段 | 填写要求 |
|---|---|
| 缺陷编号 | 沿用 DEFECT-<M域>-<主题>-NN 或 DEFECT-<T编号>-<日期>，二次复测失败加 `-r2` |
| 轮次链 | 首报 round → 修复声明的 round → 本次复测 round |
| 复测结论 | 通过/失败 + 失败断言原文贴出（含实测值） |
| 归口线（提级对象） | 首报归口线；若其修复声明与复测事实不符，注明「修复声明未在代码/包中核验到」 |
| 漏斗影响 | 逐条列出被搁置的下游用例编号与档位（如「T-023/027/028 手工档 + T-024/026 待实机档」）；写明漏到终端的影响描述 |
| 复测要求 | 提级后下一轮必须复核的最小集（脚本名+端口+关键断言） |
| 处置权限 | 04 线从不替归口线改产物；只记录、提级、跟踪（本次 19-A 条款） |

## 7. 断言生命周期管理（登记 → 草案 → 实现 → 回填 → 退役）

1. **登记**：新需求先在 08 号 §2.1 增行（草案编号连续）。
2. **草案**：写判定要点（不写完整代码），TASK-13A 报告同步清单。
3. **实现**：01 线翻译为 `check_<FR域>_<场景>` 函数并入 m2_check.py [TBD]，同步沿用 GatewayClient/check 风格。
4. **回填**：实现通过首轮回归后，08 号对照表状态列改「已覆盖」，草案标记 [已实现]。
5. **退役**：FR 变更导致断言失效时，由 04 线裁决删除并在 08 号记 [已退役+原因]；禁止静默移除。
6. **版本**：一切断言变更走 `docs/design/` 提交历史，与代码库解耦但同日归档 round 报告。

## 8. 与 m0_check 的回归链

- m0_check（TASK-06 前的基础链路）→ m1_check（网关 v2 全链路）→ m1b_check（内容包映射桥）→ m2_check（13A 新增草案）构成**四级漏斗**；任何一级红灯，下游手工档不出车。
- 日常顺序固定：m0 → m1 → m1b → m2 草案 → 手工最小集；总时长控制在单次集成窗口内（目标 ≤20 min [TBD]）。
- 各级失败归口：m0/m1 失败归 01 线网关；m1b 失败归 02/03/05 线内容包与 run_profile；m2 草案失败按 FR 域归口（E 域归 01、F/G 域归 05）。

## 9. 日志级别定义表（网关 stderr + Godot 日志共用）

| 级别 | 用法 | 示例事件 |
|---|---|---|
| ERROR | 断言失败/崩溃/协议违规 | PROCESS_CRASHED、贴证失败行 |
| WARN | 可恢复异常/降级 | RESTART_EXCEEDED 前的第 2 次失败、鼠标边界音触发 |
| INFO | 正常流程里程碑 | start/stop/load __auto/用例步骤 |
| DEBUG | 开发期细节 | 每条 JSON 消息（验收轮关闭） |

规则：验收轮运行 DEBUG 默认关闭，防止刷屏；ERROR 行必须可 grep（统一 `[ERROR]` 前缀）。
