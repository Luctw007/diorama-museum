# 提交清单（内容包三件套 + 模板）

> 按此核对后跑《自测命令卡.md》。device-id：kebab-case，全局唯一。

## 一、内容包目录必须含

```
content/<device-id>/
  meta.json                    # 见下方最小模板（必含 meta 块：id/name{zh,en}/spec_version/category/era）
  runtime.json                 # emulator/demo_mode/output_sinks/input_map（demo 起步可 emulator="none"）
  THIRD_PARTY.md               # 每行：素材名 | 分档 | 来源URL | 日期（R-091 一一对应）
  annotations/annotations.json # {"annotations":[...]}，≥30 条，id 唯一
  assemblies/*.gltf            # 网格节点名 = meta.assemblies[].id
  encyclopedia.md              # ≥2500 字（早期包口径）
```

## 二、meta.json 最小模板（注释仅示意，JSON 不放注释）

```json
{
  "meta": {
    "id": "my-device",
    "name": {"zh": "设备中文名", "en": "Device Name"},
    "spec_version": "0.2",
    "category": "personal-computer",
    "era": 1985,
    "assemblies": [{"id": "whole", "name": "整机", "children": []}]
  },
  "runtime": {"emulator": "none"},
  "components": [],
  "annotations": []
}
```

## 三、槽位（模拟器）manifest 样例

见同目录 `slot_manifest.sample.json`——新模拟器一律走槽位声明，字段含义：
slot_id / device_class / backend_type / description / license / binary_env /
media_classes / keymap。

## 四、目录条目（入库必回填，REF-02 反链义务）

在对应大类 `*.jsonl` 追加一行（字段与主仓库该文件现有行一致，示例形态）：

```json
{"id": "C-PC-999999", "name": "My Device", "aliases": [], "manufacturer": "厂商",
 "origin": "国别", "era": 1985, "taxonomy_path": ["计算机", "个人机", "子类"],
 "influence": "一句话重要性。", "status": "done", "device_id": "my-device",
 "verify": false, "sources": ["贡献者"], "research_doc": null}
```

要点：`status` 必须 `done`、`device_id` 必须等于你的包 id、id 全局唯一不重复、
taxonomy_path 三级齐全。以上由主仓库 catalog_ref_check 机器把关。
