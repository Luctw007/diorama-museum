## 一、总则

### 1.1 内容包定义

一个「设备内容包」（下称内容包）是对**一台设备**的完整数字化描述，供博物馆引擎加载、装配、标注、动画与模拟。一个内容包 = 一个目录，目录名即 `device-id`，位于 `content/<device-id>/` 之下。

内容包由两部分构成：
1. **契约数据**：`meta.json`（DeviceSpec）、`runtime.json`（RuntimeProfile）、`annotations/annotations.json`（标注集）、`THIRD_PARTY.md`（许可清册）——**机器可校验**的权威数据。
2. **资产数据**：`assemblies/`、`meshes/`、`materials/`、`sounds/` 下的网格、材质、音频等资源。

### 1.2 版本规则

- 内容包自身版本：`meta.version`，遵循 SemVer 2.0.0。
- 规范版本：`meta.spec_version`，本规范为 **`"0.2"`**。
- 引擎最低版本：`meta.engine_min_version`，SemVer；低于此版本必须拒绝加载。

> v0.3 是**规范文档**版本，未改变 `meta.spec_version` 的取值（仍 `"0.2"`），因未引入字段结构级变更。

### 1.3 度量与坐标系

- **单位**：一律**米**（SI），1 单位 = 1 米，1:1 真实比例。
- **坐标系**：**Y-up、右手系**（+X 右、+Y 上、+Z 朝向观察者），与 **Godot 4 一致**。
- **旋转**：单位四元数 `[x,y,z,w]`（模长 1，容差 1e-3）。

> **DCC 导出约定**：Blender 等建模工具默认 +Z 上，导出 glTF 时由导出器自动 +Z→+Y（glTF 规范为
> Y-up）；关键是把**单位比例设为 1.0（米）**并 **Apply All Transforms**。详见第十三章 §3。

### 1.4 glTF 要求

- 所有网格资源使用 **glTF 2.0**（`.gltf` 或 `.glb`），`asset.version` 为 `2.x`。
- 米制、Y-up、右手系；差异在导入时烘焙，不得依赖运行时翻转。
- **网格节点命名**：装配体所引用 glTF 的**场景根节点名必须等于该装配体 `node_id`**（R-090）。
  网格（mesh）名用 `<node_id>_mesh` 惯例（非硬约束）。详见第十三章 §2.2。

## 二、目录结构

```
content/<device-id>/
├── meta.json                 # DeviceSpec（元数据 + 装配树 + 元器件 + runtime 内嵌副本）
├── runtime.json              # RuntimeProfile（与 meta.json.runtime 逐字节等价）
├── THIRD_PARTY.md            # 第三方资产许可清册（必填）
├── README.md                 # 作者说明（脚手架生成，可选）
├── assemblies/               # 装配体级 glTF（命名 <assembly-id>.gltf，R-090 用）
├── meshes/                   # 网格 glTF/glb（命名 <mesh-id>.gltf / .glb，R-090 用）
├── materials/                # 材质定义（命名 <material-id>.json；可选）
├── sounds/                   # 音频（命名 <sound-id>.wav/.ogg；可选）
└── annotations/
    └── annotations.json      # 标注集（必填）
```

| 文件/目录 | 必填 | 格式 | 说明 |
|---|---|---|---|
| `meta.json` | 是 | JSON（UTF-8） | DeviceSpec，见第三章 |
| `runtime.json` | 是 | JSON（UTF-8） | RuntimeProfile，见第七章；与 `meta.json.runtime` 逐字节等价（R-004） |
| `THIRD_PARTY.md` | 是 | Markdown | 许可清册，见第八章 |
| `annotations/annotations.json` | 是 | JSON（UTF-8） | 标注集，见第六/十章 |
| `assemblies/`、`meshes/`、`materials/`、`sounds/` | 否 | — | 资源目录，可为空 |

> **`assemblies/` 与 `meshes/` 并存**：`mesh_ref` 指向哪个目录就以哪个为准（27-A 实测：pdp8 /
> atari-2600 用 `assemblies/`，其余用 `meshes/`）。loader 按 `mesh_ref` 定位，天然兼容。

**路径约定**：资源引用一律使用**相对 `content/<device-id>/` 的 POSIX 路径**（正斜杠），禁止绝对路径或 `..` 跳出。

| `manufacturer` | string | 否 | — | — |

## 五、资产预算与精度分级

### 5.1 精度分级（整机档，L1–L4）

| 分级 | 单模型三角面 | 整机节点 | 纹理分辨率 | 动画总时长 | 适用场景 |
|---|---|---|---|---|---|
| L1 | 2,000 | 50 | 512×512 | 60 s | 快速原型 / 占位 |
| L2 | 20,000 | 500 | 2048×2048 | 180 s | 默认交付 |
| L3 | 200,000 | 5,000 | 4096×4096 | 300 s | 高精度 |
| L4 | 2,000,000 | 50,000 | 8192×8192 | 600 s | 展示级特写 |

### 5.2 三档距离 LOD（单装配体档，新增）

在整机档 `precision_level` 之外，每个装配体按**观察距离**分三档 LOD（Godot 惯例：LOD0 = 最近最高）：

| 档 | 观察距离 | 单装配体三角面上限 | 纹理上限 | 对应精度级 |
|---|---|---|---|---|
| **LOD0 特写档**（高模） | <0.5m | 50,000 | 4096 | L3 |
| **LOD1 观察档**（中模/默认） | 1–2m | 20,000 | 2048 | L2 |
| **LOD2 远景档**（低模） | >2m | 8,000 | 512 | L1 |

> 判定：`meta.precision_level`（L1→LOD2、L2→LOD1、L3/L4→LOD0），未声明默认 LOD1。超预算 WARN、
> 超 1.5 倍 FAIL（MR-002）。整机三角面上限 **400,000**（Godot 4 中端 VR 单帧预算的约 5%）。
> 数字为 v0.3 起始值（可调），量级吸收 05 线 19 号冻结表。

## 六、标注内容规范

标注集存放于 `annotations/annotations.json`，为 `{ "annotations": [ ... ] }`。每条标注：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | 是 | snake_case，R-022 |
| `type` | string | 是 | `role`/`flow`/`anim` |
| `target` | string | 是 | assembly/component id，R-015 |
| `text` | string | 是 | 标注正文（中文） |
| `text_en` | string | 否 | 英文文案 |
| `surface` | string | 否 | 关联输出 surface（R-085） |
| `timeline` | array | 否 | 动画/流程时间轴（anim/flow 用） |
| `sources` | array\<string\> | 否 | 来源 URL，R-063 |

- **role**：作用说明，除根外须含「在整机」（R-061），20–200 字（R-062）。
- **flow**：信号/能量/数据流，写明起点→路径→终点。
- **anim**：动画/交互行为，写明触发条件、动作、时序。
- 文案红线：正式文案不得出现未定标记（`需核实`/`TBD`/`TODO`/`待定`/`XXX`/`???`）。

## 十一、输出 Sink 与输入映射

### 11.1 Sink 命名枚举（R-084）

`internal_crt`/`external_crt`/`terminal`/`led`/`handheld_lcd`/`speaker`/`crt_display`(兼容)/`indicator_lamps`(兼容)。

### 11.2 input_map 键名全集（R-086）

- **对象格式为推荐唯一新格式** `{map, key}`；`map` ∈ keyboard/mouse/joystick；`key` 见全集表。
- **legacy 字符串令牌为 deprecated 兼容窗口**；移除触发条件 = 全部量产包对象化完成 + 评审通过。
- **keyboard 全集** = Godot `Key` 枚举 `KEY_*` 大写全集（字母序）+ 项目扩展 3 键（KEY_POWER/KEY_RESET/KEY_REPEAT）。
- **joystick 全集**：`axis_x`/`axis_y`/`btn0`…`btn31`/`hat_0`…`hat_3`。
- **mouse 全集**：`motion`/`btn_left`/`btn_right`/`btn_middle`/`wheel_up`/`wheel_down`。

（完整枚举表见 v0.2.1 §11.2.3，本版沿用不变。）

### 11.3 与 01 线 PROTOCOL.md（v2）对齐

`input_event.key` 仍为小写物理键名（`a`/`space`/`enter`），故「`KEY_*` → 键码」翻译层仍必需；sink 路由 v2 已实现（config.sinks + light_state + speaker）。

## 十三、建模与网格（v0.3 新增）

> 本章为 22-B 草案定稿，吸收 27-A 实测与 05 线 19/20 号冻结表反馈。适用于 `assemblies/`、`meshes/` 下的正式 3D 资产。

### 13.1 网格组织

- **一个装配体 = 一个 .gltf 文件**：装配体声明 `mesh_ref` 即其网格为独立 `.gltf`/`.glb`，文件名 `<assembly-id>.gltf`。允许一个 glTF 内多 `mesh`/`node`，但**场景根节点唯一**。
- **元器件默认不单独成文件**，作为所属装配体 glTF 内的子节点；"明星件"（cpu 等）才拆独立 mesh。
- **多 node 拆分 vs 合并 mesh**：依据是"运行时是否需单独寻址"（高亮/动画/点选才拆），不是建模方便。

### 13.2 节点命名（R-090 延续，MR-001）

- glTF **场景根节点 name = 装配体 `node_id`**（R-090 硬约束，MR-001）。
- 根 `mesh` 名用 **`<node_id>_mesh`** 惯例（非硬约束；与存量占位盒 `panel_mesh`/`whole_mesh` 一致）。
- 子网格节点名 `<assembly-id>_<子部件>`，snake_case，文件内唯一。

### 13.3 坐标系与单位

- 1:1 米制、+Y 上右手系（+X 右、+Y 上、+Z 朝观察者），与 Godot 4 一致。
- **Blender → Godot 导出对照**：Blender 单位 Scale=1.0（米）、导出 glTF 选 +Y Up、导出前 Apply All Transforms；+Z→+Y 由导出器自动完成。

| 项目 | Blender（+Z 上） | Godot 4（+Y 上） | 转换 |
|---|---|---|---|
| 单位比例 | Unit Scale=1.0，Length=Meters | 1 单位=1 米 | 比例须 1.0 |
| 上轴 | +Z | +Y | 导出器自动 +Z→+Y（绕 X −90°） |
| 变换 | 导出前 Apply All | — | 避免烘焙缩放/旋转 |
| 材质 | Principled BSDF | StandardMaterial3D | metallic/roughness 直接映射 |

### 13.4 三档距离 LOD 预算

见第五章 §5.2（LOD0 特写 50k / LOD1 观察 20k / LOD2 远景 8k，单装配体；整机 ≤400k）。

**同一装配体三档完整性（增量交付）**：外观（外观壳）→ 内部蒙皮（+内壁）→ 内部结构（+板卡/元器件），三者是**同 node_id 的增量替换**关系。

### 13.5 材质与 PBR 贴图

- 统一 **metallic-roughness PBR** 管线。
- **贴图后缀**：`_basecolor` / `_normal` / `_metallic`（或 `_metallic_roughness`）/ `_emissive`（MR-003）。
- **ORM 三通道打包**（推荐，省采样）：R=Occlusion、G=Roughness、B=Metallic（吸收 05 线 20 号）。
- **material-id 命名**：`mat_<材质>_<色系>`，如 `mat_abs_beige`、`mat_fr4_green`、`mat_steel_galvanized`（R-017 引用）。
- **纹理尺寸**：2 的幂（512/1024/2048/4096），≤ 档位上限（MR-003 按 2048 判）。

**复古设备材质预设组**：

| material-id | 材质 | metallic | roughness | 代表 |
|---|---|---|---|---|
| mat_abs_beige | 米黄 ABS 塑料 | 0.0 | 0.85 | 机箱/软驱壳 |
| mat_fr4_green | 绿色 FR-4 PCB | 0.0 | 0.70 | 主板 |
| mat_steel_galvanized | 镀锌钢板 | 0.90 | 0.35 | 屏蔽盒 |
| mat_ceramic_dip | 陶瓷 DIP | 0.0 | 0.60 | 芯片 |
| mat_metal_gold | 金手指/焊盘 | 1.0 | 0.25 | 槽金手指 |
| mat_speaker_paper | 纸盆 | 0.0 | 0.95 | 扬声器 |
| mat_crt_glass | CRT 屏面 | 0.0 | 0.10 | 屏面 |

**纹理来源红线**：自产（AI 生成 + 人工核对）或 CC0/权利明确第三方；版权照片绝不入库；商标元素只登记不呈现；键帽/丝印字符自绘。第三方纹理登记 THIRD_PARTY 三件套。

### 13.6 glTF 版本约束

- glTF 2.0，三角形 primitive（mode=4），索引化，POSITION/NORMAL 必填，有纹理 TEXCOORD_0 必填。
- accessor 建议填 `min`/`max`；外壳单面法线朝外，薄壳给实体厚度（2–3mm）。
- 复用几何实例化（同 mesh 多 node），不重复导出键帽/插座。

### 13.7 占位盒 → 正式模型替换协议

1. **同 node_id 即换**：正式网格同名替换占位盒（节点名/文件名不变），`meta.json` 的 `mesh_ref`、`assemblies[].id` 不动，loader 零改动。
2. `.gltf`↔`.glb` 切换时同步 `mesh_ref` 扩展名（唯一允许的 meta 改动）。
3. **增量交付**：先外观壳 → 内部蒙皮 → 内部结构，各阶段单独合入（validate + model_check 全绿）。

### 13.8 校验规则（MR-001~004，`model_check.py`）

| 规则 | 判定 | 实现 |
|---|---|---|
| MR-001 节点命名 | 根节点 name=node_id；多根 WARN | model_check.py |
| MR-002 三角面预算 | 对照三档预算；超预算 WARN、超 1.5 倍 FAIL | model_check.py |
| MR-003 贴图引用 | 后缀表 + 尺寸 ≤2048 且 2 幂 | model_check.py |
| MR-004 扩展白名单 | 未知 KHR_* 扩展 WARN | model_check.py |
