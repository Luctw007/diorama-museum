## 一、设计总则

### 1.1 骨架复用

`m2a_check.py` 复用 01 线 `m0_check.py` / `m1_check.py` 的**连接与断言骨架**（`GatewayClient` 极简 TCP JSON-lines 客户端、`FrameAssembler` 分片重组、`check()` 断言、`collect_frames()` 收帧、网关子进程拉起 + stderr 尾部 dump），仅替换三处：① `emulator` 改为 `mame-apple2`；② `config` 增补 `frame_codec`/`sinks`；③ 断言口径从 fake 的"彩色帧"改为"Apple II 分辨率 + rgba8 + 开机特征"。骨架详情见 16-A `m2_assert_draft.md` 与本目录 17 号台本的映射对照。

### 1.2 帧格式对齐说明（rgb8 → rgba8）

PROTOCOL.md v2 §4.2 的 `frame_ready.format` 目前为 `rgb8`（RGB24，width×height×3），而 `runtime.json` 的 `crt_internal` sink 与 16-A/本批规格为 **rgba8**（width×height×4）。二者存在一处**传输层 vs 内容包层**的对齐差异。本批 m2a 断言以 **rgba8**（内容包 v0.2 sink 口径）为准，并在网关/后端把 `rgb8` 转 `rgba8`（补 alpha=255）的转换点作为一条协议验证点（T-M2-05），记入 §六 需核实清单（与 01 线网关对齐后收敛）。`[需核实]`

### 1.3 双轨执行（fake 先行 → 真实 MAME 替换）

本批采用**双轨**：fake 后端先行跑通全链路断言，真实 MAME `apple2p` 后替换（仅换 `emulator` 与 `config`），接口不变。双轨差异与切换点见 §五。

### 1.4 断言实现伪代码骨架（对齐 16-A m1_check.py）

`m2a_check.py` 主流程与 `m1_check.py` 同构，关键断言片段如下（伪代码，非逐字实现）：

```python
# 启动（T-M2-01）
client.send(start_device(emulator="mame-apple2", device_id="dev1",
    config={"frame_codec": "raw", "sinks": ["main", "led"]}))
ack = client.recv(type == "start_device_ack")      # 断言 ok == True

# 收 5 帧（T-M2-02）
frames = collect_frames(client, "dev1", FrameAssembler(), 5)
for f in frames:
    assert f["frame_id"] 连续递增                    # 1,2,3,4,5
    assert f["format"] == "rgba8"
    assert len(base64.b64decode(f["data_b64"])) == f["width"] * f["height"] * 4

# 分辨率断言（T-M2-03）
assert frames[0]["width"] == 560 and frames[0]["height"] == 384

# 开机特征（T-M2-04）：解 RGBA 后统计非全黑 + 帧间差异
assert max_pixel(frames[0]) > 0
assert frame_diff(frames[0], frames[1]) > 0

# 输入（T-M2-11）：注入 key_a → 回显
client.send(input_event(map="keyboard", key="a", value=True))
ia = client.recv(type == "input_ack"); assert ia["key"] == "a" and ia["value"] is True

# 存档（T-M2-21/22）：保存 → 推进 → 回滚
client.send(save_state(id="s1")); sa = client.recv(save_state_ack); F = sa["frame_id"]
# ... 继续收帧推进到 F + Δ ...
client.send(load_state(id="s1")); la = client.recv(load_state_ack)
assert la["frame_id"] == F                          # 帧号回到保存点
```

要点：所有断言复用 `m1_check.py` 的 `check()`/`collect_frames()`/`FrameAssembler` 骨架，仅把"彩色帧尺寸"改为"560×384 rgba8 + 开机特征"，把真实 MAME 下的"crash 键崩溃注入"替换为调试开关模拟（13 号 §十三）。fake 与真实 MAME 两轨共用同一脚本，仅切换 `--emulator` 与 `--config`。

### 1.5 验收脚本参数与卫生约定

沿用 `m1_check.py` 的既有约定：测试端口由环境变量 `GW_TEST_PORT` 覆盖（默认 17333）；启动前清理历史持久化快照（`tempfile` 下的 `diorama_*.json`，对齐 04 线 DEFECT-M1-ROLLBACK-01 备注的"洁净环境"建议，避免上一轮快照干扰回滚断言）；网关以子进程拉起（`--host 127.0.0.1 --port`），失败时 dump 网关 stderr 尾部以定位；退出码 0 = 全过、1 = 失败。真实 MAME 轨额外要求：`MAME_BIN` 环境变量指向 MAME 二进制、ROM/媒体目录经 `config` 传入（对齐 16-A 在网关注册表的 `binary_env`/`binary_hint` 登记，缺二进制时后端回 `error(EMULATOR_BINARY_MISSING)` 优雅降级）。

## 二、M2.1 画面（≥5 帧 rgba8、分辨率断言、开机特征）

### T-M2-01 · 启动进入 running 并收到首帧

| 要素 | 内容 |
|---|---|
| 前置 | 网关已就绪；`mame-apple2` 已注册（`list_emulators` 含之）；`config` 指定 `frame_codec=raw`、`sinks=["main","led"]` |
| 步骤 | 发 `start_device(emulator=mame-apple2, device_id=dev1, config)` → 等待 ack 与事件流 |
| 预期 | 收到 `start_device_ack(ok=true)`，`info` 回显 `width/height/fps/frame_codec/sinks/auto_restart`；随后收到 `status(state=running)` 或 `state` 流；首个 `frame_ready` 到达 |
| 协议验证点 | `start_device_ack.ok==true`；`info.width/height` 与预期分辨率一致；`state` 经历 `starting→running`（PROTOCOL §6） |

### T-M2-02 · 连续收 ≥5 帧且格式 rgba8

| 要素 | 内容 |
|---|---|
| 前置 | dev1 已 running |
| 步骤 | 用 `FrameAssembler` 收 5 个完整帧（`collect_frames(dev1, 5)`） |
| 预期 | 5 帧 `frame_id` 从 1 起连续递增（1,2,3,4,5）；每帧 `format=rgba8`；解码后数据长度 = width×height×4 |
| 协议验证点 | `frame_ready.frame_id` 连续；`format=="rgba8"`；`len(data)==w*h*4`；无 `frame_chunk`（raw 未触发分片）或分片重组正确（若 `force_chunk`） |

### T-M2-03 · 分辨率断言（Apple II 文本/图形尺寸）

| 要素 | 内容 |
|---|---|
| 前置 | 收到 ≥1 帧 |
| 步骤 | 断言帧的 `width/height` |
| 预期 | `width=560, height=384`（280×192 高清的 2× 整数放大，见 13 号 §14）；或按 `start_device_ack.info` 回显尺寸一致 |
| 协议验证点 | `frame.width==560 and frame.height==384`（或与 ack.info 一致）；尺寸为偶数倍放大、无非整数缩放伪影 |

### T-M2-04 · 开机画面特征验证（非全黑 + 有变化）

| 要素 | 内容 |
|---|---|
| 前置 | 收到 ≥3 帧 |
| 步骤 | 对每帧解出 RGBA 后统计：① 非全黑（存在非零像素）；② 相邻两帧存在像素差异（画面在变化） |
| 预期 | 开机画面非全黑；连续帧之间有像素变化（花屏→光标→DOS 提示符的过渡可见） |
| 协议验证点 | `max_pixel > 0`；`帧间 diff > 0`；作为"画面存活"的冒烟证据（对齐 TASK-01 彩条帧链路） |

### T-M2-05 · rgba8 转换点与 sink 路由

| 要素 | 内容 |
|---|---|
| 前置 | dev1 running，`sinks=["main","led"]` |
| 步骤 | 观察帧的 `sink` 字段与 `light_state` |
| 预期 | 帧 `sink=="main"`；`light_state`（led）至少 2 条且开/关交替；若后端出 rgb8，网关/后端补 alpha 后以 rgba8 上行（转换点） |
| 协议验证点 | `frame.sink=="main"`；`light_state.on` 交替；rgba8 转换点的 `alpha==255` 一致性（`[需核实]` 与网关对齐） |

## 五、双轨执行表（fake 先行 → 真实 MAME 替换）

| 用例 | fake 先行 | 真实 MAME `apple2p` 替换 | 切换点 |
|---|---|---|---|
| T-M2-01 启动 | fake 立即 running | 需 ROM/盘就绪，否则 `error(EMULATOR_BINARY_MISSING/MEDIA_MISSING)` | `emulator` 换 `mame-apple2`；config 加 media 路径 |
| T-M2-02/03 帧与分辨率 | fake 任意尺寸彩色帧 | Apple II 560×384 rgba8（280×192 ×2） | 断言尺寸改为 560×384 |
| T-M2-04 开机特征 | 彩条/彩色变化帧 | 花屏→光标→DOS 提示符 | 特征从"非全黑"升级为"提示符 `]` 出现" |
| T-M2-11~15 输入 | fake 回显任意键 | MAME `natkeyboard:post`（13 号 §3.1） | 输入注入通道从 fake 直通改 Lua/管道 |
| T-M2-21~25 存档 | fake 保存 frame_id 计数 | MAME `machine:save/load`（13 号 §3.1） | 快照语义从 JSON 计数改 MAME save state |

**执行顺序**：先 `fake` 全绿（锁协议层）→ 换 `mame-apple2`（锁真实模拟器层），两者共用 `m2a_check.py` 骨架，仅改 `--emulator` 与 `--config` 参数。真实 MAME 替换需先做 13 号 §十六的三项 spike（V12/V13/V15 已解决，见 13 号 §十八）。

### 5.1 协议消息时序（文字版）

**M2.1 画面**：客户端发 `start_device` → 网关下发 `start` 给后端 → 后端回 `state(starting)` → 首帧产出后回 `state(running)` → 网关回 `start_device_ack(ok)` → 后端持续上行 `frame_ready(frame_id=1..N)`（网关包装广播）→ 若 `sinks` 含 `led`，另有 `light_state` 交替。断言点：ack.ok、state 顺序（starting→running）、frame 连续、格式 rgba8、尺寸 560×384。

**M2.2 输入**：客户端发 `input_event(map=keyboard,key=a,value=true)` → 网关透传 `input` 给后端 → 后端执行注入并回 `input_ack` → 网关包装广播 `input_ack`。断言点：回显字段一致；REPT/RESET 在回显之外还需观察帧变化作为语义证据（复位画面、重复按键）。

**M2.3 存档**：`save_state(id=s1)` → 后端 `machine:save` → 完成后回 `ack(op=save_state,frame_id=F)` → 网关广播 `save_state_ack`；推进若干帧后 `load_state(id=s1)` → 后端 `machine:load` → `post_load_notifier` 触发回 `ack(op=load_state,frame_id=F)` → 网关广播 `load_state_ack` → 帧号回跳。断言点：帧号语义、`NOT_FOUND` 错误、关机后持久化（跨进程 `load` 成功）。
