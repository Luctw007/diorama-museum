## 二、镜像同步要求（内容包 + 目录 jsonl 反链同步）

1. **内容包 + 目录 jsonl 同步镜像**：镜像 7 台 ready 时，`sync_monorepo.py` 须**同时**收口内容包目录
   与对应目录 jsonl（含反链行），不能只镜像内容包漏镜像目录反链。
2. **消除 hp-2100 stale（本轮关键修复）**：镜像 `03/docs/catalog/计算机大类_目录_v2.jsonl` 中 hp-2100
   条目现为 `status=planned / device_id=null`，而共享盘已 `status=done / device_id=hp-2100`——镜像目录
   **陈旧未同步**，导致 hard 门禁 catalog_ref 报「完工包 hp-2100 无目录反链」FAIL（40/41 误报）。收口时
   必须用共享盘最新目录 jsonl 覆盖镜像，使 hp-2100 反链同步到位。
3. **`/MIR` 镜像语义**：`sync_monorepo.py` 用 robocopy `/MIR`（镜像目录独有 0 时无删风险，211-B 已实测
   「镜像独有 0、干净」），确保共享盘删旧版文件时镜像同步删除，不再出现 v2/v3 并存（此前 306 重复 id
   教训）。

## 三、收口后校验步骤

1. `python .\01\scripts\sync_monorepo.py --dry-run`（`/MIR` 核对删除清单，本轮镜像独有预期 0）；
2. `python .\01\scripts\sync_monorepo.py`（四线镜像，rc≤7 即成功）；
3. **hard 门禁复测**（收口后核心验证）：
   ```
   py -3.7 .\01\scripts\verify_all.py --daily --cache
   ```
   预期：**48 步左右全 PASS、rc=0**（当前 41 步 + 第二批 7 台 ready = 48 步；家电影音 5 台 WIP 不增 pkg 步）。
   其中 `catalog_ref` 预期 **FAIL 0**（hp-2100 反链同步 + 7 台反链齐，REF-02 归零）。
4. **catalog_ref REF-02 归零验证**：镜像后 `catalog_ref` 应 REF-01~04 全 0、`FAIL 0`；若有残留 REF-02
   （如某台 ready 反链未同步），回到第 1 步核对目录 jsonl 同步范围。
5. **ci 包装器镜像视图 FAIL 归零**：`scripts/catalog_ref_ci.py` 单独运行时基径与镜像布局不一致（211-B
   已记录「内容包 0 个」），权威口径以 verify_all 内嵌 02 检查器为准；收口后确认 verify_all 内 catalog_ref
   FAIL 0 即可，ci 包装器基径对齐为后续独立项（记录，不在本口径阻塞）。
6. `release_check.py`（FAIL 0）+ 人工 `git add -A → commit → push`（01/docs/github_setup.md §3）。

## 四、WIP 五台入镜像的处置口径

1. **不入 ready、不阻塞门禁**：crt-tv / cd-player / dvd-player / vhs-vcr / walkman-tpsl2 五台**仅有
   assemblies gltf、无 meta.json/runtime.json**，属 WIP（`pkg_registry._is_wip` 三选一：无 meta 结构件），
   镜像后**不进 ready、不产生 `pkg:*` 步、不进失败判定**。
2. **镜像时机**：WIP 五台**可随镜像同步**（`/MIR` 会把共享盘内容包目录带过去），但**不参与 hard 门禁**
   ；也可等完工后随下一批镜像，二选一由统筹定，本口径推荐「随镜像同步、只进 ready 判据不参与门禁」。
3. **完工后入 ready**：五台补 meta/runtime/THIRD_PARTY/annotations 结构件 + 删 WIP 判据 + `validate 0 FAIL`
   + 目录反链 done 后，才在下一轮镜像入 ready（对应 `第二批分档验收口径_v1.md` WIP 升档规则）。
