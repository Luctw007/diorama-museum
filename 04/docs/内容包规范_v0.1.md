## 一、总则

### 1.1 内容包定义

一个「设备内容包」（下称内容包）是对**一台设备**的完整数字化描述，供博物馆引擎加载、装配、标注与模拟。一个内容包 = 一个目录，目录名即 `device-id`，位于 `content/<device-id>/` 之下。

内容包由两部分构成：
1. **契约数据**：`meta.json`（DeviceSpec）、`runtime.json`（RuntimeProfile）、`annotations/annotations.json`（标注集）、`THIRD_PARTY.md`（许可清册）——这些是**机器可校验**的权威数据。
2. **资产数据**：`assemblies/`、`meshes/`、`materials/`、`sounds/` 下的网格、材质、音频等二进制/文本资源。

### 1.2 版本规则

- 内容包自身版本：`meta.version`，遵循 [SemVer 2.0.0](https://semver.org/lang/zh-CN/)（`主.次.修订`，可带 `-预发布`、`+构建元数据`）。
- 规范版本：`meta.spec_version`，本规范为 `"0.1"`。
- 引擎最低版本：`meta.engine_min_version`，SemVer。内容包声明它依赖的引擎最低版本；引擎低于此版本时**必须拒绝加载**该包。

### 1.3 度量与坐标系

- **单位**：一律**米**（SI）。1 单位 = 1 米，模型按 **1:1 真实比例**建模。
- **坐标系**：**Y-up、右手系**（+X 右，+Y 上，+Z 朝向观察者）。
- **旋转**：采用**四元数** `[x, y, z, w]`，必须是**单位四元数**（模长 = 1，容差 1e-3）。

### 1.4 glTF 要求

- 所有网格资源使用 **glTF 2.0**（`.gltf` 或 `.glb`），`asset.version` 必须为 `2.x`。
- 网格内单位同样为米、Y-up、右手系；如源资产为其他坐标系，须在导入时烘焙变换，**不得**依赖运行时翻转。
- v0.1 阶段网格仅要求「文件存在且可解析」，几何合法性（法线、非退化）不在自动校验范围（见第九章 R-041/R-042 降级说明）。

## 二、目录结构

每台设备的目录布局固定如下（相对 `content/<device-id>/`）：

```
content/<device-id>/
├── meta.json                 # DeviceSpec（设备元数据 + 装配树 + 元器件 + runtime 内嵌副本）
├── runtime.json              # RuntimeProfile（与 meta.json.runtime 逐字节等价）
├── THIRD_PARTY.md            # 第三方资产许可清册（必填）
├── assemblies/               # 装配体级 glTF（可选；命名 <assembly-id>.gltf）
├── meshes/                   # 网格 glTF/glb（命名 <mesh-id>.gltf / .glb）
├── materials/                # 材质定义（命名 <material-id>.json；可选）
├── sounds/                   # 音频（命名 <sound-id>.wav/.ogg；可选）
└── annotations/
    └── annotations.json      # 标注集（必填）
```

| 文件/目录 | 必填 | 格式 | 说明 |
|---|---|---|---|
| `meta.json` | 是 | JSON（UTF-8） | DeviceSpec，见第三章 |
| `runtime.json` | 是 | JSON（UTF-8） | RuntimeProfile，见第七章；内容须与 `meta.json.runtime` **逐字节等价**（R-004） |
| `THIRD_PARTY.md` | 是 | Markdown | 许可清册，见第八章 |
| `annotations/annotations.json` | 是 | JSON（UTF-8） | 标注集，见第六章 |
| `assemblies/` | 否 | — | 装配体资源；为空目录亦可 |
| `meshes/` | 否 | — | 网格资源；`assembly.mesh_ref` 引用其内文件 |
| `materials/` | 否 | — | 材质资源 |
| `sounds/` | 否 | — | 音频资源 |

**路径约定**：`mesh_ref` 等资源引用一律使用**相对 `content/<device-id>/` 的 POSIX 路径**（正斜杠 `/`），不得使用绝对路径或 `..` 跳出设备目录。

## 三、DeviceSpec 字段字典

DeviceSpec 是 `meta.json` 的根对象，含四个顶层键：`meta`、`assemblies`、`components`、`runtime`。可选顶层键 `$schema` 指向本规范 schema。**顶层禁止未声明的额外字段**（`additionalProperties: false`）。

### 3.1 `meta`（设备元数据）

| 字段 | 类型 | 必填 | 取值范围 / 默认 | 校验规则 |
|---|---|---|---|---|
| `id` | string | 是 | kebab-case，`^[a-z][a-z0-9]*(-[a-z0-9]+)*$` | R-020 |
| `name` | string | 是 | 非空 | 设备中文名 |
| `name_en` | string | 否 | — | 英文名 |
| `spec_version` | string | 是 | 固定 `"0.1"` | R-071 |
| `version` | string | 是 | SemVer | R-070 |
| `engine_min_version` | string | 是 | SemVer | R-072 |
| `precision_level` | string | 是 | `L1`/`L2`/`L3`/`L4` | R-040，见第五章 |
| `authors` | array | 否 | `author` 对象数组 | — |
| `description` | string | 否 | — | 设备概述 |
| `category` | string | 否 | — | 设备类别（如 handheld/console/computer…） |
| `sources` | array | 是（可为空） | `source` 对象数组 | R-052/053/054 |

#### `author` 对象

| 字段 | 类型 | 必填 |
|---|---|---|
| `name` | string | 是 |
| `contact` | string | 否 |
| `role` | string | 否 |

#### `source` 对象（来源引用，见第八章许可分档）

| 字段 | 类型 | 必填 | 取值范围 | 校验规则 |
|---|---|---|---|---|
| `type` | string | 否 | `documentation`/`photo`/`manual`/`video`/`scan`/`audio`/`other` | — |
| `title` | string | 否 | — | — |
| `url` | string | 是 | `^https?://` | R-052 |
| `license` | string | 是 | `public_domain`/`cc`/`licensed`/`visual_reference_only` | R-053（四档） |
| `accessed_at` | string | 是 | `YYYY-MM-DD` | R-054 |

### 3.2 `assemblies`（装配体数组）

装配体 = 树节点。整机为**根装配体**（`parent: null`）。每项字段：

| 字段 | 类型 | 必填 | 说明 | 校验规则 |
|---|---|---|---|---|
| `id` | string | 是 | 节点 id，snake_case | R-021/023 |
| `name` | string | 是 | 显示名 | — |
| `role` | string | 是 | 作用文案（见第六章） | R-061 |
| `transform` | object | 是 | 见 3.5 | R-030~033 |
| `parent` | string \| null | 是 | 父装配体 id；根为 `null` | R-010 |
| `children` | array\<string\> | 是 | 子装配体 id 列表 | R-011/012/013 |
| `components` | array\<string\> | 是 | 挂载的元器件 id 列表 | R-014（反向） |
| `annotations` | array\<string\> | 是 | 标注 id 列表 | R-018 |
| `mesh_ref` | string | 否 | 网格 glTF 相对路径 | R-016/041/042 |

**装配树规则**：装配体构成一棵（或多棵）树；`parent` 与 `children` 必须**双向一致**（A.parent=B ⟺ B.children 含 A），且**无环**。根装配体允许 `children` 为空（单节点设备）。

### 3.3 `components`（元器件数组）

元器件 = 装配树的**叶节点**（不可再有子节点），挂在某装配体之下。

| 字段 | 类型 | 必填 | 说明 | 校验规则 |
|---|---|---|---|---|
| `id` | string | 是 | 节点 id，snake_case | R-021/023 |
| `name` | string | 是 | 显示名 | — |
| `type` | string | 是 | 元器件类型（如 `ic`/`capacitor`/`resistor`/`connector`…） | — |
| `role` | string | 是 | 作用文案（**必须含「在整机」**） | R-061 |
| `assembly` | string | 是 | 所属装配体 id | R-014 |
| `annotations` | array\<string\> | 是 | 标注 id 列表 | R-018 |

### 3.4 `runtime`（内嵌 RuntimeProfile）

与 `runtime.json` 内容**逐字节等价**（R-004）。字段见第七章。

### 3.5 `transform`（变换）

| 字段 | 类型 | 必填 | 说明 | 校验规则 |
|---|---|---|---|---|
| `translation` | array\<number\> | 是 | `[x,y,z]`，米 | R-030 |
| `rotation` | array\<number\> | 是 | `[x,y,z,w]` 四元数，单位 | R-031 |
| `scale` | array\<number\> | 是 | `[sx,sy,sz]`，各分量 > 0 | R-032/033 |

变换按 glTF 语义解释：局部坐标 = `T * R * S`（先缩放、再旋转、再平移）。

## 四、命名规范

| 对象 | 正则 | 风格 | 示例 | 校验规则 |
|---|---|---|---|---|
| `device-id` | `^[a-z][a-z0-9]*(-[a-z0-9]+)*$` | kebab-case（连字符） | `test-device`、`gb-dmg-01` | R-020 |
| 节点 id（assembly/component） | `^[a-z][a-z0-9_]*$` | snake_case（下划线） | `mainboard`、`chip_cpu` | R-021/023 |
| 标注 id | `^[a-z][a-z0-9_]*$` | snake_case | `mainboard_role` | R-022 |
| output_sinks 的 `id`/`surface` | `^[a-z][a-z0-9_]*$` | snake_case | `screen_0`、`screen` | R-022 |
| 文件名 | `^[a-z][a-z0-9_]*(\.[a-z0-9]+)?$` | snake_case + 小写扩展名 | `mainboard.gltf` | 约定 |

约定补充：
- 允许的扩展名：`.json` `.gltf` `.glb` `.bin` `.png` `.jpg` `.jpeg` `.wav` `.ogg` `.md` `.txt`。
- `THIRD_PARTY.md` 为保留名，不受上述文件名正则约束。
- 所有 id **全局唯一**（assembly 与 component 共享同一命名空间，不得重名或跨界重名）。
- 小写字母开头，仅小写字母、数字、下划线（device-id 另加连字符）；禁空格、禁中文、禁大写。

## 五、资产预算与精度分级

每台设备声明一个精度分级 `meta.precision_level`。各级**面数/节点/纹理预算**如下（**v0.1 起始值，可调**，不是绝对真理）：

| 分级 | 单模型三角面上限 | 整机节点数上限 | 纹理分辨率上限 | 适用场景 |
|---|---|---|---|---|
| L1 | 2,000 | 50 | 512×512 | 快速原型 / 占位 |
| L2 | 20,000 | 500 | 2048×2048 | 默认交付 |
| L3 | 200,000 | 5,000 | 4096×4096 | 高精度 |
| L4 | 2,000,000 | 50,000 | 8192×8192 | 展示级特写 |

**v0.1 校验策略（降级）**：`validate.py` 的 R-041 仅校验「glTF 存在且可解析」，R-042 仅做**统计输出**（节点数、三角面数），**超限不阻塞 PASS**。精确的预算比对由 `tools/validate/budget_check.py` 单独提供（`python budget_check.py <gltf> --level L2`），供作者自查优化。原因：v0.1 阶段 glTF 几何可能尚不完整，机械预算阻断会误伤。此降级策略在完成报告中明示，后续版本可将 `budget_check` 合并进 `validate` 并升级为阻塞规则。

## 六、标注内容规范

标注集存放于 `annotations/annotations.json`，为 `{ "annotations": [ ... ] }` 结构。每条标注：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | 是 | snake_case，R-022 |
| `type` | string | 是 | `role`/`flow`/`anim` 三者之一 |
| `target` | string | 是 | 标注对象：assembly 或 component 的 id，R-015 |
| `text` | string | 是 | 标注正文 |
| `sources` | array\<string\> | 否 | 来源 URL 列表，R-063 |

### 6.1 三类标注写法

- **`role`（作用）**：说明该装配体/元器件在整机中的作用。**除根装配体外，正文必须包含「在整机」字样**（R-061）。字数 20–200（R-062）。根装配体及其 `role` 标注描述整机本身，豁免「在整机」要求。
- **`flow`（流程）**：描述信号/能量/数据流，须写明**起点 → 路径 → 终点**。
- **`anim`（动画/交互）**：描述动画或交互行为，须写明**触发条件、动作、时序**。

### 6.2 文案红线

- 正式文案（`text`、`role`、`description`）**不得**出现未定标记：`需核实`、`待核实`、`TBD`、`TODO`、`FIXME`、`待定`、`XXX`、`???`（R-060）。有疑问的内容应移入「开放问题清单」（见完成报告模板），而非留在正式文案里。
- 来源引用：`sources` 给出 URL 时，须为 http/https 且可追溯（R-063）；正文可用 `[来源: <URL>]` 或依赖 `sources` 字段。

## 七、RuntimeProfile 规范

RuntimeProfile 描述设备如何运行。字段：

| 字段 | 类型 | 必填 | 说明 | 校验规则 |
|---|---|---|---|---|
| `emulator` | string | 是 | 模拟器 id，`^[a-z][a-z0-9_-]*$` | v0.1 已定义 `fake` |
| `version` | string | 是 | 模拟器/运行时版本，SemVer | — |
| `system` | string | 是 | 模拟的系统名 | — |
| `media_hint` | string | 是 | 介质提示枚举（下表） | — |
| `bios_required` | boolean | 是 | 是否需要 BIOS | — |
| `bios_guide_url` | string \| null | 是 | BIOS 获取指引；`bios_required=false` 时为 `null` | — |
| `output_sinks` | array | 是 | 输出端点数组 | R-022 |
| `input_map` | object | 是 | 逻辑动作名 → 物理输入路径 | — |

### 7.1 `media_hint` 枚举

`none`（无介质）/ `cartridge`（卡带）/ `disk`（磁盘）/ `firmware`（固件）/ `tape`（磁带）/ `cd_rom`（光盘）/ `floppy`（软盘）。

### 7.2 `output_sinks`（输出端点）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | 是 | snake_case，R-022 |
| `surface` | string | 是 | surface 名，snake_case（如 `screen`/`speaker`），R-022 |
| `type` | string | 是 | `video`/`audio`/`hid` |
| `format` | string | 否 | 如 `rgba8`/`pcm16` |

### 7.3 `input_map`（输入映射）

键为**逻辑动作名**（snake_case），值为**物理输入路径**（点分，如 `joypad.start`）。

**通用键名集合（v0.1 自定）**：`power`、`reset`、`start`、`select`、`dpad_up`/`dpad_down`/`dpad_left`/`dpad_right`、`a`、`b`（可按设备扩展，如 `x`/`y`/`l`/`r`）。

> **开放问题（网关协议对齐）**：TASK-01 的 `PROTOCOL.md` 尚不存在，本键名集合为 v0.1 自定。待 PROTOCOL.md 发布后，`input_map` 键名与物理路径格式须与其消息定义对齐，并升版本规范。

## 八、THIRD_PARTY.md 模板与许可分档

### 8.1 许可分档（四档）

| 分档 | 英文枚举 | 说明 | 填写要求 |
|---|---|---|---|
| 公共领域 | `public_domain` | 无版权限制 | 来源 URL + 获取日期 |
| CC | `cc` | 署名/共享等 CC 条款 | 来源 URL + 获取日期 + 具体 CC 协议与署名 |
| 授权许可 | `licensed` | 已获授权 | 来源 URL + 获取日期 + 授权方与范围 |
| 仅视觉参考 | `visual_reference_only` | 仅参考，不直接用于最终资产 | 来源 URL + 获取日期 + 声明未使用原始资产 |

自产/原创资产标注为 `原创`（original），**无需**来源 URL 与获取日期。

### 8.2 模板

```markdown
# THIRD_PARTY.md — 第三方资产许可清册

| 资产 | 类型 | 许可分档 | 来源 URL | 获取日期 | 说明 |
|---|---|---|---|---|---|
| <资产名> | <网格/贴图/音频/文档> | <公共领域/CC/授权许可/仅视觉参考/原创> | <http(s) URL，原创填 - > | <YYYY-MM-DD，原创填 - > | <说明/署名> |

## 声明
- 本包未包含任何无授权或版权不明的第三方资产。
```

**规则**：除「原创」外，每行**必须**填写「来源 URL」与「获取日期」（R-051）。来源 URL 与获取日期是许可合规的最低可追溯要求。
