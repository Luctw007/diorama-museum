## 〇、总览：只算顺序，不算时间

这是业余项目，不承诺任何日期。路线图以**里程碑的顺序关系**为准：完成上一段的"完成判据"才翻篇，
否则不动下一段。三段里程碑如下：

| 里程碑 | 一句话目标 | 完成判据（摘要） |
|---|---|---|
| **v0.1 demo** | 一台能走、能拆、能查的演示版 | 43 号清单三件套全绿 + 引擎侧门禁 27/27 |
| **v0.2 开源** | 把仓库按开源标准整理、可被社区接手 | LICENSE 复核 + CONTRIBUTING 定稿 + contrib_kit 发布 + monorepo 上线 + issue 模板 |
| **v1.0 全馆** | 四厅内容齐备、镇馆之宝可跑 | 30 台镇馆之宝入馆 + 四厅台本齐 + 模拟器槽位 ≥5 真跑机种 |

## 一、里程碑一：v0.1 demo（当前在做的这一段）

- **目标一句话**：产出一个"黎明厅能走通、一台设备能拆到 L3、三台机器能真跑、图鉴 1484 条能查"的
  可演示版本，并打上 `v0.1` 标签。

- **完成判据**：以 04 线 `43_v01发布验收清单_v1.md` 为裁判书，三件套 16 项全绿：
  1. **A 件套（黎明厅实机 + 一台设备可拆解）**：RC-A-01~A-06 通过（首验 6 步 / 引擎冒烟 22 项 /
     全流程 8 站走通 / 一台设备 L0→L3 拆解 / 爆裂控件 G1~G7 标注 / 低载 HUD 不崩）；
  2. **B 件套（三台真跑）**：RC-B-01~B-05 通过（MAME apple2 / SIMH pdp8 / Stella Atari 2600
     三台真跑 + need_verify 四条打勾 + `verify_all --daily --cache` 全绿）；
  3. **C 件套（图鉴页可用）**：RC-C-01~C-05 通过（1484 条检索 / 条目卡详情 / 筛选 token 三件 /
     总览首页 / 性能基线）。
  - 引擎侧门禁口径：`verify_all` 全绿（27/27 级同源），豁免项须经用户侧书面确认。

- **主要工作项**：引擎侧 Godot 实机联调、MAME/SIMH/Stella 三后端真跑通道、图鉴检索与条目卡、
  拆解状态机与爆裂控件、HUD 与低载稳定性。

- **依赖线**：01 线（引擎/网关/真跑）、03/05 线（内容包与 1484 条目录）、04 线（43 号清单与规格）、
  02 线（规范与校验器已就位，本段主要是供校验口径）。

- **如何判断可以翻篇**：43 号清单 16 项全绿或经用户侧书面豁免，`git tag v0.1` 成功、`git status`
  干净、`git check-ignore third_party/mame/mame` 有输出（二进制红线生效）——三者同时满足才进 v0.2。

## 二、里程碑二：v0.2 开源

- **目标一句话**：把 `v0.1 demo` 整理成"社区能从零接手、按规则贡献、经门禁合入"的开放仓库。

- **完成判据**（五项齐备）：
  1. **LICENSE 复核**：主仓 MIT 边界清晰；GPL 类模拟器（MAME/SIMH/Stella 等）以独立进程隔离的
     证据归档；许可台账（`许可台账_v1.md`）里"待核实"项清零或明确降级；
  2. **CONTRIBUTING 定稿**：`CONTRIBUTING.md` 三路径可照做、红线章可执行（82-A 已起草，本段定稿）；
  3. **contrib_kit 发布**：贡献者工具包（校验器入口 + 样例包 + 模板）打包可下载；
  4. **monorepo 上线**：五线仓库按 81-B git 化，公开可 clone，`.gitignore` 红线生效；
  5. **贡献者 issue 模板**：目录/内容包/槽位三类 issue 模板就位，标注"新手友好"标签。

- **主要工作项**：法务复核、许可台账消疑、CONTRIBUTING 与 ROADMAP 定稿、贡献工具打包、仓库
  公开与 issue 模板。

- **依赖线**：02 线（LICENSE/许可台账/CONTRIBUTING/ROADMAP）、01 线（81-B monorepo 化）、
  03/05 线（许可三件套零异常）、04 线（验收口径）。

- **如何判断可以翻篇**：许可十问全部有明确状态且无"待核实"阻塞项；`git clone` 到干净环境后能
  跑通 `CONTRIBUTING.md` 的"自测口径"（validate 0 FAIL + REF 四查）；第一个社区 issue 能被模板
  接住并流转。

## 三、里程碑三：v1.0 全馆

- **目标一句话**：四厅台本齐备、镇馆之宝 30 台入馆且多台真跑，形成"可运营的全馆体验"。

- **完成判据**（三项齐备）：
  1. **镇馆之宝 30 台入馆**：全馆目录里 30 台核心展品内容包齐（meta/runtime/glTF/annotations/
     encyclopedia/THIRD_PARTY 六件齐），过 validate 0 FAIL；
  2. **四厅台本齐**：黎明厅 / 大型机厅 / 个人机厅 / 游戏机厅四份导览台本定稿并实机可触发；
  3. **模拟器槽位 ≥5 个真跑机种**：至少 5 台设备经真实后端（MAME/SIMH/Stella/Mesen 等）跑起来，
     槽位 manifest 与 `emulators_registry` 一致、许可三件套齐。

- **主要工作项**：30 台核心设备内容包量产、四厅台本与音频工程、槽位系统从"骨架"到"多后端真跑"、
  图鉴从 1484 条扩到全馆、导览动线与 VR/交互打磨。

- **依赖线**：03/05 线（内容包量产 + 目录普查收官）、04 线（台本/音频/验收）、01 线（槽位折叠 +
  多后端）、02 线（规范 v0.7 定稿 + 校验器收敛）。

- **如何判断可以翻篇**：`verify_all` 全馆全绿；四厅台本走查无红字；≥5 台真跑存证；全馆内容包
  的 REF 四查（目录↔内容包引用一致性）0 冲突。

## 四、时间轴小节：如何判断"可以翻篇"

不设日期，只设**翻篇条件**——每段末尾都有一条"如何判断可以翻篇"，它同时是下一段的入口门槛。
翻篇条件的共性：**可机器验证（门禁全绿）+ 可人工确认（用户侧/验收签字）**，缺一不可。任何一段
在翻篇前被发现回退（门禁由绿转红），回到该段修完再走，不跨段带病。

## 五、交叉引用表：社区在哪个阶段能贡献什么

| 阶段 | 社区能贡献什么 | 参考文档 |
|---|---|---|
| v0.1 demo | 基本不接受外部贡献（内容与验收在封版门内） | 43 号清单、81-A 门禁 |
| v0.2 开源 | **目录条目**（一行 jsonl）、**内容包**（六件清单）、**槽位**（manifest）三路径全部开放 | `CONTRIBUTING.md` 三路径 |
| v0.2 开源 | issue 模板启用，可报 bug / 提设备 / 纠目录 | issue 模板（本段产出） |
| v1.0 全馆 | 台本/音频/翻译等策展类贡献开放，镇馆之宝补充提案 | 04 线台本规格、`CONTRIBUTING.md` 红线章 |

> 说明：v0.1 阶段社区能做的是"围观与提建议"；真正"可贡献"从 v0.2 开源开始，这正是三件套
> （CONTRIBUTING / ROADMAP / 许可台账）要在 v0.2 前就位的原因——让社区在仓库公开的那一刻，
> 就有一套能照做的规则、一条能看懂的路线、一份能回指的合规台账。

### 补充：三件套与三里程碑的对应关系

- **CONTRIBUTING**（82-A）对应 v0.2 开源的"贡献入口"，是社区接手的操作手册；
- **ROADMAP**（本文档）对应全程的"顺序地图"，是"现在到哪了、下一步是什么"的路标；
- **许可台账**（87-B）对应 v0.2 的"合规门槛"，是 LICENSE 复核的原料，也是红线章（ROM 不进仓、
  许可三件套）的逐项落点。三者合起来，就是"能进、能懂、能合规"的开源三件套。
