## (a) 概述与历史地位

VAX-11 是 DEC 于 1977 年 10 月 25 日发布、1978 年开始出货的 32 位计算机系列，其中 VAX-11/780 是首款机型 [S37][S38]。名字里的 "VAX" 是 **Virtual Address eXtension（虚拟地址扩展）** 的缩写——它把 PDP-11 的 16 位地址空间一口气扩展到 32 位虚拟地址（4 GB 空间），并通过硬件分页与内存管理把"虚拟内存"真正变成了主流小型机的标配 [S37]。

VAX-11 的历史地位是多重的：

1. **小型机性能的新基准**：VAX-11/780 的运行速度约合每秒一百万条指令（1 MIPS），从此"VAX MIPS"成了一个跨厂商的性能度量单位——业界长期以"多少个 VAX MIPS"来形容一台机器的快慢 [S38]。
2. **VMS 操作系统**：DEC 为 VAX 量身打造的 VMS（后来称 OpenVMS）是一套兼具实时性与多用户分时能力的高可靠操作系统，在银行、电信、制造、科研等领域服役数十年，至今仍有忠实用户 [S37]。
3. **PDP-11 兼容**：VAX 提供 PDP-11 兼容模式，让海量的 PDP-11 软件可以平滑迁移，体现了 DEC 一贯的"兼容继承"哲学 [S37]。
4. **BSD Unix 的重镇**：VAX 也是 BSD Unix 的重要平台（4.xBSD 最初即以 VAX 为主力开发平台），深刻影响了后续 Unix/Linux 生态 [S37]。

从 PDP-11 到 VAX-11，DEC 完成了一次"向上生长"：把小型机的内存空间、寻址能力与可靠性提升到足以承载大型企业应用的级别，直接与 IBM 大型机在中高端市场展开竞争。VAX 的成功也让 DEC 一度成为全球第二大计算机制造商。

对本展厅而言，VAX-11 是"小型机演进主线"的终点站：它证明了一条从 PDP-8（12 位）→ PDP-11（16 位）→ VAX-11（32 位虚拟寻址）清晰可循的技术脉络，也把"虚拟内存""分页""保护环"这些现代操作系统教科书概念带到了台前。

## (c) 工作原理

### 系统框图（ASCII）

```
                        ┌────────────────────────────────┐
                        │          VAX-11 整机            │
                        └────────────────────────────────┘
                                     │
         ┌───────────────────────────┼───────────────────────────┐
         │                           │                           │
         ▼                           ▼                           ▼
 ┌────────────────┐         ┌────────────────┐         ┌────────────────┐
 │   CPU 板组       │◀──────▶│  内存管理单元 MMU │◀──────▶│   主存(半导体)    │
 │ · 16×32 位寄存器  │  虚拟  │  · 分页(512B)     │  物理  │  (可扩展)         │
 │ · ALU / 微码     │  地址  │  · 4 级保护环      │  地址  │                  │
 │ · 指令译码       │        │  · 页表(TLB)      │        │                  │
 └────────────────┘        └────────────────┘        └────────────────┘
         │                          │ 缺页/访问违例
         │                          ▼
         │                  ┌────────────────┐
         │                  │   缺页处理/调度   │  ← 操作系统(VMS)介入换页
         │                  └────────────────┘
         │
         ▼
 ┌────────────────────────────────────────────────────────┐
 │              I/O 子系统（总线适配 + 外设控制器）               │
 │  · 磁盘/磁带 · 终端 · 网络 · 控制台                          │
 └────────────────────────────────────────────────────────┘
```

### 数据流说明

1. **虚拟地址生成**：CPU 的指令/数据访问先产生 32 位虚拟地址。
2. **地址转换（分页）**：MMU 通过页表/TLB 把虚拟地址转换为物理地址；页表项含访问权限与保护环信息 [S37]。
3. **缺页处理**：若目标页不在物理内存，MMU 触发缺页中断，由 VMS 操作系统把页从磁盘调入内存后重试——这是"虚拟内存"让程序以为拥有 4 GB 空间的机制 [S37]。
4. **执行与 I/O**：运算结果写回寄存器/内存；I/O 经总线适配器访问外设。

### 关键子系统职能

- **CPU 与 32 位寄存器组**：16 个 32 位寄存器，PC/SP 亦为普通寄存器（延续 PDP-11 的"寄存器正交"哲学）。
- **内存管理单元 MMU**：分页 + 保护环 + TLB，是"虚拟寻址"的硬件核心，也是本厅原理讲解的主线 [S37]。
- **分页机制（512 字节页）**：固定小页 + 页表层级，支撑虚拟内存与进程隔离。
- **4 级保护环**：核心态/用户态等权限分级，支撑 VMS 的高可靠性与多用户隔离。

> 以上职能描述即未来 FR-C 原理标注素材底稿；因本厅 VAX-11 只做外观级 + 运行方案，标注以整机/机柜/CPU/MMU 层级为主，不逐元件展开。

## (d) 装配体层级树草案

```
VAX-11 整机（机柜级，以 /780 为展示代表）
├── 机柜结构（Cabinet / 机架 + 前面板 + 电源/散热）
├── 电源子系统（多电压直流电源、风冷/散热）
├── CPU 子系统
│   ├── CPU 板组（数据通路 + 寄存器 + ALU）
│   ├── 微程序控制板（VAX 为微程序实现）
│   └── 控制台/诊断板
├── 内存管理子系统
│   ├── MMU / 页表缓存 TLB 板
│   └── 主存模块（半导体内存板 ×N）
├── I/O 子系统
│   ├── 总线适配器（如 Unibus/Massbus 适配）
│   ├── 磁盘控制器 / 磁带控制器
│   └── 终端/通信控制器
└── 外围设备（可作独立展项）
    ├── 磁盘机（RA/RM 系列）
    ├── 磁带机
    ├── 终端（VT 系列）
    └── 控制台终端
```

**逐层要点与建模拆解预算评估（外观级）：**

- **整机→子系统**（约 6–8 节点）：以"机柜 → CPU/内存/I/O → 外设"分层；本厅只做外观级，机柜内部可做"半透明 + 板卡示意"，不逐板逐元件建模。
- **子系统→板卡**（示意级，约 10–20 节点）：CPU/MMU/内存板做示意级"板卡占位"，作为机柜拆开的视觉层次。
- **板卡→元器件**：**不做**（外观级范围外）；重点资源投向整机外观、机柜开合、与"虚拟寻址"原理动画。
- **难度点**：① VAX-11/780 为大型立柜，外观建模工作量大，需平衡精度与预算；② "虚拟寻址/分页/缺页"是抽象概念，须靠动画而非模型表达；③ 若做"运行方案"，终端交互（VMS 控制台）是更务实的可玩出口。

## (e) 百科卡全文（C1 级成品文案）

**DEC VAX-11 —— 把"虚拟内存"变成主流的机器**

1977 年 10 月 25 日，DEC 发布了一台名字有点拗口的计算机——VAX-11/780。VAX 是 "Virtual Address eXtension" 的缩写，直译过来就是"虚拟地址扩展" [S37]。这短短几个字，藏着这台机器最核心的雄心：把计算机的"地址空间"从 PDP-11 的 6 万多个地址，一口气扩展到 40 多亿个——32 位寻址 [S37]。

为什么要这么大的空间？因为 DEC 想让一台"小型机"去做原本只有大型机能做的事：同时服务几十个用户、跑银行交易、管工厂生产、做科学计算。而这一切，都建立在"虚拟内存"这个想法之上——程序以为自己独占了一整片巨大的内存，实际上的内存却可以比它小得多，缺了的"页"由操作系统随时从磁盘上补进来 [S37]。这个今天所有操作系统都离不开的机制，正是 VAX-11 把它变成了小型机上的主流标配。

要理解"虚拟内存"有多神奇，可以想象一位作家在一张无限大的书桌上写作。实际上他的书桌只有普通大小，但每当他要写新的一页，一个"看不见的助手"就会把用不着的那页纸收进抽屉、把需要的那页纸放上来——作家永远感觉不到抽屉的存在，以为桌子真的无限大。VAX-11 的硬件分页机制，扮演的正是这位"助手"的角色：程序永远"以为"自己有 4 GB 内存，实际背后是操作系统在一页页地搬进搬出 [S37]。

VAX-11/780 一问世，就成了衡量计算机快慢的"尺子"。它大约每秒能执行一百万条指令，业界干脆拿它当单位——"1 VAX MIPS"。此后的很多年里，评价一台新机器，人们会说它"相当于多少个 VAX MIPS" [S38]。一台机器能成为整个行业共同的度量衡，这本身就是莫大的殊荣——就像"马力"之于发动机一样，VAX-11 成了计算机性能的"马力"。

DEC 还为 VAX 打造了专属的操作系统 VMS。它可靠、稳定，能扛住银行和电信级别的不间断运行，在关键行业里服役了几十年，直到今天仍有"OpenVMS"的忠实拥趸 [S37]。VMS 的"高可靠"不是口号：它用 4 级保护环把系统核心与用户程序严格隔开，用分页给每个进程独立的地址空间，让一个程序崩溃也拖不垮整台机器——这些设计，正是现代高可用系统的源头之一 [S37]。

而另一边，BSD Unix 也把 VAX 当成了自己的主战场。4.xBSD 最初就是以 VAX 为主力开发平台，从这里走向了更广阔的 Unix/Linux 世界 [S37]。于是 VAX 成了一个奇妙的交汇点：一边是 DEC 自家的高可靠商用系统 VMS，一边是开放自由的学术系统 BSD Unix，两者在同一种硬件上并行生长，各自开枝散叶。

从 PDP-8 的 12 位，到 PDP-11 的 16 位，再到 VAX-11 的 32 位虚拟寻址——DEC 的小型机走完了一条清晰的成长之路，也把"虚拟内存""分页""保护环"这些概念，从教科书带进了真实的机房。VAX 的成功，一度让 DEC 成为全球第二大计算机制造商，也让"小型机"三个字，第一次拥有了与大型机正面叫板的底气 [S37]。

**可以这样看**：去想象它那颗"看不见的助手"——你眼前这台机器里的每一个程序，都活在自己那 40 多亿个地址的"专属宇宙"里，而真正把这宇宙扛起来的，是背后一页页默默搬动的分页机制。这就是"虚拟"二字的浪漫。

**深度解读一：VMS 的"可靠性"，是怎么炼成的。** DEC 为 VAX 打造的 VMS 操作系统，在银行、电信、制造这些"一刻都不能停"的行业里服役了数十年 [S37]。它的可靠性来自一整套严谨的设计：4 级保护环把系统核心与用户程序层层隔开，一个普通程序的崩溃最多只影响它自己，拖不垮整台机器；分页机制给每个进程独立的地址空间，让它们互不踩踏。这套"隔离 + 保护"的思想，后来成为所有现代高可用操作系统（包括今天的 Linux/Windows 内核）的共同基石。

**深度解读二：BSD Unix 的"主场"。** VAX 的另一面，是开放学术世界的心头好。加州大学伯克利分校的 BSD Unix（4.xBSD）最初就是以 VAX 为主力开发平台，虚拟内存、TCP/IP 网络栈这些今天互联网的基石，很多都是先在 VAX 上的 BSD 里打磨成熟的 [S37]。于是 VAX 成了一条奇妙的"双轨"：DEC 用它跑高可靠的商用 VMS，学术圈用它跑开放自由的 BSD Unix——同一种硬件，滋养了两种截然不同又都影响深远的软件文化。

**深度解读三：与 IBM 大型机正面叫板。** VAX 的成功，让 DEC 一度成为全球第二大计算机制造商，也让"小型机"第一次有了与 IBM 大型机正面竞争的底气 [S37]。企业客户突然多了一个选择：不买动辄百万美元的大型机，用几台 VAX 搭起一个"分布式"的系统，也能扛起关键业务。这场"小型机 vs 大型机"的路线之争，深刻塑造了 1980 年代的企业计算格局。

**深度解读四：VAX 之后——MicroVAX 与"VAX 遗产"。** VAX 的故事也没有停在机柜里。1985 年，DEC 推出 MicroVAX II——把 VAX 架构装进了更小、更便宜的系统，甚至做成了芯片级的实现 [S37]。VAX 的指令集、VMS 的可靠性哲学、虚拟内存的分页思想，都作为遗产沉淀进了后来的计算世界。即便 DEC 本身已在 1998 年被收购、成为历史，OpenVMS 与 VAX 模拟器社区至今仍在活跃，延续着这台机器的生命。

**关键参数（面向玩家）：** 32 位字 · 32 位虚拟寻址（4 GB）· 16 个 32 位寄存器 · 分页内存管理 · ≈1 VAX MIPS · 1977/78 [S37][S38]。

**参考来源：** [S37][S38][S39]。

## (f) 原理讲解大纲（C2/C3/C4）

- **C2（框图层）**：标注"CPU / MMU / 主存 / I/O"四大功能区；高亮"虚拟地址 → 物理地址"的转换路径。
- **C3（信号流层）**：标注两类信号——① 虚拟地址（CPU 发出）→ ② 物理地址（MMU 转换后）；建议做"一次地址转换"动画：虚拟地址 → 查页表/TLB → 命中/缺页 → 物理访问。
- **C4（原理动画）**（分镜轮廓见下）：

**分镜 1《40 亿个地址》**：从 PDP-11 的 64 KB 地址空间（16 位）画面，扩展到 VAX 的 4 GB（32 位）画面，字幕点出"虚拟地址扩展"的字面含义。

**分镜 2《缺页》**：一条虚拟地址流经 MMU，页表查询"未命中"，触发缺页中断，操作系统从磁盘把页调入内存，再重试成功——展示"虚拟内存"的完整闭环。

**分镜 3《保护环》**：用四圈同心环动画展示核心态到用户态的权限分级，点题"高可靠多用户系统靠什么守住边界"。

**分镜 4《VAX MIPS》**：把"1 VAX MIPS"的度量概念视觉化——一台 /780 作为基准刻度，其他机器按比例标注在其旁。

## (g) 模拟器/演示可行性

**已有开源/可用模拟器现状：**

1. **SIMH "Classic"（Bob Supnik 维护的 3.x 流）**：SIMH 覆盖 VAX 家族，含 **VAX 11/780、11/750、11/730、MicroVAX** 等模拟器，可运行 VMS 与 BSD Unix 4.3 等历史系统 [S40][S43]。**许可：MIT-style（modified MIT）开源许可** [S40]。
2. **Open SIMH（V4 流）**：包含 VAX 模拟器的治理化后续项目，仓库 `https://github.com/open-simh/simh` [S41]。**许可：MIT-style / BSD** [S41][S42]。
3. **VMS 软件授权（Hobbyist / Community License）**：VMS 的业余爱好者/社区许可（Hobbyist Program，后为 Community License）允许非商业使用，但**具体条款与获取方式「需核实」**，展陈须规避商业授权风险。

**结论：能跑（功能级，规模较大）。**

- **能跑**：用 SIMH 的 VAX 模拟器，可真实运行 VMS 或 BSD Unix，体验 32 位虚拟内存多用户环境 [S40]。
- **不能跑/不建议**：宣称"逐拍仿真 VAX 微架构"——SIMH 是功能级模拟；VMS 授权（Hobbyist/Community License）边界需确认；且 VAX 系统规模大，可玩上手门槛高于 PDP-11。
- **推荐方案**：以"静态高精度 3D（外观级，机柜开合 + 半透明板卡示意）+ 虚拟寻址原理动画 + SIMH 跑 VMS/BSD 作可玩出口"三件套承载；"看缺页动画 + 敲一条 VMS 命令"是务实的体验组合。

**方案 A/B 与工作量粗估：**
