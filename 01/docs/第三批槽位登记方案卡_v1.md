## ② manifest 字段模板（以 simh-hp2100 manifest 为参照，resolve_entry 契约）

```json
{
  "slot_id": "hercules-s370",
  "device_class": "mainframe",            // [需核实：四台 device_class 枚举值]
  "backend_type": "hercules",
  "module": null,                          // 预留（无后端模块）
  "description": "Hercules S/370（二进制由用户自备，见 licenses 记录）",
  "license": "QPL（需核实）",
  "binary_env": "HERCULES_S370_BIN",
  "binary_hint": "third_party/hercules/s370",   // [需核实：编译产物路径]
  "media_classes": ["disk"],               // [需核实：按 191-A 枚举 disk/firmware/tape 等]
  "keymap": null
}
```

- 字段契约出处：slot_loader.py resolve_entry——module 显式声明（含 null=预留）优先于 BACKEND_TYPE_MODULE；media_class 枚举 MEDIA_CLASSES（none 为合法值）；binary_hint 可相对槽位目录或指向 third_party（206-A 口径）。

## ③ release_check R2 第三批判定方案（先 dry-run，二进制就位后 live）

1. 预留态（module=null）：run_status=missing，按第二批预留口径**放行不 FAIL**（参照 196-B 判定）；
2. 登记转正（module 就位 + binary_hint 已配但二进制缺失）：run_status=dry-run，合法；
3. 二进制就位（binary_path 解析命中）：run_status=live，真跑判定成立；
4. 转正后若纳入 REQUIRED_SLOTS/阈值上调（66 号口径 ≥5），由当时任务更新判定集合，本卡不预改。
