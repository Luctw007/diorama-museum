> 任务：TASK-197-B（02 线）。定位：v0.7 C-3（`sign_ref` 引用键统一）由 192-B 分派「02 主 / 03·04 协」，
> 本方案由 02 线**定义权威 id 格式 + 三线存量键映射表 + 回填规则**，供 03（annotations）/ 04（图鉴短卡）

## 一、权威 id 格式（唯一口径）

**裁决：`sign_ref` 的权威 id = 设备目录 id（`C-xxx` 等 `大类码-中分类码-6位序号` 格式），全库唯一、
由 `id_registry allocate` 分配。**

- **设备级引用**：`sign_ref` 写**目录 id**，如 `"C-MF-000050"`（UNIVAC I）——指向该设备的标牌/百科/
  图鉴短卡。
- **子部件精确引用**（可选，需精确到某条标注时）：用**两级引用** `目录id#标注id`，如
  `"C-MF-000050#whole_role"`——前半是目录 id（设备级权威），后半是包内标注 id（`annotations.json`
  的 `id` 字段）。
- **禁止**：`sign_ref` 直接写包内局部标注 id（如 `"whole_role"`），因标注 id 在多包间重复（nokia-3310
  与 pdp8 都有 `whole_role`），不具备全库唯一性，不能作跨线引用键。

> 理由：① 目录 id 是全库唯一权威（`id_registry` 分配、`catalog_check` CC-02 查重）；② 03 线图鉴短卡
> 已用目录 id 作主键（既有惯例，零迁移）；③ tour 台本引用的是"某台设备的标牌"，本质是设备级引用。

## 二、三线存量键映射表

| 线 | 存量键现状 | → 权威 id | 对齐状态 |
|---|---|---|---|
| 03 线图鉴短卡 | 主键 = 目录 id（`C-MF-000050` 等，见 `图鉴短卡文本_第二批首批_v1.md`） | 目录 id | **已对齐**（主键即目录 id，无需回填） |
| 03 线 annotations | `id` 字段 = 包内标注 id（`whole_role`/`sw_data_00_role` 等，多包重复）+ `target` = 装配体 id | `目录id#标注id`（两级） | **待回填**（tour 引用时组合，annotations 本身不改） |
| 04 线图鉴 UI | 消费图鉴短卡，用目录 id | 目录 id | **已对齐**（消费侧沿用目录 id） |
| v0.7 tour 台本 `sign_ref` | 草案"标牌引用（关联标注/百科条目）"，未定义权威 id | 目录 id（或 `目录id#标注id`） | **本方案定义** |

> 未对齐项（03 annotations 的包内标注 id）如实标「待回填」：本方案**不改** annotations 存量（标注 id
> 是包内局部命名，改它会影响引擎加载），改为 tour 台本引用时用两级格式 `目录id#标注id` 组合。

## 三、回填规则（03/04 线后续执行）

1. **03 线**：图鉴短卡无需回填（已用目录 id）；tour 台本引用子部件标注时，用 `目录id#标注id` 两级
   格式（目录 id 由目录条目已知，标注 id 由 `annotations.json` 的 `id` 字段取），**不改 annotations
   存量**。
2. **04 线**：图鉴 UI 消费图鉴短卡，沿用目录 id，无需回填。
3. **02 线**：v0.7 章 C 的 `sign_ref` 字段说明更新为"指向设备目录 id（设备级），子部件精确引用用
   `目录id#标注id`"（v0.7 终稿同步时写回）。
4. **校验口径**：`catalog_ref_check` 无新违规（tour 台本 `sign_ref` 的目录 id 部分应能解析到目录条目）；
   标注 id 部分不参与 catalog_ref 校验（属包内引用，由 validate 的 R-xxx 管）。

## 四、与任务书的漂移（如实）

- 04 线图鉴短卡实际是"消费 03 线图鉴短卡文本"（design 规格文档），非独立短卡存量；03 线
  `图鉴短卡文本_第二批首批_v1.md` 已用目录 id 作主键，故映射表里 04 线标"已对齐"（无需回填）。
- 03 annotations 的 `id` 是包内局部键（`whole_role` 等多包重复），本方案裁决"不改存量、tour 引用时
  组合两级格式"，避免动 03 线 34 台存量包的 annotations。
