# 年代（era）字段回填规范 v1

> 03 线 TASK-135 交付。为通讯与移动大类目录的 `era` 字段制定回填规范，使年代切片可被图鉴时间轴与展厅可信引用。
> 本规范同样适用于计算机大类目录的 era 维护。

## 一、era 取值来源优先级

按以下优先级取值，**同类来源取「早」**（较早问世的权威来源优先）：

1. **官方手册 / 官方资料**（产品官方规格书、官方发售公告）
2. **定案表**（`镇馆之宝30台定案表_v1.md` 第六节年代切片覆盖）
3. **研究卡**（`docs/research/hall-phone/*`、`hall-generic/*`、`hall-workstation/*`）
4. **百科**（Wikipedia / Computer History Museum 等）

> 当高级来源缺失时，向下逐级取值；多个同级来源年代不一致时，取「早」并标「需核实」。

## 二、「需核实」标记语义

- `verify: true` 表示该条 `era` **未经可靠来源确认**，为估计值或存疑值，仅供时间轴粗排序，**不可作为展签的确定年代**。
- `verify: false` 表示 `era` 有可靠来源支撑，可直接引用。

## 三、estimated 与 null 的使用边界

- **era 必须是整数年份**（满足 CC-05：`1880 ≤ era ≤ 当年+1`）。
- **不得用 null**：CC-05 会把 null 判为「非合法年份」而 FAIL。
- **不得用 estimated 占位**：拿不准的年份，填一个**估计年份**（同类近似机型或系列首作年代），并同时置 `verify: true` 标「需核实」。
- 一句话：**「估计值 + verify=true」取代「null/estimated」**，既满足 schema 约束，又如实标注不确定性。

## 四、回填记录格式

每次回填在条目 `sources` 追加来源编号（如 `S63B`），并在 v3 头部「回填统计」登记：

```
- 新增/修正 era 条目数
- 所引来源编号清单
- 需核实（verify=true）条目数
```

## 五、本轮（通讯 v2→v3）回填结果

- 全量核对 `通讯与移动大类_目录_v2.jsonl` 共 **306 条**：era 全部为合法年份（1880–2027），**0 条缺漏、0 条越界**。
- 存疑条目 **94 条**已标 `verify: true`（保持「需核实」），`verify: false` 212 条。
- 本轮**无新增/修正 era**（v2 已在 63-B 轮完成 era 填充），仅作规范性核对并升级版本号到 v3，头部登记来源与统计。
