## 一、实测目标（场景 / 步骤 / 观察项）

> 语义界定：`co_active_max` = **同一画面内同时处于「激活态」（拆解中/运行中）的设备数上限**，区别于
> `max_running`（同厅运行配额 ≤4，B-03 已 PASS，exhibit_layout_spec §3）。前者是同屏渲染/交互并发上限，
> 后者是同厅进程/实例配额上限，两者不混。

1. **实测场景**：大厅/单厅视图内，多台设备**同时进入激活态**（拆解爆裂或真跑运行），逐级增加同屏激活台数。
2. **前置条件**：01 线三台真跑 RC 已出（MAME apple2 / SIMH pdp8 / Stella Atari 2600，按 241-B 口径），
   且槽位系统可多后端并发（当前 slot 声明 0、真跑矩阵待槽位折叠后联调）。
3. **观察项**：逐级采集 **帧率 FPS / 帧时间 ms / 内存 MB / 是否掉帧或卡顿**（含拆解态与真跑态两种激活形态）。

## 二、判据（每步 PASS 判据 + 采集数据格式）

1. **梯度测试**：N = 1, 2, 3, 4, 5 逐级同屏激活，每级稳定运行 ≥ 30 秒后记录。
2. **PASS 判据**：该级 FPS ≥ 引擎目标帧率线（默认 30 FPS，以引擎实际目标为准）且无连续掉帧；取「不卡的
   最大 N」为权威值 `co_active_max`。
3. **默认 3 校验**：重点验证「N=3 不卡、N=4 是否开始掉帧」——若 N=3 达标则默认 3 成立；若 N=4 仍稳则权威值
   上修 4；若 N=3 已掉帧则下修 2。
4. **采集数据格式**（每级一行，可写入 F4 预算表附档）：

```
{N 台} | FPS_avg | FPS_min | frame_ms_p99 | mem_MB | 是否卡顿(y/n) | 激活形态(拆解/真跑混合比)
```
