## 一、总则与适用范围

### 1.1 目标

在正式录音 / 采购 / 程序化生成开产之前，把音频资产的**格式、命名、响度、来源**四件事写成可执行
规则，避免各内容线各自为政、响度不一、授权不清。音频是四可标准里"氛围与沉浸"的载体，本章直接
服务"可看/可玩"之外的听觉体验。

### 1.2 适用对象

- `content/<device-id>/sounds/` 下的全部音频文件（BGM、效果音、解说、环境 bed、设备运行声）；
- 程序化合成音频（`SYNTH.md` 配方登记的合成件）；
- 音频资产的 THIRD_PARTY 许可登记。

> 本草案同时是 04 线 20/21 号音频工程规格的上游规范化收编（对照表见附录 A），目标是让
> 08 线采购、04 线验收、01 线引擎在正式录音开产前拿到统一的格式/命名/响度/来源口径。

### 1.3 基本原则

1. **母带与交付分离**：自录母带 WAV（高规格）与交付版 OGG（降规格）分离，母带留档、交付入包；
2. **响度统一**：以 LUFS 为目标、dBFS 为峰值上限的双层规范，杜绝"每包一个音量"；
3. **命名即契约**：文件名承载类别/归属/序号，引擎与校验器按命名正则扫描，零成本；
4. **授权先行**：外部素材沿 10 号"待核"口径，只登记不越权，红线来源一律转自录/自产。

### 1.4 术语定义

| 术语 | 定义 |
|---|---|
| BGM | Background Music，厅/展区底乐 |
| SFX | Sound Effect，一次性事件音（交互/运行/过渡） |
| VO / 解说 | Voice Over，导览讲解音 |
| amb / 环境 bed | Ambience，持续氛围底噪层 |
| LUFS | Loudness Units Full Scale，响度目标（EBU R128） |
| dBFS | Decibels Full Scale，峰值/电平上限 |
| 母带 | 自录/委约的高规格 WAV 源文件 |
| 交付版 | 入包的 OGG Vorbis 文件 |
| SYNTH.md | 程序化合成音频的配方登记文件 |

### 1.5 音频与"四可"标准的关系

音频专章服务四可标准的听觉维度，与视觉（建模章）、交互（输入映射）正交：

| 四可 | 音频承载 | 对应类别 |
|---|---|---|
| 可看 | 展项氛围、底乐铺陈 | amb + BGM |
| 可拆 | 拆解卡合/拾取/落座手感 | sfx（grab/snap/lid） |
| 可懂 | 导览解说、原理讲解 | vo |
| 可玩 | 运行声、键帽/开关反馈、崩溃/恢复提示 | sfx + run |

> 设计目标：让玩家"闭眼也能感知设备在运行、拆解有手感、讲解可听懂"，故响度分层（vo > sfx >
> BGM > amb）与空间定位（点声源 vs 头部锁定）是本章两大支柱。

### 1.6 与各线的分工边界

| 线 | 职责 | 与本章关系 |

## 二、资产格式与规格

### 2.1 WAV / OGG 选用矩阵

| 场景 | 格式 | 采样率 | 位深/码率 | 说明 |
|---|---|---|---|---|
| 自录母带 | WAV | 96 kHz（母带）/ 48 kHz（交付前降采样） | 24 bit | 信噪比 ≥60 dB，单条 ≥5 take |
| 委约母带 | WAV | 48 kHz | 24 bit | 委约合同随包留档 |
| 交付·效果音 | OGG Vorbis | 48 kHz | q5（约 160 kbps） | 立体声（点声源单声道） |
| 交付·解说 | OGG Vorbis | 48 kHz | q6（约 192 kbps） | 单声道 |
| 交付·BGM | OGG Vorbis | 48 kHz | q6 | 立体声 |
| 交付·环境 bed | OGG Vorbis | 48 kHz | q5 | 立体声 |
| 程序化合成 | WAV（配方渲染）→ OGG 交付 | 48 kHz | q5 | SYNTH.md 记配方 |

> 统一采样率 **48 kHz**（04 线 20 号同）；96 kHz 仅作自录母带（10 号 §2 口径），交付前降采样。
> 不引入第三方运行时依赖（解码交给 Godot/网关，内容包只存文件）。分轨交付（BGM/vo/sfx/amb 各
> 独立文件），禁止把多类别混录成单轨，否则引擎无法按母线路由与闪避。

### 2.2 格式选用决策

**为何 WAV + OGG，为何 48 kHz**：

- **母带 WAV**：无损、可反复剪辑降噪、自录/委约的存档源；24 bit 保留动态余量（降噪/变调不损失）。
- **交付 OGG Vorbis**：开源无专利、Godot 原生解码、体积适中（q5≈160 kbps 效果音、q6≈192 kbps
  解说/BGM）；**不选 MP3**（专利/许可历史、瞬态损伤）、**不选 FLAC 交付**（体积大、引擎加载慢）。
- **48 kHz**：游戏/引擎标准采样率（Godot 默认混音 48000 Hz），与网关 `audio_chunk` 的 s16le 直通
  经引擎重采样对齐；**不选 44.1 kHz**（CD 标准，与引擎混音需重采样，无收益）。96 kHz 仅自录母带
  （高倍采样留降噪空间），交付前降采样 48 kHz。

### 2.3 位深与响度目标

- **WAV 位深**：24 bit（母带）；交付 OGG 为有损，无位深概念，按码率档（q5/q6）。
- **响度目标（LUFS，EBU R128 积分响度）**——本章为**双层规范**：LUFS 目标 + dBFS 峰值上限：

| 类别 | LUFS 目标 | 峰值上限（dBFS） | 说明 |
|---|---|---|---|
| 解说 vo | −16 ±1 LU | ≤ −3 | 前景，最响 |
| 效果音 sfx | −18 ±1 LU | ≤ −12（单条）/ ≤ −6（并发整组） | 交互反馈 |
| BGM | −24 ±1 LU | ≤ −12 | 底乐 |
| 环境 bed amb | −30 ±2 LU | ≤ −24 | 氛围底噪，最弱 |

> 说明：本章把 04 线 20 号混用的 dBFS 峰值 / RMS / LUFS 统一为「LUFS 目标 + dBFS 峰值上限」双层，
> 即"文件做到多响看 LUFS、绝不超多少看 dBFS"。04 线原数值（narr LUFS −16、sfx 峰值 −12、bed −32
> dBFS 峰）归并进上表。

### 2.2b 响度原理（LUFS 与 dBFS 的区别）

- **LUFS（积分响度）**：衡量"人耳感知的响度"，是**目标**——决定文件"听起来多响"。
  用 EBU R128 积分（K 加权），适合统一"解说多响、效果多响、底乐多响"。
- **dBFS（峰值电平）**：衡量"瞬时最高采样点距削波的距离"，是**上限**——决定文件"绝不爆音"。
  峰值超 0 dBFS 即削波失真，故必须留 headroom（如 vo ≤−3、sfx ≤−12）。
- **RMS（均方根）**：介于两者之间的"平均电平"，04 线用于 UI 类（−20 dBFS RMS）；本章用 LUFS
  替代 RMS 作"平均响度"的权威口径，RMS 仅作参考。

> 一句话：**LUFS 管"多响"，dBFS 管"别爆"**。双层规范让母带师/生成器各司其职——先调到目标
> LUFS，再检查不超峰值上限。

### 2.8 事件类别完整分类（供命名与采购参考）

沿用 04 线 20 号 §1 的音源分类，本章固化为五大类（每类给出命名前缀与代表事件）：

| 类别 | 前缀 | 代表事件 | 授权倾向 |
|---|---|---|---|
| UI 通用 | sfx_ui_* | confirm/cancel/deny/error/boundary/slider_tick/slider_snap/hint_toast/badge | 程序化合成 |
| 设备交互 | sfx_<device>_* | lid_open/close、snap_in/out、pick/approach/drop_settle/grab_bounce/restore_* | 首选自录 |
| 运行类 | sfx_<device>_* | power_on/off、key_single/repeat、release_reset、load_media | 首选自录 |
| 运行类（合成） | sfx_ui_* / sfx_<device>_* | snapshot/crash/reconnect/auto_recover_ok/degrade_advice | 程序化合成 |
| 设备本体运行声 | run_<device>_* | transformer/fan/relay/floppy_seek/floppy_motor/crt_whine/speaker_beep | 合成/直通 |
| 环境 bed | amb_* | hall/cabinet/workbench/crt_room | 待核或自录 |
| 场景过渡 | sfx_ui_* | enter_hall/exit_hall/pedia_card/save_load | 程序化合成 |
| BGM | bgm_<厅>_* | dawn/crt/mainframe/game | 原创委约或 CC |
| 解说 | vo_<厅>_<站>_* | 各站句编号 | 自录或 TTS |

> 完整事件表（56 条）在 04 线 20 号 §2；本章只定义"类别 → 前缀 → 授权倾向"的规范映射，
> 不复制事件表全文。

### 2.3 时长上限

| 类别 | 时长上限 | 例外 |
|---|---|---|
| 效果音 sfx | ≤ 4 s | amb 循环 60–120 s 无缝 |
| BGM | 1'30–2'00 成曲 + 循环点 | 出口时间线段一次过 0'45 |
| 解说 vo | 按台本（语速 180 字/分 ±5%） | 每段 ≤60 字防憋气 |
| 环境 bed amb | 60–120 s 无缝循环 | — |

### 2.4 立体声 / 单声道规则

| 类别 | 声道 | 定位语义 |
|---|---|---|
| UI/面板音 | 单声道 | 头部锁定（不随头转） |
| 环境 bed | 立体声（成对） | 全向氛围 |
| 点声源（设备/拆装/运行） | 单声道 | 供 AudioStreamPlayer3D 定位 |
| 解说 vo | 单声道 | 头部锁定（轻微宽化 0.1） |
| BGM | 立体声 | 全向 |

> 规则：需要空间定位的一律单声道（定位交给引擎），氛围/底乐才立体声；UI 单声道头部锁定。

### 2.5 音频来源三渠道与采购原则

音频按来源分三渠道，各有登记与红线要求：

| 渠道 | 说明 | 登记要求 | 红线 |
|---|---|---|---|
| 自录 | 真机/现场实录（首选，避免二手权属不清） | THIRD_PARTY 标「原创」 | 录制规格见 §2.6 |
| 采购 | 外部素材站（Freesound/99Sounds 等） | THIRD_PARTY 三件套（分档+URL+日期）+ CC-BY 署名 | 仅 CC0/权利明确；红线见 §3.3 |
| 程序化合成 | 合成器/脚本生成（UI/过渡/运行声） | `SYNTH.md` 记配方（免 THIRD_PARTY） | 音色稳定、零外部依赖 |

> 采购原则（10 号 §4.5）：M1 只采购「运行必需 + 高感知」；体验增益类延后；与 MAME 音频直通
> 冲突的条目挂起。凡涉及真实设备声（开盖/键帽/开机嗡/软驱），一律**首选自录**。

### 2.6 自录录制规格（统一）

| 项 | 规格 |
|---|---|
| 母带 | 24 bit / 96 kHz WAV（降采样后 48 kHz 交付） |
| 信噪比 | ≥60 dB |
| 单条 take | ≥5 次，入组时选 take 后处理 |
| 环境 | 安静室内（底噪 <35 dB） |
| 话筒 | 电容麦（单品特写）/ 接触麦（键帽）/ 压电贴片 |
| 降噪 | 仅轻度（高通 80–100 Hz，勿过度降噪、勿斩瞬态） |

**自录要点表**（10 号 §2，节选）：

| 条目 | 设备/话筒 | 距离/指向 | 时长 | 提示 |
|---|---|---|---|---|
| 开盖/关盖 | 真机顶盖；接触电容麦 | 5–10 cm，指向卡扣铰链 | 单动作 ≥2 s | 保留塑料瞬态 |
| 卡合装/拆 | 插座插拔（塑料/金属） | 15 cm 心形 | ≥1 s | 去底噪 ≤6 dB |
| 开机/关机嗡 | 真机开关；近场电容麦 | 10 cm 面板侧 | 含通电嗡起 ≥4 s | 嗡声保留 |
| 键帽单次/连打 | 真机键盘；接触麦贴键帽 | 2 cm | 5 击 + 连打 10 s | 高通 100 Hz |
| 复位键 | 真机 reset 键 | 5 cm | ≥3 击 | 保留金属 snap |
| 介质载入 | Disk II 插盘/退盘 | 20 cm 机前 | ≥3 次 | 保留门开关双响 |
| 风扇 | 真机风扇 | 30 cm 45° | 稳态 30 s | 去机械共振峰 |
| 软驱寻道/马达 | Disk II 读写中 | 20 cm 隔音箱 | 寻道 ≥30 s | 分离电机底噪与步进 |

> 归库命名：`raw/R-01/<条目>_take<k>.wav`；选定后转交付版；原盘留档 30 天。

### 2.9 音频技术约束与常见坑

针对本项目的复古设备/博物馆场景，录音与合成的常见坑提前规避：

| 易错点 | 表现 | 规避 |
|---|---|---|
| 爆音（削波） | 峰值超 0 dBFS，瞬态失真 | 留 headroom（§2.3 峰值上限），终检跑 T-199 |
| 响度不一 | 各包音量忽大忽小 | 统一 LUFS 目标（§4.10 决策树） |
| 降噪过度 | 瞬态被斩、发闷 | 仅轻度降噪（高通 80–100 Hz，≤6 dB 衰减） |
| 采样率混用 | 44.1/48 kHz 混入 | 统一 48 kHz（§2.1 矩阵） |
| 母带当交付 | WAV 直接入包 | 母带留档，交付转 OGG |
| 命名歧义 | `sfx_lid_open` 多设备同名 | 补设备前缀（§3.1/3.4） |
| 授权越权 | YouTube 翻录/游戏原声 | 红线来源转自录（§3.3） |
| 循环点接缝咔嗒 | BGM 循环跳变 | 循环点选无旋律头段，接缝响度差 ≤1 dB |
| 点声源用立体声 | 定位失效 | 点声源单声道，定位交引擎（§2.4） |
| 合成件无配方 | 复现难 | SYNTH.md 记配方（§3.5） |

### 2.10 音频生产流程（六步，供执行）

## 三、命名规则

### 3.1 前缀与结构

| 类别 | 命名结构 | 示例 | 说明 |
|---|---|---|---|
| BGM | `bgm_<厅>_<序号>` | `bgm_dawn_01`、`bgm_crt_01` | 厅= dawn/crt/mainframe/game… |
| 效果音 | `sfx_<设备|ui>_<动作>` | `sfx_apple_ii_power_on`、`sfx_ui_confirm` | 设备= 具体 device-id；ui= 通用 UI |
| 解说 | `vo_<厅>_<站>_<句>` | `vo_dawn_s2_01`、`vo_dawn_s2_02` | 站= 展位号；句= 句编号 |
| 环境 bed | `amb_<厅|场景>` | `amb_hall`、`amb_cabinet`、`amb_crt_room` | — |
| 设备运行声 | `run_<设备>_<部件>` | `run_apple_ii_fan`、`run_apple_ii_relay` | 循环属性入 amb 语义（见 3.2） |

> 命名正则（校验 A-01）：`^(bgm|sfx|vo|amb|run)_[a-z0-9_]+$`，snake_case。

### 3.2 与 04 线 20 号既有 id 的对照（裁决）

## 四、响度分级与混音优先级

### 4.1 响度分级（三层 + 环境）

| 层级 | 类别 | LUFS | 峰值 dBFS |
|---|---|---|---|
| 前景 | 解说 vo | −16 | ≤ −3 |
| 交互 | 效果音 sfx | −18 | ≤ −12 / −6 |
| 底乐 | BGM | −24 | ≤ −12 |
| 氛围 | 环境 bed amb | −30 | ≤ −24 |

### 4.2 混音优先级表（并发 ≤4，挤最低）

| 优先级（高→低） | 类别 | 说明 |
|---|---|---|
| 1 | 错误/警告（sfx_error/crash/deny） | 必须可闻，挤掉一切 |
| 2 | 确认/提示（sfx_confirm/badge） | 用户反馈 |
| 3 | 拆装/交互（grab/snap/lid） | 手感音 |
| 4 | 环境（amb/bgm） | 可被挤，淡出即可 |

> 同屏并发 ≤4 条（T-187）；超量按优先级挤最低。BGM 闪避：任何 vo 播放时 BGM 自动 −8 dB（0.3 s
> ramp），bed 层再 −6 dB（04 线 20 号 §1.1）。

### 4.3 与 04 线 20 号的响度对照

04 线 20 号给的是 dBFS/RMS/LUFS 混合值（narr LUFS −16、sfx 峰值 −12、UI RMS −20、bed −32 dBFS
峰）。本章统一为「LUFS 目标 + dBFS 峰值」双层，把 04 线数值归并：

| 04 线数值 | 本章归并 | 裁决 |
|---|---|---|
| narr LUFS −16 | vo LUFS −16 | 采纳 |
| sfx 峰值 −12 / UI RMS −20 | sfx LUFS −18 + 峰值 −12 | 调整（RMS 并入 LUFS） |
| BGM 淡入 −18 dB（增益） | BGM LUFS −24 | 调整（增益≠响度目标，拆两层） |
| bed −32 dBFS 峰 | amb LUFS −30 + 峰值 −24 | 调整 |

### 4.4 母线结构与混音架构

沿用 04 线 20 号 §4.1 的母线划分（Godot AudioStreamPlayer3D 注册表），本章固化为规范：

| 母线 | 子层 | 主要音源 | 处理链 |
|---|---|---|---|

| UI 母线 | — | 头部锁定音 | 单声道双耳直送（不定位） |

### 4.5 距离衰减参数表

沿用 04 线 20 号 §4.2，本章固化为规范（Godot Attenuation 参数）：

| 声源类别 | 衰减模型 | unit_size | 参考距离 | 最大距离 | 衰减 | HRTF | 混响发送 |

### 4.6 配音分镜版式（解说稿符号）

沿用 04 线 20 号 §3.1，供配音/TTS 校对：

- `／` = 短停 0.3 s；`／／` = 长停 0.8 s（段落）；`【】` = 重读词；`（吸气）` = 换气点；每段 ≤60 字防憋气。
- 静音标准：句间噪声门 −60 dBFS，句首 50 ms 预滚、句尾 200 ms 余韵。
- 联动：字幕与 vo 起止 ≤100 ms 容差；vo 被玩家打断时字幕同断。

### 4.7 闪避与互斥组

- **闪避**：任何 vo 轨播放时 BGM 自动 −8 dB（0.3 s ramp）；bed 层再 −6 dB（04 线 20 号 §1.1）。
- **互斥组**：同一互斥组内交叉 40 ms（组定义沿用 04 号 §1.6）；组 run 崩溃急停全组（保留错误音 + bed）。
- **并发上限**：同屏并发 ≤4 条；超量按优先级挤最低（错误 > 确认 > 拆装 > 环境）。

### 4.8 网关音频直通互斥（audio_chunk）

- 网关广播 `audio_chunk{device_id, seq, sample_rate, channels, format:"s16le", data_b64}`（PROTOCOL §消息表）；
  客户端按 `(device_id, seq)` 去重入队，送 EmuAudio 母线播放（sample_rate=8000 由引擎重采样 48 kHz）。
- 直通可用时，本地 `run_speaker_beep` 合成件静音（以直通为准）；网关断连 500 ms 内 EmuAudio 淡出防爆音。

### 4.9 响度分级依据（为何 −16 / −18 / −24 / −30）

响度分层不是拍脑袋，依据如下：

1. **解说 −16 LUFS**：播客/有声书常用目标（Apple Podcasts 推荐 −16 LUFS），人声清晰且不过响；
   博物馆"导览腔"需在 50% 音量点可听清（T-184），−16 LUFS 经实听校准。
2. **效果音 −18 LUFS**：低于解说 2 LU，作为交互反馈不抢解说；高于 BGM 6 LU，保证按键/开盖
   "有手感"（可感知但不高出解说）。
3. **BGM −24 LUFS**：流媒体底乐常用目标（−23 LUFS 为 EBU R128 广播基准附近），纯铺陈不干扰；
   播放时再按 §4.7 闪避（vo 播时 −8 dB）进一步压低。
4. **环境 bed −30 LUFS**：近底噪级，只提供"空间存在感"，不参与信息传递；低于 BGM 6 LU 形成
   "环境 < 底乐 < 效果 < 解说"的清晰层级。

> 峰值上限对应留 headroom：解说 −3 dBFS（人声瞬态需宽容）、效果 −12 dBFS（短促音留余量防叠加
> 爆音，整组并发 ≤−6）、BGM −12、bed −24。这些数值为起始值，实听校准后升版（04 线 20 号同口径）。

### 4.10 音量分级决策树（供母带师/生成器执行）

```
确定类别（vo / sfx / bgm / amb）
   ├─ vo  → 目标 −16 LUFS，峰值 ≤−3 dBFS，单声道
   ├─ sfx → 目标 −18 LUFS，峰值 ≤−12 dBFS（并发 ≤−6），单声道（点源）/头部锁定（UI）
   ├─ bgm → 目标 −24 LUFS，峰值 ≤−12 dBFS，立体声
   └─ amb → 目标 −30 LUFS，峰值 ≤−24 dBFS，立体声
```

### 4.11 响度目标（LUFS）与播放增益（dB）的区别

本节澄清两个易混概念，避免母带师/引擎误用：

- **LUFS 目标**（§2.3/§4.1）：文件"做到多响"的**母带规格**，在转码/母带阶段定死，写进文件本身。
- **播放增益（dB）**（§4.4 母线/§4.7 闪避）：引擎**运行时**对文件的音量缩放（如 BGM 淡入 −18 dB、
  vo 播时 BGM −8 dB），是混音层的动态控制，不改文件。

> 例：BGM 文件做到 −24 LUFS（母带目标），播放时引擎再给 −18 dB 淡入增益（运行时），二者叠加是
> 混音语义，不是"文件 −24 和 −18 冲突"。04 线 20 号的"BGM 淡入 −18 dB"是增益，本草案的
> "BGM −24 LUFS"是响度目标，二者不同层（对照表 #7 已裁决）。

- 04 线 21 号 T-182~199 = **运行级动态验收**（触发/淡入/定位/遮挡/音量/授权台账），需引擎埋点 +
  频谱工具 + 人工实听；
- 二者互补：A-04（来源三件套）与 T-198（授权登记完整性）重叠，未来可合并为一处权威校验。

### 6.8 响度测量方法（供未来 A-02 实现参考）

- **LUFS 测量**：EBU R128 标准（K 加权 + 通道权重 + 400 ms 门限 + 积分），常用工具：ffmpeg
  `loudnorm`、BS.1770 计量器、iZotope RX / Audacity 内置响度插件。
- **峰值 dBFS 测量**：采样点绝对最大值，工具任意音频编辑器（Audacity 峰值表）。
- **实现提示**：纯 stdlib 无法精确测 LUFS（需重采样滤波），故 A-02 落地时建议：浅校验（采样率/
  声道/时长，读文件头）走纯 stdlib，LUFS/峰值走 ffmpeg 子进程或 CI 侧计量（红线仅限"运行时依赖"，
  CI 工具可引外部计量）。

## 七、音频与引擎 / runtime 的加载衔接

本章只规定"资产是什么规格"，不越权规定引擎实现；但须明确资产如何被引擎消费，避免资产与引擎
脱节：

### 7.1 sounds/ 的加载语义

- `sounds/` 下文件按**文件名前缀**路由到对应母线（§4.4）：`bgm_*`→厅母线-bgm、`vo_*`→厅母线-narr、
  `amb_*`→厅母线-bed、`sfx_*`→设备/UI 母线、`run_*`→设备母线-run。
- 点声源类（`sfx_<device>_*`、`run_*`）由引擎 `AudioStreamPlayer3D` 按 §4.5 距离衰减表定位；
  UI 类（`sfx_ui_*`、`vo_*`）头部锁定（单声道双耳直送）。
- 命名前缀即路由契约：引擎/校验器按前缀扫描，改名即改路由，故 §3 命名是硬约束。

### 7.2 与网关 audio_chunk 直通的衔接

- 设备本体运行声优先走**网关直通**（`audio_chunk`，模拟器真实音频），本地合成件（`run_speaker_beep`）
  在直通可用时静音（§4.8）。
- 直通的 `sample_rate`（如 8000）由引擎重采样至 48 kHz 混音；重采样质量档待实机核对（开放问题）。

### 7.3 与 meta.json.runtime 的衔接

- `runtime.output_sinks` 已声明 `speaker`（音频 sink，v0.3 §7）；`sounds/` 是**内容包资产**，
  `output_sinks[].format`（如 pcm16）是**运行时格式声明**，二者语义不同：前者是文件、后者是
  网关直通格式。
- 有 `speaker` sink 的包，其设备运行声（`run_*`/直通）才被引擎启用；无 speaker sink 的静态包
  只有 `amb_*`/`bgm_*`/`sfx_*`。

## 附录 C：开放问题（留给 v0.4 正式版裁决）

1. **LUFS −16 解说是否过响**：与 bed −30 的差（约 14 LU）需实听校准（04 线 20 号开放问题 ①）。
   *背景*：−16 LUFS 是播客标准、人声清晰，但博物馆"导览腔"配 −30 环境底噪时，14 LU 的落差
   可能偏大，需实听确认"50% 音量可懂"（T-184）与"不刺耳"的平衡点。
2. **TTS 与真人配音取舍**：预算门（04 线 20 号开放问题 ②）；TTS 需逐站人工校对稿。
   *背景*：真人配音质感好但成本高；TTS 需逐站过重音/停顿校对，禁止直接读 markdown。
3. **响度测量工具**：A-02/A-03 需读 WAV/OGG 头，未来实现时选定纯 stdlib 或引入轻量解析（红线段）。
   *背景*：OGG Vorbis 头解析与 LUFS 测量非纯 stdlib 可轻松完成，实现 audio_check 时须权衡
   "纯 stdlib 只做浅校验"vs"引轻量库做真 LUFS 测量"（红线不引第三方运行时依赖，但 CI 工具可）。
4. **遮挡 −6 dB/层**：射线判定实现载体（物理层 or 手动遮挡盒）待定（04 线 20 号开放问题 ④）。
   *背景*：遮挡衰减依赖射线判定，需 01 线定"物理碰撞层"还是"手动遮挡盒"实现。
5. **`run_*` 系列 bed 化**：`run_transformer` 等循环属性是否并入 `amb_` 语义，待与 04/05 线对齐。
   *背景*：10 号已把 `run_transformer` 等 bed 化（→ `amb_*`），但 04 线 20 号仍用 `run_*` 前缀；
   两处命名语义需统一裁决。

## 附录 E：术语与符号速查

| 符号/术语 | 含义 |
|---|---|
| LUFS | 积分响度单位（EBU R128），"多响"的目标 |
| dBFS | 满刻度分贝，"不超多少"的峰值上限 |
| q5/q6 | OGG Vorbis 质量档（约 160/192 kbps） |
| ORTF | 立体声拾音制式（近场环境录制用） |
| SYNTH.md | 程序化合成配方登记文件 |
| 三件套 | 许可分档 + 来源 URL + 获取日期 |
| Headroom | 峰值到 0 dBFS 之间的安全余量（防爆音） |
| 闪避 Ducking | 某轨播放时自动压低他轨（vo 播 BGM −8 dB） |
| 母带 Mastering | 最终响度/动态统一处理，产出交付规格 |
| 头部锁定 | 音源不随玩家转头改变方位（UI/解说） |
| 点声源 | 3D 空间中有确定位置的声音，供引擎定位 |
