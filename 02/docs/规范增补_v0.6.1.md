## 二、runtime.slot.media_class 与目录建议的衔接条款

1. **目录条目 `media_class` 字段**（新增可选字段）：62-B 推定产出的是"建议值"，由 03/05 线人工
   复核后回填进目录条目的 `media_class` 字段（低置信度条目优先复核）。
2. **内容包 `runtime.slot.media_class`**：内容包的槽位提示字段（v0.5 §6.3）声明"本设备用什么介质
   类目"，应与目录条目 `media_class` 一致。
3. **衔接规则**：目录条目 `media_class`（目录侧）与 `runtime.slot.media_class`（内容包侧）二者同义，
   前者是"全库建议"、后者是"已产包的确认值"。冲突时以内容包 `runtime.slot` 为准（已确认 > 建议）。
4. **推定边界**：推定只做"建议"，不写回他线文件；`card`/`app_package` 两类规则已就位，待目录
   出现对应设备后验证。

## 三、目录校验 CC-08（状态 ↔ 设备包存在性）

| 规则 | 判定 | 级别 |
|---|---|---|
| CC-08 | `status ∈ {package, wip, done}` 的条目必须带非空 `device_id`，且该 `device_id` 存在于 03/05/02 线 `repo/content` 目录（rigid 判定，不存在报 FAIL） | FAIL |

- 与 CC-04 的关系：CC-04 校验"状态枚举合法 + done/package 非空 device_id"；CC-08 在 CC-04 基础上
  扩展至 `wip`，并增加"device_id 存在性"的 rigid 判定。
- 语义：目录侧声明"这台设备已产包/生产中/待验收"，就必须能指认一个真实存在的内容包；指认不存在的
  包 = 悬空引用，门禁 FAIL。

## 四、CC-08 实跑（1562 条最新版目录）


## 附记：目录批次规则（v 全量文件替代制）

目录文件版本采用**全量文件替代制**：新版本 `v2` 必须包含 `v1` 的全部条目（增删以"新版本 = 上一版本
的全量超集 + 本轮增改"为准），产出版本后应**删除旧版本**，避免 v1/v2 并存导致重复计数与跨文件查重误报。
该规则由 CC-02（批内全文件联合查重 + 台账对账）与 CC-08（device_id 存在性）共同保障：一旦 v1 未删、
v2 复用 v1 的 id，CC-02 即报跨文件重复；一旦 v2 缺失 v1 的 done 条目，CC-08 即报 device_id 悬空。
