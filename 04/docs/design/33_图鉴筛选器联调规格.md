## 1. 筛选 token 系统

### 1.1 token 定义（五类）

| token 类 | 值域 | 一个筛选 = 多 token？ | 数据字段映射（catalog 行） |
|---|---|---|---|
| big | 大分类（6~7 项） | 单选（同类别互斥） | `path[0]` |
| mid | 中分类（≤40） | 多选（同类别叠加 OR，异类别 AND） | `path[1]` |
| sub | 子分类（≤400/层） | 多选 | `path[2]` |
| era | 年代档（§31 号 1.2 六档/双头滑杆） | 双端点各 1 | `year ∈ [start,end]` |
| status | 状态五徽章 | 多选 | `status` |

- token 呈现 = 筛选栏胶囊（token bar）：`[大分类:★] ×` 形态，每胶囊含类图标+值+移除钮；全部 token 删除则回全量（与 31 号 §1 组合规则一致：类内 OR、类间 AND、搜索词 AND）。

### 1.2 token 状态机（添加/移除/组合/清空，ASCII 全文）

```
        ┌─────────────┐ 分类树点选/下拉加项      ┌──────────────┐
        │  Empty(全量) │ ─────────────────────▶ │  TokenBar 有值 │
        └─────────────┘                        └──────┬────────┘
             ▲  移除最后一项                          │ 再添加（同类别替换/异类别并存）
             │        ┌──────────────────────────────┤
             │        ▼                              ▼
        ┌─────────────┐  [清空]                 ┌──────────────┐
        │  结果区刷新   │ ◀───────────────────── │  token 冲突判定│
        └─────────────┘                         └──────────────┘
                                                     │ 同类别旧值被新值替换（互斥类）
                                                     │ 异类别 AND 合并；搜索词恒 AND 头位
   规则：加 token 不关闭树/下拉（连续加）；每次变更 300ms 内只发 1 次查询（防抖合一，§2.1）；
        年代档 token 由双头滑杆更新而非树点选。
```

### 1.3「分类树点选即加 token」双操作表

| 操作 | 桌面 | VR |
|---|---|---|
| 点选树节点 | 单击节点 → 该级 token 直入 token bar（大分类单击+中分类单击=两 token） | 射线点选（热区 ≥0.04 m，12 号 §2.4） |
| 取消点选 | 再点同节点 → 移除该 token（toggle） | 同左 |
| 批量清空 | [清空筛选] 按钮二次确认 | 手背菜单链末项 [清空]（12 号 §3 第三路径） |
| token 胶囊移除 | 每胶囊自带 × 钮 | 射线点 ×（≥0.04 m） |
| 年代档 | 拖双头滑杆 | 握持键拖滑杆（Inspect-Grab，29 号 §4 滑块语义） |

## 2. 搜索与排序

### 2.1 搜索框（联调参数）

| 项 | 参数 |
|---|---|
| 防抖 | **300 ms**（输入停止 300 ms 才发 `search`；期间 token 变更共享同一 300 ms 栅（§1.2 防抖合一）） |
| 联想 | ≤8 条（31 号 §1.3）；命中域 name.zh/name.en/aliases（CatalogData `build_index` 现为精确小写命中——模糊排序由 UI 层 prefix 优先补齐 [需实机核对：引擎侧 fuzzy 待实装]） |
| 无结果文案 | 「没有找到『<q>』。试试：年代筛选 / 分类浏览 / 查看全部预订中条目」+ [重置筛选]（31 号 §1.3 同文） |
| 联想态选择 | 上/下键移动；回车直达第 1 条详情；Esc 收起 |

### 2.2 排序键表

| 排序键 | 方向 | 数据源 | 说明 |
|---|---|---|---|
| 年代 | 升/降 | `year` | 默认降（新机在前）；同代内按名称 |
| 名称 | 升/降 | `name` | 拼音/字母序 |
| 影响力 | 降 | `reason` 非空者为「影响力条」置顶（有 reason 高于无 reason，其次按年代） | 31 号搜索权重沿用；排序仅在当前结果集内 |

- 排序状态 = 单个 radio 键（互斥）；切换排序不发新查询（结果集内存内重排，无 IO）。

## 3. 数据契约（对 catalog_data.gd 逐函数调用契约）

> 现状函数（56-A 实产）逐条给「入参/出参/联调要求」；Paged 为 33 号新增提案（万级防御）。

### 3.1 现函数契约表

| 函数 | 入参 | 出参 | 联调要求 |
|---|---|---|---|
| `load_meta()` | 无 | bool | 图鉴页初始化调用一次；false → 显示 31 号空态并出错误 toast |
| `get_taxonomy()` | 无 | Dictionary（大→中→[子] 树） | 树面板直接渲染；树节点 id 作 token 值 |
| `get_shards()` | 无 | Array（meta.shards：{big,mid,count}） | 分片清单驱动中分类计数徽章 |
| `load_shard(big,mid)` | 两大分类+中分类名 | Array（条目，内部键 name/year/…+_taxonomy） | 树展开=中分类时才调；缓存命中零 IO（规格已保证） |
| `build_index()` | 无 | int（索引键数） | 首次开搜索框时调一次（888 级即刻；万级接引擎侧并发索引 [需实机核对]） |
| `search(keyword)` | String | Array（精确命中条目） | 300 ms 防抖后调；prefix 补全在 UI 层做 |
| `get_summary()` | 无 | Dictionary（total_rows/loaded_shards…） | 顶部计数条数据源 |

### 3.2 Paged 提案（万级防御；01 线评审后并入 CatalogData）

```json
{ "get_page": { "in":  {"big":"计算机","mid":"个人机","subs":["8位家用"],
                        "era_start":1975,"era_end":1990,"statuses":["done"],
                        "sort":"year_desc","offset":0,"limit":100,"request_id":"r-0031"},
               "out": {"items":[{"id":"apple-ii", ...}], "total":42,
                       "next_offset":100, "request_id":"r-0031"} } }
```

### 3.3 分片请求与取消策略

| 项 | 规则 |
|---|---|
| 请求标识 | 每次查询带自增 `request_id`；响应回带同 id |
| 过期丢弃 | 结果区渲染时比对 `request_id` 与「最新已发 id」——不等则丢弃（快速翻动/连续改 token 时旧响应作废） |
| 读取取消 | 分片 JSON 已缓存后不再 IO；未缓存的分片由 load_shard 同步读——万级下改为异步读 + 可中断 Promise 型 [需实机核对：Godot 线程/异步文件 API 选型] |
| 防抖合一 | 搜索词与 token 变更共享 §2.1 的 300 ms 栅（变更风暴只发最后一态） |

## 4. 性能验收（888 与 10k 两档目标 + 可测方法）

| 指标 | 888 条（真实数据） | 10k 条（scale_bench 合成） | 可测方法 |
|---|---|---|---|
| 树渲染帧率 | ≥60 fps | ≥60 fps | Godot `Engine.get_frames_per_second()` 采样 30 s @2K（31 号 T-367 同源） |
| 滚动帧率 | ≥60 fps | ≥60 fps（虚拟滚动，31 号 §1.4 池 40） | 同 + 单帧尖峰 ≤16.7 ms×3 例外 |
| 首屏 | 树+首页 ≤500 ms（冷启） | ≤1 s | `Time.get_ticks_msec()` 从 load_meta 到首页数据就绪 |
| 搜索响应 | ≤100 ms（内存索引命中） | 索引构建 ≤2 s；查询 ≤100 ms | 计时埋点（build_index/search 包夹） |
| 内存 | 行对象池 ≤40 行（31 号池上限） | 索引内存 ≤64 MB [需实机核对：合成实测] | `Performance.get_monitor(MEMORY_STATIC)` 差分；scale_bench 提供 摄取/查询/内存 三档表可复用（tracemalloc 实测） |
