## (a) 概述与历史地位

PDP-11 由 DEC 于 1970 年推出，是一台 16 位小型计算机，被广泛视为**史上最具影响力的计算机之一** [S36][S31]。如果说 PDP-8 证明了"小型机有市场"，那么 PDP-11 则定义了"一台小型机应该长什么样"——它的正交指令集、8 个通用寄存器、字节可寻址的内存、以及那条统一的 **Unibus** 总线，深刻影响了此后几乎所有微处理器与小型机的设计（包括 Motorola 68000 与 Intel 8086 在内，都常被指出借鉴了 PDP-11 的架构思想）[S36]。

PDP-11 最重要的历史功绩，是成为 **UNIX 与 C 语言**的孵化平台 [S36]。贝尔实验室的 Ken Thompson 与 Dennis Ritchie 最初在 PDP-7 上写了 Unix 的雏形，随后把它移植到 PDP-11；C 语言也正是为了在 PDP-11 上重写 Unix 而被设计出来的 [S36]。可以说，今天运行着 Android、iOS、服务器与无数嵌入式设备的 Unix/Linux 血统，其关键的青春期就是在 PDP-11 上度过的。

PDP-11 的商业成功同样惊人：它是 DEC 有史以来销量最大的计算机之一（累计产量以数十万计），并衍生出 LSI-11 等微处理器实现，把 PDP-11 的架构塞进芯片、带进了嵌入式与个人计算机的新时代 [S36]。

技术上，PDP-11 的几项设计堪称教科书 [S36]：

1. **正交指令集 + 8 种寻址方式**：几乎任意指令都能配合任意寻址方式作用于任意寄存器，程序员获得前所未有的表达自由度。
2. **统一内存与设备（Unibus）**：CPU、内存、所有外设都挂在同一条总线上，设备寄存器与内存统一编址，I/O 编程变得异常优雅。
3. **字节可寻址 + 小端序**：8 位字节、16 位字，小端字节序（低位在前）——这一字节序约定后来被 x86 家族沿用至今。
4. **栈与递归的自然支持**：R6 专用作栈指针、R7 作程序计数器，让子程序调用、递归、高级语言编译都变得自然。

从 PDP-8 的"极简"到 PDP-11 的"优雅"，小型机完成了从"够用"到"好用"的跨越，也把一整代程序员的思想塑造成了后来的模样。

## (c) 工作原理

### 系统框图（ASCII）

```
                        ┌────────────────────────────────┐
                        │           PDP-11 整机            │
                        └────────────────────────────────┘
                                     │
         ┌───────────────────────────┼───────────────────────────┐
         │                           │                           │
         ▼                           ▼                           ▼
 ┌────────────────┐         ┌────────────────┐         ┌────────────────┐
 │   CPU 板组       │◀──────▶│   内存(磁芯/半导体) │         │  外设控制器      │
 │ · 通用寄存器 R0–R7│   Unibus│   (字节可寻址)     │         │ (设备寄存器     │
 │ · 状态寄存器 PSW  │         └────────────────┘         │  与内存统一编址) │
 │ · 算逻单元 ALU    │                ▲                     └────────────────┘
 └────────────────┘                 │                              ▲
                                     │                              │
                                     └──────────  Unibus（统一总线）──────────┘
                                        · 数据/地址/控制复用
                                        · 内存与设备寄存器统一编址
                                        · DMA 直接内存访问
```

### 数据流说明

1. **取指**：R7（PC）指向当前指令，指令取出后 PC 自动递增，指向下一条；这一"PC 就是普通寄存器"的设计是 PDP-11 优雅性的来源 [S36]。
2. **寻址计算**：指令的低位指定源/目的操作数的寄存器与寻址方式；8 种寻址方式中，寄存器间接、自增、自减等可直接实现指针遍历与栈操作 [S36]。
3. **执行**：ALU 对源/目的操作数运算，结果写回目的；字节与字操作均可 [S36]。
4. **I/O**：外设通过设备寄存器挂载在 Unibus 上，与内存统一编址——读一个外设状态就像读一个内存地址一样简单；DMA 允许外设直接访问内存而不打扰 CPU [S36]。

### 关键子系统职能

- **通用寄存器组（R0–R7）**：8 个 16 位寄存器，全部可用作累加器、指针或变址；R6/R7 分别专职栈指针与程序计数器，让递归与子程序调用自然成立 [S36]。
- **Unibus（统一总线）**：单一异步总线承载数据、地址与控制，内存与设备统一编址，是 PDP-11 架构的灵魂 [S36]。
- **状态寄存器 PSW**：记录条件码（N/Z/V/C）与处理器优先级等，支撑条件分支与中断处理。
- **内存管理单元 MMU（中高端型号）**：提供地址映射与保护，支撑 UNIX 等分时操作系统（早期 /20 无 MMU）[S36]。

> 以上职能描述即未来 FR-C 原理标注素材底稿。

## (d) 装配体层级树草案

```
PDP-11 整机（机柜/机箱，以 /45 或 /70 为展示代表）
├── 机柜结构（Chassis / 机架 + 前面板 + 电源笼）
├── 电源子系统（多电压直流电源）
├── CPU 板组
│   ├── 数据通路板（ALU + 寄存器组 R0–R7）
│   ├── 时序/控制板
│   ├── 微程序控制板（视型号）
│   └── 内存管理单元 MMU 板（中高端）
├── 存储器子系统
│   ├── 存储模块（磁芯/半导体板 ×N）
│   └── 存储控制器板
├── Unibus 背板 + 扩展槽
│   ├── Unibus 背板（走线）
│   └── 外设控制器插卡（终端/磁盘/磁带/纸带…）
├── 前面板子系统
│   ├── 开关/按键（RUN/HALT/装载等）
│   └── 指示灯/地址数据显示
└── I/O 设备（外围，可作独立展项）
    ├── 终端（电传/CRT）
    ├── 磁盘/磁带机
    └── 纸带读入/穿孔机
```

**逐层要点与建模拆解预算评估：**

- **整机→子系统**（约 6–10 节点）：以"机柜 → CPU/内存/外设 → Unibus 背板"分层，突出 Unibus 的统一总线特征。
- **子系统→板卡**（约 20–40 节点）：Unibus 插卡是天然的"板级组合体"，外设控制器卡可按"同构插卡模板"批量复用。
- **板卡→元器件**（理论可达数千节点）：**不建议全量展开**；PDP-11 用 TTL/MSI 规模集成，**建议**以"板级组合体 + 实例化"建模，仅 1–2 块教学板（如数据通路板）做逐元件展开。
- **难度点**：① Unibus 背板走线与"内存/设备统一编址"的抽象，需动画表达；② "PC 就是普通寄存器"这一优雅点，适合用"自增寻址遍历数组"的动画呈现；③ 前面板可做有限"RUN/HALT/单步 + 灯显"交互。

## (e) 百科卡全文（C1 级成品文案）

**DEC PDP-11 —— 那台定义了"计算机该怎么设计"的小型机**

1970 年，DEC 推出了一台 16 位的小型机 PDP-11。它没有大型机的排场，也没有 PDP-8 的便宜到极致，但它有一项在当时独一无二的品质——**优雅** [S36]。

PDP-11 的优雅体现在细节里。它有 8 个通用寄存器，个个都能当累加器、当指针、当变址寄存器用；它有 8 种寻址方式，几乎任意指令都能和任意寻址方式自由组合。更有意思的是，它把程序计数器（PC）也当成一个普通寄存器——于是"取完这条指令，PC 自动加一"这种再自然不过的事，居然能从硬件设计里"免费"地涌现出来 [S36]。这种被称为"正交性"的设计哲学，后来成了无数处理器设计师心中的黄金标准。

要理解"正交"有多美妙，可以打个比方：早期的机器，指令和寻址方式往往"绑定"得死死的——加法只能用某几种方式、跳转又只能用另外几种方式。而 PDP-11 把它们"拆开"了：随便哪条指令，配随便哪种寻址方式，都能用在随便哪个寄存器上。于是程序员获得了一种近乎"乐高积木"的自由——想用寄存器间接寻址去跳转？可以；想用自增寻址去加法？也可以 [S36]。

PDP-11 还发明了 **Unibus**——一条把所有东西都接在一起的统一总线。CPU、内存、终端、磁盘，全都挂在同一条总线上，外设的寄存器就像内存地址一样可以直接读写 [S36]。这让 I/O 编程第一次变得如此简洁：读一个外设的状态，就像读一个变量那么自然。这种"内存与设备统一编址"的巧思，直接降低了硬件编程的门槛，也让整个系统显得异常干净利落。

但 PDP-11 最伟大的遗产，藏在软件里。贝尔实验室的 Ken Thompson 和 Dennis Ritchie，正是在 PDP-11 上把 Unix 移植成形，并为重写它而发明了 C 语言 [S36]。可以说，今天我们手机里的 Android、服务器上的 Linux、无数设备里的嵌入式系统，它们共同的"青春期"，就是在 PDP-11 上度过的。一台机器能同时孵育出一个操作系统和一个编程语言——这样的"文化功绩"，在计算机史上屈指可数。

它的影响还深深烙进了后来的处理器设计。就连后来统治个人电脑的 Intel x86 架构，也处处能看出 PDP-11 的影子——小端字节序、寄存器与寻址方式的组织，都能追溯到这台机器 [S36]。有人戏称，PDP-11 是"微处理器时代的设计师们抄作业的范本"。

从 PDP-8 的"够用"，到 PDP-11 的"好用"，小型机完成了从工具到范式的跨越。它卖出了数十万台，成了 DEC 最畅销的机器，也成了整整一代程序员与操作系统设计师共同的精神故乡。今天你在任何一本计算机体系结构教材里看到的"通用寄存器""正交指令集""统一总线"，源头几乎都能追到这台 16 位的小机器身上。

**可以这样看**：去看它那条横贯机柜的 Unibus 背板，去想象"内存和所有外设都共享同一条路"的简洁；再去想，你手机里跑着的 Linux 内核，它的祖先，就是在这样一台机器上写出来的。

**深度解读一：Unix 与 C 的"母机"。** 1969 年前后，贝尔实验室的 Ken Thompson 先是在一台 PDP-7 上写出了 Unix 的雏形；为了让 Unix 能在一台"像样的机器"上真正跑起来，实验室换来了 PDP-11，Unix 随之移植过来 [S36]。为了重写 Unix 而不用每次都被汇编语言折磨，Dennis Ritchie 发明了 C 语言——一门"足够贴近硬件、又足够抽象"的语言 [S36]。于是，一个操作系统和一门编程语言，在同一台 16 位小机器上互相成就。今天跑在几十亿台设备上的 Linux，其设计 DNA 直接承袭自 PDP-11 上的 Unix。

**深度解读二：x86 为何"长得像" PDP-11。** 如果你去读 Intel 8086 的手册，会发现它的小端字节序、寄存器寻址的组织方式、乃至"数据可以按字节或字操作"的习惯，都与 PDP-11 惊人相似。这并非巧合——8086 的设计者在相当程度上借鉴了 PDP-11 广受好评的架构思想 [S36]。也就是说，你今天用的每一台 x86 电脑，从字节序到寻址方式，都间接地欠着 PDP-11 一份"设计债"。

**深度解读三：LSI-11，把小型机"塞进芯片"。** PDP-11 的故事没有停在机柜里。1975 年，DEC 推出了 LSI-11——把 PDP-11 的处理器做成了芯片级的实现 [S36]。这意味着 PDP-11 的架构第一次"离开机柜、走进芯片"，为后来把它嵌入各种设备与个人计算机铺平了路。一台 1970 年的机柜级小型机，其指令集最终能缩进一块芯片——这本身就是"摩尔定律"最生动的注脚。

**深度解读四：一个丰富的软件生态。** PDP-11 不只跑 Unix。DEC 自己的 RT-11（实时单用户）、RSX-11（实时多任务）、RSTS/E（分时）等操作系统，覆盖了从实验室实时控制到多用户分时的各种场景 [S36]。这种"一台机器、多种系统、各取所需"的丰富生态，让 PDP-11 既能当实验室的控制中枢，又能当大学里的教学分时系统，还能当工厂车间的实时控制器——一台机器，几乎无所不能。

**关键参数（面向玩家）：** 16 位字 · 8 个通用寄存器 · Unibus 统一总线 · 8 种寻址方式 · UNIX/C 的孵化平台 · 1970 [S36]。

**参考来源：** [S31][S36][S39]。

## (f) 原理讲解大纲（C2/C3/C4）

- **C2（框图层）**：标注"CPU / 内存 / Unibus / 外设"四大功能区；高亮"内存与设备统一编址"这一核心特征。
- **C3（信号流层）**：标注三类信号——① 数据通路（寄存器 ↔ 内存，16 位）；② 地址/控制（Unibus 复用线）；③ DMA 通道（外设 ↔ 内存直通）。建议做"一次自增寻址"动画：PC 取指 → 自增 → 用寄存器间接遍历一段数据。
- **C4（原理动画）**（分镜轮廓见下）：

**分镜 1《一条总线连起一切》**：机柜内景，Unibus 背板横贯画面，CPU、内存、各外设卡依次点亮挂载，字幕点出"内存与设备，统一编址"。

**分镜 2《PC 是个普通寄存器》**：数据通路特写，展示"PC 自增"如何让程序顺序执行，再演示一次"用寄存器自增寻址遍历数组"。

**分镜 3《Unix 的摇篮》**：分屏——左边是 1970 年代 PDP-11 上的 Unix 终端画面（文本），右边滑过今天的 Linux/Android/嵌入式设备，字幕点出"血脉相承"。

**分镜 4《小端的由来》**：放大一个 16 位字的内存布局，展示小端字节序（低位在前）如何存储，点题"这个约定一直用到了今天"。

## (g) 模拟器/演示可行性

**已有开源/可用模拟器现状：**

1. **SIMH "Classic"（Bob Supnik 维护的 3.x 流）**：SIMH 的 PDP-11 模拟器是其中最成熟、使用最广的之一，可运行 RT-11、RSX-11、RSTS/E 以及 UNIX V6/V7 等历史系统 [S40][S43]。**许可：MIT-style（modified MIT）开源许可** [S40]。
2. **Open SIMH（V4 流）**：包含 PDP-11 模拟器的治理化后续项目，仓库 `https://github.com/open-simh/simh` [S41]。**许可：MIT-style / BSD** [S41][S42]。
3. **UNIX 软件授权（Ancient UNIX）**：Unix V6/V7 等早期版本经 Caldera/SCO 在 2002 年以"Ancient UNIX License"（类 BSD 许可）开放，允许用于教育与非商业研究——这是 PDP-11 演示最宝贵的软件资产，但**具体分发条款「需核实」**（须确认 Ancient UNIX License 的适用范围）。

**结论：能跑（生态最丰富）。**

- **能跑**：用 SIMH 的 PDP-11 模拟器，可真实运行 UNIX V6/V7、RT-11 等，体验"命令行 + C 程序"的完整历史环境 [S40]。
- **不能跑/不建议**：宣称"逐拍仿真 Unibus 时序"——SIMH 是功能级模拟；且需注意早期 UNIX 的 Ancient UNIX License 授权边界，商用分发前须逐项确认。
- **推荐方案**：以"静态高精度 3D（含 Unibus 背板）+ 原理动画 + SIMH 跑 UNIX/RT-11 作可玩出口"三件套承载；"在 PDP-11 上敲一段 C 程序"是最佳可玩亮点。

**方案 A/B 与工作量粗估：**
- **方案 A（轻量，推荐先做）**：静态模型 + C2/C3/C4 原理动画 + 外链 SIMH 跑 UNIX V7。工作量：模型 1 人周，动画 1 人周。
- **方案 B（重，进阶）**：内嵌 SIMH + 终端交互（网页内嵌 telnet 式终端会话）。工作量：额外 1–2 人周（需处理终端仿真、Ancient UNIX License 合规）。

> 许可红线提示：SIMH 为 MIT-style，可再分发；早期 UNIX 的 Ancient UNIX License 须确认适用范围，商用分发前逐项核实 [S40][S43]。
