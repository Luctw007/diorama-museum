## 三、校准建议（只写建议，不改口径文件本体）

> 校准的本质：177-B 口径是"先于量产的预判"，182-B 实测是"量产首台之后的回看"。预判写得再细，
> 也难免漏掉真实包里的中间态。下面 4 条校准建议，是两台真实包"反照"出的口径盲区，只作建议写进
> 本记录，改口径另行立项（避免在量产中途反复横跳口径文本）。

1. **补 S 档"有模拟器声明但未登记槽位"中间态**：altair-8800 实测 `emulator=simh-altair8800` 但
   `slot=None`、未登记槽位 manifest，且 `simh-altair8800` 是否在 registry 的 `bone` 状态**需核实**。
   口径 §二只写了"有 bone 则登记槽位 / 无 bone → none 静态"两端，漏了"emulator 已声明、后端未 bone、
   未登记槽位"的中间态。**建议**：口径补一句——`emulator` 非 `none` 但 `slot` 未登记 = "待接后端"，
   不算静态展示、也不算未做，验收上 validate 仍 0 FAIL、反链仍要 done，槽位登记等 01 线后端到位后补。
2. **明确 B 档"最小件"是下限不是上限**：nokia-3310 实测 assemblies 6 + annotations 33 + encyclopedia
   2548 字，远超 B 档最小要求（≥1 gltf），仍 0 FAIL。**建议**：口径 §四补"B 档只设下限，做得更全
   不算超标、不加额外验收"。
3. **encyclopedia NOTE 分支待验证**：口径 §四说"B 档 encyclopedia 可存缺口 → NOTE 转补不进失败判定"，
   与 `pkg_registry._missing_encyclopedia` 判据一致；但本实测两台百科均齐，**未触发**"缺 encyclopedia"
   的 NOTE 分支。**建议**：后续用一台"故意缺百科"的 B 档包验证 NOTE 是否真只提示、不进失败判定。
4. **assemblies 装配体数与 gltf 文件数的一致性**：altair-8800 的 meta 声明 `assemblies` 7 个，但
   assemblies/ 目录只有 6 个 gltf（另有 MESHES.md 说明）。**建议**：口径 S 档"assemblies 全"补一句
   "装配体数 = 独立 gltf 数 + MESHES.md 说明的复用/空装配体数"，避免"7 装配体 6 gltf"被误读为缺件。
   原因：v0.5 起允许"外观/内部蒙皮/内部结构"是同一个 node_id 的增量替换，而非一一对应独立 gltf；
   装配体数 > gltf 数是合法常态，不是缺件。

## 四、实测方法说明（本次怎么测的）

- **只读实测**：全程只跑 02 线校验器（`validate.py` / `catalog_ref_check.py`）与 01 线注册表/门禁
  （`pkg_registry.py` / `verify_all.py --only`）**读现有包**，未新建/修改任何内容包、脚本、校验器。
- **两台择取**：nokia-3310 是第二批先行样板（B 档）、altair-8800 是第二批首批第 2 台（S 档候选），
  正好覆盖口径里"两端"——B 档最小件、S 档全规格。
- **交叉复验**：除全量 `catalog_ref_check` 外，用 `verify_all --only pkg:*` 对两台分别单点过闸，
  证明"单包过闸"与"全量门禁"两条链路一致。
- **口径对照口径**：对照表以 `第二批分档验收口径_v1.md` 的三档口径逐条比对，结论只标"实测一致 /
  口径未覆盖"，不主观评价口径好坏（校准建议单列、不改口径本体）。

## 五、结论

两台第二批包均**真实 0 FAIL 过闸**，三档公共硬底线（validate 0 FAIL / REF 四查 0 / THIRD_PARTY 三件套 /
id 唯一 / 反链 REF-02）**逐项实测一致**。口径对"两端"（S 档全规格、B 档最小件）的描述准确，但对
"中间态"（S 档有模拟器未登记槽位、B 档超过下限、缺百科的 NOTE 分支、装配体数 vs gltf 数）留了 4 处
待校准点，均已列入校准建议、**不改口径文件本体**，改口径另行立项。

> 一句话总结：**口径方向正确、底线被两台真实包验证通过，但量产真实包的中间态比口径预判更丰富，
> 建议在下一批量产前把 4 条校准建议并入口径 v2。**
