# 拆解深度模型（docs/depth_model.md）

> TASK-51B 交付。长期目标：数千上万种设备，任何一台都能拆到"每个大部件"，进一步到板卡/元件。
> 本文档是拆解深度的统一依据——与 02 线 v0.3 建模章（网格/预算）、04 线 32 号体验规格、现有
> explode_controller 的三方对齐产物（差距审阅见第 6 章）。

## 1. 深度分级（L0-L3）

| 级 | 名称 | 内容 | 单机预算（顶点上限） | 生产策略 |
|---|---|---|---|---|
| L0 | 整机 | 外壳闭合完整形态 + 底座锚点 | 3 万 | 每台必做 |
| L1 | 大部件 | 七标准类目（见 §2），独立 glTF、可按件拿下 | 每件 1.5 万，整机 ≤10 万 | 每台必做（资料不足时按同类同代机参考标注「需核实」） |
| L2 | 板卡与子模组 | 大部件内部的板级拆分（扩展卡、屏驱动板、电源子板…） | 每件 8 千，整机 ≤25 万 | 视资料：名机全做，其余按类目模板 |
| L3 | 元件 | 芯片/电容/电阻/连接器的代表件 | 仅代表件 ≤20 个/机，每件 1 千 | 只做代表件 + 浮动解说，永不全拆 |

**规模约束口号**：L1 全齐、L2 择优、L3 代表件——这是"上万台设备"下拆解成本可控的唯一解。

## 3. DeviceSpec 表达（两方案对比与裁决）

| 方案 | 表达 | 优点 | 缺点 | 裁决 |
|---|---|---|---|---|
| A 全嵌套 | assemblies 树无限嵌套 L0→L1→L2→L3 | 唯一树，loader 天然支持 | meta.json 巨大；跨设备复用板级定义差 | **采用（现状即此）** |
| B 引用式 | L1 部件 `subassembly_of:"L0"` 平铺 + 引用公共板卡 | 复用强 | 需要引用解析层，与现有 loader/annotations 不兼容 | 驳回（v0.6 后如公共板卡需求出现再议，见开放问题） |

glTF 节点名=node_id（R-090）在 L2/L3 保持同一规则；L3 元件可并入所在板卡 glTF 内作独立命名节点（不强制单文件）。

## 4. 级联爆炸与状态机层进

- 现有状态机：CLOSED→OPENED→EXPLODED（全树按深度一次爆炸，MAX_DEPTH=8，位移公式
  `offset = value × depth × STEP`）；
- **级联爆炸定义**（54-B 体验、引擎后续实现）：EXPLODED(L1 展开) 中点选某 L1 件 → 进入
  **子树视图**：该件移到视口中心（运镜轨迹：目标框缩放 0.8-1.2s），其 L2 子树沿该件局部
  轴再次爆炸；面包屑 `整机 / 主板 / 扩展卡` 逐级返回；L3 不做全拆，只高亮代表件 + 浮动解说；
- 展开系数与示例：L1 步距 0.12m（STEP）、L2 步距 0.06m、L3 高亮不位移（数值进 54-B 定稿）；
- 深度上限：MAX_DEPTH=8 覆盖 L0-L3 的任意中间层，无需改动（防御性足够）。

## 5. 加载与内存预算（万级设备的硬约束）

| 项 | 值 |
|---|---|
| 仅外观巡游（L0 占位盒） | 每机即时加载，无需驻留 |
| L1 拆解会话驻留 | 完成后立即释放；单机驻留 ≤150MB 显存（正式建模档） |
| 切机策略 | exhibit_host 配额与 clear_devices 已实现；五机同屏时仅 1 台保有 L2/L3 节点 |
| 目录索引 | 与 exhibit_index 分离：目录走 catalog_ingest 分片（每片 ≤5k），图鉴只按需取片 |

## 6. explode_controller 差距审阅（静态，基于 11-C 实现）

| # | 能力 | 现状 | 差距（供后续任务） |
|---|---|---|---|
| 1 | 多级树爆炸 | 支持（深度+轴已算，MAX_DEPTH=8） | 无 |
| 2 | 级联/子树爆炸 | 无（全树一次性展开） | 新增 `explode_subtree(node)` + 局部基准形变记录 |
| 3 | 相机聚焦运镜 | 无 | 新增 `focus_node(node)`（目标框+时长参数） |
| 4 | 运行锁 | 有占位接入点 | 接网关 status 信号（46 线 launch 后可行） |
| 5 | 部件类轴预设 | 轴自动猜（父级位移方向） | 接入 §2 七类主轴预设表（annotations 提供类码时优先） |
| 6 | L3 代表件高亮层 | 无 | 新增 rep_highlight 集合渲染（不位移） |
| 7 | 面包屑导航 | 无 | 新增 depth_breadcrumb 状态（数据即可，UI 归 04 线） |
| 8 | 深层性能回收 | 无（全部节点常驻场景树） | 子树视图切换时的 hide/show 批处理 |

## 7. 开放问题

1. 引用式板卡复用（方案 B）随"公共部件库"出现时的再议入口（预计目录普查后浮出）；
2. 七类之外的部件（如天线/电池/镜头）暂归 L1-ENC 或按档案新开类码——第 2 版 taxonomy 时统一；
3. L3 代表件选择标准（"教学代表性"权重表）交由 03/05 线在生产中沉淀。
