## 0. 总则

- 每条验收项五要素齐全：**判据 / 验证方法 / 预期证据 / 由谁验 / 验不过的回退路径**。
- 由谁验口径：**用户侧** = 真人上机走查并签字；**01 测** = 01 线跑脚本收日志证据；**04 测** = 04 线对照规格逐条核对文档与截图。
- 证据形式：录屏/截图 PNG、命令日志原文、打勾表照片（三类任一即可，路径写入证据栏）。
- 回退路径统一原则：失败 → 记录哪一步、什么报错 → 派对应线修复 → **整份清单重跑**（不单条放行）。

## 4. 封版门

1. **全绿判定**：RC-A-01~A-06、RC-B-01~B-05、RC-C-01~C-05 共 16 项全部通过（豁免项须在 §1.2/RC-B-02 处显式批注理由并经用户侧确认）。
2. **tag 流程**（与 81-B git 化衔接）：在 81-B 建好的 01 线版本库上执行 `git status` 确认干净 → `git tag -a v0.1 -m "v0.1 demo: hall walkthrough + 3 real-runs + pedia 1484"`；**不 push**（无远端）；二进制/ROM 禁入红线照 81-B `.gitignore`，tag 前 `git check-ignore third_party/mame/mame` 须有输出。
3. **未全绿**：禁止打 tag；按各回退路径修完 → 整份清单重跑 → 直到全绿或经用户侧书面豁免。
4. 打勾完成即启动 v0.2 开源准备（《项目建议》§④：LICENSE 复核/CONTRIBUTING/ROADMAP）。
