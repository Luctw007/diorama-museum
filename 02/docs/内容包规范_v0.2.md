## 一、总则

### 1.1 内容包定义

一个「设备内容包」（下称内容包）是对**一台设备**的完整数字化描述，供博物馆引擎加载、装配、标注、动画与模拟。一个内容包 = 一个目录，目录名即 `device-id`，位于 `content/<device-id>/` 之下。

内容包由两部分构成：
1. **契约数据**：`meta.json`（DeviceSpec）、`runtime.json`（RuntimeProfile）、`annotations/annotations.json`（标注集）、`THIRD_PARTY.md`（许可清册）——**机器可校验**的权威数据。
2. **资产数据**：`assemblies/`、`meshes/`、`materials/`、`sounds/` 下的网格、材质、音频等二进制/文本资源。

### 1.2 版本规则

- 内容包自身版本：`meta.version`，遵循 [SemVer 2.0.0](https://semver.org/lang/zh-CN/)。
- 规范版本：`meta.spec_version`，本规范为 `"0.2"`。
- 引擎最低版本：`meta.engine_min_version`，SemVer；引擎低于此版本时**必须拒绝加载**该包。

### 1.3 度量与坐标系

- **单位**：一律**米**（SI），1 单位 = 1 米，模型按 **1:1 真实比例**建模。
- **坐标系**：**Y-up、右手系**（+X 右，+Y 上，+Z 朝向观察者）。
- **旋转**：**四元数** `[x, y, z, w]`，必须为单位四元数（模长 = 1，容差 1e-3）。

### 1.4 glTF 要求

- 所有网格资源使用 **glTF 2.0**（`.gltf` 或 `.glb`），`asset.version` 必须为 `2.x`。
- 网格内单位米、Y-up、右手系；坐标系差异在导入时烘焙，**不得**依赖运行时翻转。
- **网格节点命名约定（v0.2 新增）**：装配体所引用 glTF 的**场景根节点名（或网格名）必须等于该装配体的 `node_id`**（R-090），便于引擎按 id 定位节点做高亮/动画。

## 二、目录结构

```
content/<device-id>/
├── meta.json                 # DeviceSpec（元数据 + 装配树 + 元器件 + runtime 内嵌副本）
├── runtime.json              # RuntimeProfile（与 meta.json.runtime 逐字节等价）
├── THIRD_PARTY.md            # 第三方资产许可清册（必填）
├── README.md                 # 作者说明（脚手架生成，可选）
├── assemblies/               # 装配体级 glTF（可选；命名 <assembly-id>.gltf）
├── meshes/                   # 网格 glTF/glb（命名 <mesh-id>.gltf / .glb）
├── materials/                # 材质定义（命名 <material-id>.json；可选）
├── sounds/                   # 音频（命名 <sound-id>.wav/.ogg；可选）
└── annotations/
    └── annotations.json      # 标注集（必填）
```

| 文件/目录 | 必填 | 格式 | 说明 |
|---|---|---|---|
| `meta.json` | 是 | JSON（UTF-8） | DeviceSpec，见第三章 |
| `runtime.json` | 是 | JSON（UTF-8） | RuntimeProfile，见第七章；与 `meta.json.runtime` **逐字节等价**（R-004） |
| `THIRD_PARTY.md` | 是 | Markdown | 许可清册，见第八章 |
| `annotations/annotations.json` | 是 | JSON（UTF-8） | 标注集，见第六/十章 |
| `assemblies/`、`meshes/`、`materials/`、`sounds/` | 否 | — | 资源目录，可为空 |

**路径约定**：资源引用一律使用**相对 `content/<device-id>/` 的 POSIX 路径**（正斜杠 `/`），禁止绝对路径或 `..` 跳出设备目录。

## 三、DeviceSpec 字段字典

DeviceSpec 是 `meta.json` 的根对象，含四个顶层键：`meta`、`assemblies`、`components`、`runtime`。可选顶层键 `$schema`。**顶层禁止未声明额外字段**（`additionalProperties: false`）。

| `name` | localized | 是 | `{zh, en}`，zh 必填 | R-087（v0.2 起，原 string 迁移到 name.zh） |
| `name_en` | string | 否 | — | **deprecated**，superseded by name.en（R-088） |
| `intro` | localized | 否 | `{zh, en}` | v0.2 新增，对应草稿 meta.intro |
| `description` | string | 否 | — | 简短概述（v0.1 沿用） |
| `era` | integer | 否 | 1800–2100 | v0.2 新增（R-089），对应草稿 meta.era |
| `manufacturer` | string | 否 | — | v0.2 新增，对应草稿 meta.manufacturer |
| `category` | string | 否 | — | 设备类别 |
| `spec_version` | string | 是 | 固定 `"0.2"` | R-071 |
| `version` | string | 是 | SemVer | R-070 |
| `engine_min_version` | string | 是 | SemVer | R-072 |
| `precision_level` | string | 是 | `L1`/`L2`/`L3`/`L4` | R-040，见第五章 |

| `license` | string | 是 | public_domain/cc/licensed/visual_reference_only | R-053 |

| 字段 | 类型 | 必填 | 说明 | 校验规则 |
|---|---|---|---|---|

| 字段 | 类型 | 必填 | 说明 | 校验规则 |
|---|---|---|---|---|
| `id` | string | 是 | 节点 id，snake_case | R-021/023 |
| `name` | string | 是 | 显示名 | — |
| `type` | string | 是 | 元器件类型 | — |
| `part_no` | string | 否 | 官方零件号（v0.2 新增，对应草稿 part_no） | — |
| `role` | localized | 是 | 作用文案（必须含「在整机」） | R-061 |

### 3.4 `runtime`（内嵌 RuntimeProfile）

与 `runtime.json` 逐字节等价（R-004）。字段见第七章。

### 3.5 `transform`（变换）

| 字段 | 类型 | 必填 | 说明 | 校验规则 |
|---|---|---|---|---|
| `translation` | array\<number\> | 是 | `[x,y,z]`，米 | R-030 |
| `rotation` | array\<number\> | 是 | `[x,y,z,w]` 四元数，单位 | R-031 |
| `scale` | array\<number\> | 是 | `[sx,sy,sz]`，各分量 > 0 | R-032/033 |

> 变换按 glTF 语义：局部坐标 = `T * R * S`。设计文档附录 A 的六元组 `[0,0,0,0,0,0]` 占位形式**在本规范中废弃**，统一采用对象形式（见附录 C 迁移表）。

## 五、资产预算与精度分级

| 分级 | 单模型三角面 | 整机节点 | 纹理分辨率 | 动画总时长 | 适用场景 |
|---|---|---|---|---|---|
| L1 | 2,000 | 50 | 512×512 | 60 s | 快速原型 / 占位 |
| L2 | 20,000 | 500 | 2048×2048 | 180 s | 默认交付 |
| L3 | 200,000 | 5,000 | 4096×4096 | 300 s | 高精度 |
| L4 | 2,000,000 | 50,000 | 8192×8192 | 600 s | 展示级特写 |

> 以上为 **v0.2 起始值，可调**（不是绝对真理）。`budget_check.py` 提供 glTF 顶点/三角面精确统计与 PNG/JPEG 纹理尺寸解析，超限**不阻塞**（报告提示）。动画总时长上限用于 R-081。

## 六、标注内容规范

标注集存放于 `annotations/annotations.json`，为 `{ "annotations": [ ... ] }`。每条标注：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | 是 | snake_case，R-022 |
| `type` | string | 是 | `role`/`flow`/`anim` |
| `target` | string | 是 | assembly/component id，R-015 |
| `text` | string | 是 | 标注正文（中文） |
| `text_en` | string | 否 | 英文文案 |
| `surface` | string | 否 | 关联输出 surface（R-085，见第十一章） |
| `timeline` | array | 否 | 动画/流程时间轴（anim/flow 用，见第十章） |
| `sources` | array\<string\> | 否 | 来源 URL，R-063 |

### 6.1 三类标注写法

- **`role`（作用）**：说明在整机中的作用。**除根装配体外，正文必须含「在整机」**（R-061）；字数 20–200（R-062）。
- **`flow`（流程）**：描述信号/能量/数据流，写明**起点 → 路径 → 终点**。
- **`anim`（动画/交互）**：描述动画或交互行为，写明**触发条件、动作、时序**；可携带 `timeline`（第十章）。

### 6.2 文案红线

正式文案（`text`、`role.zh`、`caption`、`intro.zh`）**不得**出现未定标记：`需核实`、`待核实`、`TBD`、`TODO`、`FIXME`、`待定`、`XXX`、`???`（R-060 标注、R-083 caption）。有疑问的内容移入「开放问题清单」。

## 十、动画标注与时间轴（v0.2 新增）

`anim`（及可选的 `flow`）标注可携带 `timeline` 数组，描述一段镜头序列，用于 C4「信号级展示」的载体。

### 10.1 `timeline` 段结构

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `t` | array\<number\> | 是 | 起止秒 `[start, end]`，要求 `end > start`（R-080/R-081） |
| `camera` | object | 是 | `{pos:[x,y,z], look:[x,y,z]}` 镜头位姿 |
| `arrow` | object | 否 | `{from:[x,y,z], to:[x,y,z], label}` 指向箭头 |
| `highlight` | array\<string\> | 否 | 高亮节点 id 列表（须存在，R-080） |
| `caption` | string | 否 | 解说词（R-082/R-083） |
| `easing` | string | 否 | `linear`/`ease_in`/`ease_out`/`ease_in_out` |

### 10.2 展示级（C2/C3/C4）最少要求

| 展示级 | 最少要求 |
|---|---|
| C2（静态展示） | role/flow 文案齐全，timeline 可选 |
| C3（结构/流程展示） | timeline 含 camera/arrow/highlight，caption 可选 |
| C4（信号级展示） | **逐镜头 caption 齐全**（R-082），与配文/配音一一对应 |

- `presentation_level` 缺省视为 C3。
- 时长上限：单个标注 timeline 总时长（各段时长之和）不得超过其 `precision_level` 对应动画时长上限（R-081）。
- 与配文/配音对应规则：C4 下每个 caption 对应一段配音或字幕单元，caption 缺失即无法配音，故判 FAIL（R-082）。

## 十一、输出 Sink 与输入映射（v0.2 新增）

### 11.1 Sink 命名枚举（R-084）

`output_sinks[].surface` 取值固定为以下枚举（v0.2 写死）：

| 枚举 | 含义 |
|---|---|
| `internal_crt` | 内屏 CRT（复古 CRT 显示器） |
| `external_crt` | 外接 CRT |
| `terminal` | 电传终端 / 打印输出 |
| `led` | LED 显示 |
| `handheld_lcd` | 掌机 LCD |
| `speaker` | 扬声器 |
| `crt_display` | （v0.1 兼容）显示器屏（CRT/平面屏通用名） |
| `indicator_lamps` | （v0.1 兼容）指示灯组 |

> v0.1 存量包使用 `crt_display` / `indicator_lamps`；v0.2 保留为兼容枚举（deprecated，新包建议用 `internal_crt` / `led`）。

`annotation.surface`（若填写）必须引用已在 `output_sinks` 中声明的 surface（R-085 闭环）。

### 11.2 input_map 键名全集（R-086）

`input_map` 为「逻辑动作名 → 输入描述」映射，**接受两种形态**：

1. **结构化（v0.2 推荐）**——值 = `{map, key}`：

```json
"input_map": {
  "key_a": { "map": "keyboard", "key": "KEY_A" },
  "joy1_btn0": { "map": "joystick", "key": "btn0" }
}
```

2. **legacy 字符串令牌（v0.1 兼容，deprecated）**——值 = 设备逻辑令牌（两层键名模型，
   见 01 线 `docs/runtime_mapping.md` §5：`动作名 → 设备逻辑令牌`，令牌为小写点分路径）：

```json
"input_map": {
  "power": "panel.power",
  "key_a": "keyboard.key_a",
  "store_bit_00": "panel.switch.bit_00"
}
```

> 决策（TASK-07 复跑修订）：v0.1 存量包（manchester-baby/eniac/apple-ii）全部使用
> legacy 字符串令牌且经 01 线实测"两层键名模型"成立，故 v0.2 继续接受该形态
> （R-086 通过并给出迁移提示，不再阻断）。

| 字段 | 取值 |
|---|---|
| 动作名（键） | snake_case（`key_a`/`joy1_axis_x`/`power` 等） |
| `map` | `keyboard` / `mouse` / `joystick` |
| `key` | keyboard → Godot `KEY_*`（`^KEY_[A-Z0-9_]+$`）；joystick → `axis_[xy]` / `btnN` / `hat_*`；mouse → `motion`/`btn_left`/`btn_right`/`btn_middle`/`wheel_up`/`wheel_down` |

### 11.3 与 01 线 PROTOCOL.md（v1）对齐差异表

| 项 | PROTOCOL.md v1 | 本规范 v0.2 | 差异与处理 |
|---|---|---|---|
| 输入消息 | `input_event` 含 `map`+`key`，keyboard 键名为小写（`a`/`space`/`enter`） | `input_map` 值含 `map`+`key`，keyboard 用 Godot `KEY_*` 大写 | 网关后端需做「`KEY_*` → 实际键码」翻译层；本表为翻译契约输入 |
| `map` 取值 | `keyboard`/`mouse`/`joystick` | 同 | 一致 |
| sink 路由 | v1 未实现（计划 FR-E4） | v0.2 定义 surface 枚举 + R-085 闭环 | v0.2 先定契约，网关 v2 实现路由 |

> **对齐任务**：01 线网关升级到 v2 时，`input_event` 的 `key` 应接受 `KEY_*` 命名；本规范的 input_map 即为「逻辑动作 → 通用输入」的映射契约（列入开放问题）。
